# DingoEngine — Claude Context

## What this project is

DingoEngine is a C++20 game engine built on a graphics abstraction layer (NVRHI) targeting Vulkan (primary), DirectX 11, and DirectX 12. User code lives in `Layer` subclasses pushed onto an `Application`-owned `LayerStack`; games are usually thin layers driving Scene/ECS scripts.

## Build system

- **Tool**: Premake5. Regenerate with `./vendor/premake/bin/premake5.exe vs2026` from the repo root (do NOT use `Generate-Windows.bat` from a non-interactive shell — it ends in `PAUSE`).
- **Build**: MSBuild on `DingoEngine.slnx` (or a single example's `.vcxproj`), `/p:Configuration=Debug /p:Platform=x64`. Configs: `Debug`, `Debug-ASan`, `Release`, `Distribution`. Requires the `VULKAN_SDK` env var. Workspace `startproject` is `Dingo-TestFramework`.
- **Linux** (GCC ≥ 13, x86-64): `./Generate-Linux.sh` (= `vendor/premake/bin/premake5 gmake`, 5.0.0-beta8; unlike the `.bat` it doesn't pause), then `make -j"$(nproc)" config=<debug|debug-asan|release|distribution> [Project]`; outputs land in `build/bin/<Config>-linux-x86_64/`, the vendor projects' makefiles in `build/make/` (inside their submodules they would overwrite FreeType's tracked `Makefile`). `VULKAN_SDK` must be LunarG's tarball (Ubuntu's Vulkan headers and shaderc are too old), and assimp 6.0.4 is built from source into the git-ignored `vendor/assimp/lib/linux-x86_64/` (LINUX-SUPPORT.md Appendix A). The Vulkan loader is never linked (`vk::DynamicLoader`), D3D sources are left out, and `DE_DEBUG_BREAK` raises `SIGTRAP`. Headless check: `xvfb-run scripts/ci/linux-smoke-test.sh <Config>` (needs `mesa-vulkan-drivers` and `python3-xlib`). LINUX-SUPPORT.md tracks what is done and what's left.
- **Output**: engine = static lib; examples = executables. Run examples with cwd = the example's source dir so relative `assets/...` paths resolve.
- **New executable checklist**: any project linking the engine must call `copyAssimpRuntime()` (shared helper in the root `premake5.lua`) from its own `premake5.lua`, or it dies with `STATUS_DLL_NOT_FOUND` (`0xC0000135`) before `main` — in Debug-ASan it also copies the ASan runtime DLL. On Linux the same call gives the executable the engine's whole link list in a link group, since `make` links only the libraries a project names. Also add it to `.github/workflows/build-release.yml`'s Windows packaging (one job per example; the Linux job packages every `examples/*` itself) and the `.vscode` build/launch entries. On Linux the engine's post-build step also merges the engine, every vendor lib and the static assimp into `build/dist/<cfg>/libDingoEngine.a` (`scripts/merge-static-libs.sh`), the twin of Windows' `lib.exe` merge.
- **Debug-ASan** links and runs (v0.6.3). The Windows CI doesn't build it; the Linux workflow (`build-linux.yml`) builds all four configurations and runs `scripts/ci/linux-smoke-test.sh` in each, under Xvfb and llvmpipe, on every push and pull request to master. The Vulkan SDK's shaderc/SPIRV prebuilts are non-ASan, so the configuration defines `_DISABLE_STRING_ANNOTATION` / `_DISABLE_VECTOR_ANNOTATION` workspace-wide; dropping them brings back ~500 `LNK2038 annotate_*` mismatches. The MSVC linker needs no `-fsanitize` flag (cl embeds `/INFERASANLIBS`); GCC does, so Linux adds it.
- **Version**: `VERSION` holds `major.minor`; CI appends the commit count and overwrites `include/DingoEngine/BuildInfo.h` (`DE_ENGINE_VERSION_*`, read by `Application::GetEngineVersion/GetEngineBuildNumber`). The checked-in `BuildInfo.h` is a `0.1.0` placeholder and `VERSION` trails the release branch — neither is a reliable "what am I on" source; the branch/tag is.
- **PCH**: `depch.h` / `depch.cpp`.

Vendor forks that upstream as CMake (e.g. box2d) carry their own `premake5.lua`, `include`d from the root workspace.

The test framework takes `--test=<name substring>` (case-insensitive) to boot straight into one case — `--test=asset`, `--test=Text` — otherwise it starts on the first.

Device and adapter selection lives in `Graphics/NVRHI/` (`VulkanGraphicsContext.cpp` for Vulkan). Without a hardware GPU (a VM), D3D11 takes the default adapter, which is WARP, and D3D12 falls back to WARP with a warning (v0.8.2); Vulkan without a driver stops at instance creation with a `DE_CORE_VERIFY` and logs the missing extensions or layers. WARP rasterizes on the CPU: fine for running the test app, meaningless for timings. `GraphicsContext::SupportsWireframe()` is false on a Vulkan GPU without `fillModeNonSolid`; `NvrhiPipeline` then builds `FillMode::Wireframe` solid and warns once (v0.8.3, #78).

## Code conventions

| Thing | Convention |
|---|---|
| Namespace | `Dingo` (everything) |
| Members | `m_Name` (instance), `s_Name` (static), `UPPER_SNAKE_CASE` constants/macros |
| Backend classes | `Vulkan*`, `DirectX12*`, `Nvrhi*`, `Win*` |
| Log macros | engine `DE_CORE_INFO/WARN/ERROR/ASSERT`; client `DE_INFO/...` |
| Event binding | `DE_BIND_EVENT_FN(fn)`; bit flags via `BIT(x)` |

- `DE_CORE_ASSERT(cond, msg)` takes a **plain string only** — NOT `std::format` args (adjacent-literal pasting; format args fail to compile). `DE_CORE_WARN/ERROR` do take format args.
- In a public header, a member named after its own type spells the type qualified: `Dingo::Mesh* Mesh`, `Dingo::CullMode CullMode = Dingo::CullMode::Back`. MSVC accepts `Mesh* Mesh`, but GCC rejects it (`-Wchanges-meaning`) in every translation unit that includes the header.
- On-screen text is **UTF-8** (v0.6.2): `DrawText`/`GetStringWidth` share the decoder in `src/DingoEngine/Graphics/Utf8.h`, and invalid bytes read as Latin-1. The MSDF atlas bakes Latin-1, printable General Punctuation (U+2010–U+2027, U+2030–U+205E) and U+20AC; anything else draws `?`. Changing the charset must bump `k_FontAtlasCacheFormatVersion` in `Font.cpp`. Only the engine project builds with `/utf-8`, so non-ASCII literals in the test app/examples are hex-escaped.

## Comments — keep them to a minimum

Do not write code comments unless absolutely necessary. A comment must earn its place by stating a load-bearing "why" — a constraint, invariant, or non-obvious consequence the code cannot express itself. Never narrate what the next line does, never leave change-tracking or review commentary ("added X", "fixed Y"), and apply the same restraint to scripts, YAML, shaders, and example code. When in doubt, leave it out.

## Key patterns

- **Entry point**: implement `CreateApplication()` returning a heap-allocated `Application*`; `EntryPoint.h` owns `main()`.
- **Layers**: override `OnAttach/OnDetach/OnUpdate(dt)/OnUIRender` (UI only if ImGui enabled).
- **Teardown**: `Application::OnDestroy()` runs once when `Run()`'s loop exits, with everything still live (v0.6.2 — before that it was called from `~Application()` → `Destroy()`, where virtual dispatch had already stripped the derived class, so overrides never ran; never move it back into `Destroy()`). GPU-resource teardown still belongs in `Layer::OnDetach`, which the engine deliberately runs while the renderer is still answerable: `Renderer::Shutdown()` parks the render thread → layers detach → `Renderer::Destroy()`. So `OnDetach` may still ask for the white texture, a sampler or the swap-chain framebuffer. Managed assets are freed after the layers that borrow them, and audio after that (an `AudioClip` must not outlive the engine that decoded it).
- **Debug window**: one tabbed ImGui window, on unless `ApplicationParams.EnableDebugOverlays = false` (it forces the ImGui backend up even in a UI-less Distribution build). **F3** = Engine, **F4** = Renderer (v0.7: incl. the light budget; v0.8: skinning stats), **F5** = Input, **F6** = Assets, **F7** = Animation (v0.8).
- **In the background** (v0.7.2, former known bug K20): minimized or unfocused. `ApplicationParams::UpdateInBackground` (default false; `Application::SetUpdateInBackground` at runtime) decides. Off, `Application::Run` pauses: no `OnUpdate`, no `AssetManager::Update`, no render, `WaitEvents(0.1)`, the paused time left out of the deltas (the loop also re-bases after the wait that ends a pause), audio still playing, and the first frame runs even unfocused unless minimized (a window that opens unfocused isn't blank). On, it keeps calling `AssetManager::Update` and every layer's `OnUpdate` with the real delta; an unfocused window renders normally, and a minimized one is paced by `Window::WaitEvents` at up to 60 Hz (about 35 on Windows' 15.6 ms timer) and swaps `BeginFrame`/`EndFrame` for `Renderer::SkipFrame()` and skips ImGui. `SkipFrame` waits for the render thread as `BeginFrame` does, so main-thread GPU work can't race it, and runs the GPU garbage collection itself. Until the next `BeginFrame`, `Renderer::IsFrameSkipped()` is true and `Renderer` uploads/clears/draws, `Renderer2D`/`Renderer3D` scenes (latched at `BeginScene`; a skipped 3D `EndScene` only clears its lights) and `SceneRenderer::Render` are no-ops, because every game renders from `OnUpdate`; a skipped `Renderer::Upload` is dropped, not deferred. v0.7.0–v0.7.1 always paused while minimized, which froze networked games. `Input::Update` runs once after each round of `OnUpdate`, before the next poll, so each edge reaches exactly one `OnUpdate`; on resume, the private `Input::Resume` refreshes gamepads and drops the scroll and cursor motion collected while paused. `Window::GetWidth/GetHeight` read 0 meanwhile (`Application::IsMinimized()`; `Renderer2D::GetViewportSize()` keeps the swap-chain size, `Window::GetAspectRatio()` the last aspect with both sides above 0 since v0.8.3, #97). Test: `--test=background` (`--update-in-background=off`); the test app sets the flag.
- **Input** (reworked v0.5.1): frame-coherent snapshot with standard semantics — `Is...Pressed` = edge ("just pressed"), `Is...Down` = held, plus `Released`/`Up` — uniform across keys, mouse buttons, and gamepad buttons (pre-0.5.1 code had `Pressed`/`Down` inverted). Gamepads: `GamepadButton`/`GamepadAxis` codes, `GetGamepadLeftStick/RightStick` (deadzone-filtered), triggers remapped to [0,1], up to 16 pads, `GamepadConnected/DisconnectedEvent`. Mouse adds `GetMouseDelta`/`GetMouseScrollDelta` + `MouseMoved/MouseScrolledEvent`. v0.6.2: `SetCursorMode(Normal/Hidden/Locked)` (raw motion while Locked; `GetMouseDelta` reads zero for 2 frames after a mode change or refocus, because GLFW warps the cursor), `IsAnyKey/MouseButton{Pressed,Down}`, `WindowFocusEvent` + `Window::IsFocused()`. Input reaches the GLFW window through a private `Input::AttachWindow` that `Window` calls. ImGui's GLFW backend would reset a Hidden cursor every frame, so `ImGuiLayer::Begin` sets `NoMouseCursorChange` while the mode isn't Normal. Rumble (v0.8.3, #88): `SetGamepadRumble(low, high, seconds, pad)`/`StopGamepadRumble`/`IsGamepadRumbleSupported`, XInput pads on Windows only (GLFW's gamepads are input only). `Internal::XInput` (`src/DingoEngine/Core/XInput.*`) loads the XInput DLL at run time; `Input` pairs each GLFW joystick id with its XInput user index by replaying GLFW's own assignment (it walks user indices in order, giving each new pad the lowest free id) on every connect and when the window attaches. `Application::Run` calls the private `Input::UpdateRumble` every pass, paused or not, so a rumble ends on time; detaching the window stops them all.
- **Params/builder**: resources are built from fluent `*Params` structs passed to static `Create()` factories: `Texture::Create(TextureParams().SetWidth(512)...)`.
- **Assets** (v0.6): `Application::Get().GetAssetManager()` — UUID `AssetHandle`s (a default-constructed `UUID`/`AssetHandle` is 0 = `k_InvalidAsset` since v0.6.3; fresh ids come from `UUID::Generate()`), path dedup against a configurable asset root (`ApplicationParams.Assets`), `Load`/`LoadAsync` (textures+audio decode on a worker thread, GPU publish in the main-thread pump; shader/model/font async requests amortize one-per-frame on the main thread), typed `Get*` returning nullptr until the object exists, failure keeps the registration (`State == Failed`). A **texture** hot-reload moves the asset to `State == Reloading`, **not** back to `Loading`, while the new pixels decode on the worker: the object stays alive, `Get*` keeps returning the same live pointer and `IsReady()` stays true, so a game gating draws on `IsReady()` never blinks a sprite out while an artist saves. (A shader hot-reload recompiles synchronously inside the poll and never leaves `Ready`.) `GetPendingCount()` counts `LoadAsync` requests only (reloads are counted separately by `GetReloadingCount()`), so it stays usable as a loading-screen gate. Opt-in hot-reload polls timestamps and reloads textures/shaders (and, since v0.8 P9, models with their `.events` sidecar) IN PLACE: `Texture::Reinitialize` swaps contents inside the same object; `Shader::Reload` recompiles past the name-keyed disk cache, bumps `GetGeneration()`, and pipelines/render passes lazily rebuild at bind time (`NvrhiCommandList::SetPipeline`/`SetRenderPass`). A shader compile error during reload keeps the old program (no assert). `AssetManager::Reload` uses the same in-place path for textures/shaders/models (fonts and audio are recreated, invalidating pointers); `Unload` always frees the object, so it invalidates pointers games cache — that's why the debug panel offers Reload but no Unload. The manager OWNS what it loads — never `Destroy()`/`delete` a managed asset; raw factories remain for unmanaged resources. The F6 tab is built from `UI::AssetSummarySection`/`AssetRegistrySection`. See docs/asset-pipeline.md.
- **Audio** (v0.5): `Application::Get().GetAudioEngine()` — `LoadClip` once, then `Play` (returns an `AudioSoundId` for Stop/Pause/volume/pitch/loop/position) or `PlayOneShot` (fire-and-forget) per instance. Positional audio via the `glm::vec3` overloads + `SetListenerPosition`. In the ECS: `AudioSourceComponent` / `AudioListenerComponent`. v0.6.2: distance falloff via `SoundAttenuation` (per sound in `SoundPlayParams::Attenuation`, live via `SetAttenuation`, engine-wide via `SetDefaultAttenuation`). Its defaults equal miniaudio's own (`MaxDistance` = float max), so behaviour is unchanged until a game opts in. `AudioAttenuationModel::None` is miniaudio's inverse model with rolloff 0 (v0.8.3, #96): miniaudio's own `none` bypasses the spatializer, and with it the panning and the sound's volume, which miniaudio keeps there.
- **Bindables**: `Texture`, `GraphicsBuffer`, `Sampler` implement `IBindableShaderResource` for slot binding in a `RenderPass`.
- **Events**: `EventDispatcher dispatcher(event); dispatcher.Dispatch<WindowResizeEvent>(DE_BIND_EVENT_FN(OnResize));`
- **Backend hiding** (hard requirement): EnTT, Box2D, Jolt, ImGui, miniaudio, NVRHI must never appear in a public header. Public APIs use abstract classes + static `Create()` + opaque handles (see `Physics3D`). GLM in public headers is fine.

## Scenes, ECS & physics

- `Scene` owns entities (EnTT, PIMPL'd) and lazily-created per-dimension physics worlds: `Physics2D` (Box2D) / `Physics3D` (Jolt), reached via `Scene::GetPhysics2D()/GetPhysics3D()`. A scene only pays for the dimension it uses.
- **Lifecycle**: `OnStart` → `OnUpdate` → `OnStop`, `IsRunning()`; `Clear()` also stops. `SceneManager` is the default driver: first `SetActiveScene` selects, later switches auto-run `OnStop`(out)+`OnStart`(in); `CreateScene` never activates. Scripts can request a switch via `RequestSceneTransition(name)` (drained by `SceneManager::OnUpdate` after the active scene updates).
- **Rendering**: `SceneManager::OnRender()` → engine-owned `SceneRenderer`, which reads the primary `CameraComponent` (ortho view from 2D `TransformComponent`, perspective from `Transform3DComponent`), submits the scene's lights through `Scene::SubmitLights`, and draws the 3D pass then 2D as overlay. `Scene::RenderEntities/RenderEntities3D` stay public for custom passes. `Render(scene, target)` (v0.8.3, #89) renders into a `Framebuffer` (`SetRenderTarget` for the call, the previous target restored); the projections take the aspect of whatever is drawn into: the target, else the current render target, else the swap chain. `RenderEntities` (v0.8.3, #94) sorts sprites, circles and text into one stream by world z, then kind (sprite, circle, text: the old pass order), then hierarchy depth, and calls `Renderer2D::Flush()` at every change of kind, since each kind batches separately; text takes its world rotation (#93, `TextParameters::Rotation`).
- **Scripts**: `ScriptableEntity` — `OnCreate` → `OnStart` (before physics bake) → `OnUpdate` → `OnDestroy`. A controller script can build the whole world in `OnStart`; keeps game layers tiny (DungeonCrawler3D is the showcase). Calling `DestroyEntity` from inside a script's `OnDestroy` is safe: `DetachScript` unregisters the script *before* running `OnDestroy`, and `Clear`/`StartScripts`/`OnUpdate`/`ForEachScript` all walk handle snapshots rather than the live script map.
- **Components**: 3D mirrors 2D — `Transform3DComponent` (pos, quat, scale), `MeshRendererComponent` (`Mesh*` + color + optional `Material*`), `RigidBody3DComponent`, `Box/Sphere/CapsuleCollider3DComponent` (collider size = fraction of transform scale), `MeshCollider3DComponent` (v0.6.2: the mesh at the FULL transform scale, like the renderer; null `Mesh` = the entity's `MeshRendererComponent::Mesh`). New built-in components must be registered via `DE_INSTANTIATE_COMPONENT` in `src/.../Entity.cpp` or clients can't use them.
- **Lights** (v0.7): `PointLightComponent`, `SpotLightComponent` (position from `Transform3DComponent`, world position under a parent since v0.7.1; spot aim = world `Rotation * Direction`; skipped without its own transform; `Enabled`), `AmbientLightComponent`, and `DirectionalLightComponent` + `Color`/`Intensity` (its legacy `Ambient` adds white ambient AND scales the light by `1 - Ambient`, keeping the old `a + (1-a)·N·L` look; up to 4 count, each adding its `Ambient`; components go in entity order, roughly creation order). `SceneRenderer` calls `Scene::SubmitLights` (→ `Internal::LightSystem`); a custom 3D pass calls it itself. **Default-light rule**: only a registry with NO light component gets a default `DirectionalLightComponent` (a disabled one still counts; a point/spot without a `Transform3DComponent` doesn't, and warns once), and ambient is always set, so an all-lights-off scene goes dark. Registered in `DE_INSTANTIATE_COMPONENT`; no runtime handles. Gameplay queries: `GetLightAttenuation(light, point)` (`Light.h`) is the lit shader's per-light weight (falloff² · cone², no N·L, occlusion or budget) and `Point/SpotLightComponent::ToLight(transform)` builds the light `SubmitLights` submits from a world-space transform (`SubmitLights` passes the world pose; a game passes `GetWorldPosition/GetWorldRotation` under a parent), both on the renderer's own `Graphics/LightMath.h`. See docs/lighting.md.
- **Hierarchy** (v0.7.1): `Entity::SetParent/RemoveParent/GetParent/GetChildren/FindChild`, `GetWorldTransform/Position/Rotation/Scale`, `SetWorldPosition/Rotation` (3D only: a node without a `Transform3DComponent` reports its parent's 3D world), and the 2D `GetWorldPosition2D/SetWorldPosition2D/GetWorldRotation2D/SetWorldRotation2D`. The links live in the engine-internal `Internal::HierarchyComponent` (`Scene/Systems/HierarchySystem.h`), emplaced on the first `SetParent` and never in `DE_INSTANTIATE_COMPONENT`. `Transform3DComponent` and `TransformComponent` are local to the parent (2D: position turns with the parent's rotation, z and rotation add, `Size` is never inherited; a parent counts as identity in a dimension it has no transform for); world values are computed on demand and never cached past one pass, and a root returns its component's own values untouched, which is what keeps flat scenes bit-identical. Every world reader (`RenderEntities3D`, `RenderEntities`, `LightSystem`, `CameraUtils`, `AudioSync`, `PhysicsSync`) goes through `HierarchySystem`; a new reader that treats either transform as world space must too. A per-entity loop uses a `HierarchySystem::WorldMemo`: `Begin` per pass, then each linked entity's world is composed once, parents first, bit-identical to the on-demand functions (without a single link it is the plain component read). Sprites tie-break equal world z on depth (parent first). Destroy and duplicate take the subtree. Physics: bodies bake from the world pose and world scale; dynamic and controller children write back `local = inverse(parentWorld) × simulated`, shallowest first; kinematic children are `MoveKinematic`'d before each step to their end-of-step world pose, extrapolating the nearest ancestor that has a moving body or controller by its velocity (exact for a kinematic ancestor); static children don't follow. 2D does the same through `Physics2D::MoveKinematic`/`GetAngularVelocity` (Box2D's approximate trig leaves ~0.1° of angle error). Since v0.8 P6 a kinematic child's body ignores every ancestor's body (`Physics3D::IgnoreCollision`, a Jolt `GroupFilter` keyed by body-id pairs; a change wakes both) and every ancestor's character controller ignores it (`CharacterController3D::IgnoreBody`, a `BodyFilter` passed to `ExtendedUpdate`). `PhysicsSync::SyncAncestorFilters` works the pairs out at the start of every 3D step and diffs them against the last, so reparenting and runtime bodies take effect on the next step. Nothing else is filtered: dynamic and static children, siblings and 2D bodies still collide. **Sockets** (v0.8 P6): `SetParent(parent, "joint", keep)` (a `const char*` overload keeps a string literal off the bool one) stores an `Internal::SocketComponent` beside the link; world = parentWorld × joint frame × local, the joint frame being `AnimationSystem::JointFrame` (the animator's pose, or the rest pose; position and rotation only, so an FBX root's 0.01 scale isn't inherited). `HierarchySystem::LinkTransform` / `WorldMemo::LinkOf` are where a socket enters, so every reader and the physics prediction follow it; unsocketed links compose exactly as before.
- **Character controllers**: `CharacterController3DComponent` — `Scene::OnUpdate` calls `controller->Update(dt)` itself, so a script only *sets* velocity/direction; never step it by hand. Controllers are rebuilt on `OnStart`, so scripts must not cache a `CharacterController3D*` across an `OnStop`/`OnStart` cycle (use-after-free).
- **Runtime handles** (v0.6.3): public components hold settings only. An entity's live physics body (+ 2D shape ids), character-controller slot and playing sound are engine-internal EnTT components in `src/DingoEngine/Scene/Systems/RuntimeComponents.h`, present exactly while the thing they name is alive (emplaced on create, removed on destroy, `registry.clear<T>()` when the world stops). So copying, assigning or duplicating a component can never alias a body — never add a handle field back onto a public component, and never add the runtime structs to `DE_INSTANTIATE_COMPONENT`. Clients read handles via `Scene::GetRuntimeBody2D/3D`, `GetRuntimeSound`, `GetCharacterController`; 3D's "none" sentinel is `k_InvalidBody3D` = 0xFFFFFFFF, **not 0**.
- `Scene::OnUpdate` runs scripts, steps live worlds, writes simulated transforms back (2D → `TransformComponent`, 3D → `Transform3DComponent`). The 3D step takes `ceil(dt * 60 - 0.1)` Jolt collision steps, clamped to [1, 4] (v0.6.2; it was always 1, which let bodies tunnel through mesh colliders at 30 fps). `Scene::OnUpdate` caps its delta at `PhysicsSync::k_MaxStepTime` = 4/60 s and drops the rest. The cap covers scripts and both worlds alike, so `MoveKinematic` targets and controller velocities match what physics simulates, and a scene runs slow through a stall instead of tunnelling. Before it (K15), a cold shader cache's 1.3 s first frame dropped DungeonCrawler3D's player through the floor. Layers outside a scene still get the real delta.
- Shape is baked into the body at creation (no separate 3D shape handles). Mesh/ConvexHull shapes are cached per world by `Mesh::GetId()` — never by `Mesh*`, whose address a freed mesh can hand to a new one — and each body wraps the shared shape in its own `ScaledShape`. Triangle meshes are Static/Kinematic only (Dynamic falls back to the hull) and one-sided; fast bodies against them need `ContinuousCollision` (Jolt `LinearCast`). Camera picking: `Scene::ScreenPointToRay(screenPos, viewportSize)` + `Ray::IntersectGroundPlane` (perspective cameras only).

## Rendering notes

- Shaders are authored as GLSL, compiled to SPIR-V (ShaderC) and cross-compiled to HLSL/DXBC for D3D. `GLM_FORCE_DEPTH_ZERO_TO_ONE` is workspace-global: SPIR-V already emits [0,1] depth — never enable SPIRV-Cross `fixup_clipspace`. Depth targets must set `isShaderResource = false`.
- **Shader disk cache** (`.cache/shaders/` beside the executable since v0.6.2 — `CacheManager` falls back to `GetUserDataDir("DingoEngine")/cache/<exe stem>` when that is read-only; it used to follow the cwd) is validated at load: each `.spv`/`.dxbc` carries a header with a source hash (+ entry point/shader model) and a format version, so edited inline or file shaders recompile automatically — no manual cache clearing. Bump `k_ShaderCacheFormatVersion` in `NvrhiShader.cpp` when compile options or the shader toolchain change.
- **Renderer2D**: auto-batching quads/circles/MSDF text; default 2000 quads per batch, overflow flushes (configurable via `ApplicationParams`). `EndScene` draws quads, then circles, then text; `Flush()` (v0.8.3) draws what is queued so far. Each flush claims another batch vertex buffer from a pool sized for `MaxQuads`, so a stream that switches kind often costs buffers, not just draw calls. One renderer runs at most `k_MaxScenesPerFrame` (32) `BeginScene`s a frame, the room its volatile camera buffer has on Vulkan (it was 8 before v0.8.3). Each batch pass keeps a pipeline per target format (`Internal::GetFramebufferFormatKey`, `Graphics/FramebufferFormat.h`), picked at flush from the current target: a render target need not match the swap chain, which is BGRA8 on most Linux drivers (L16; before it, 2D drawn into an RGBA8 target there was `VUID-vkCmdDrawIndexed-renderPass-02684`). Examples whose HUD text must stay above a fade or a flying body give it a `HUD_TEXT_Z` (Candlewick and Marionette 0.6, AngryBirds 0.5), since text no longer always draws last.
- **Readback** (v0.8.3, #90): `Texture::ReadPixels(done)` (RGBA8 2D only) records a copy into a staging texture. Inside a frame it joins the frame list (never a list of its own mid-frame: D3D11's `ClearState`), puts back the texture's previous resource state (D3D12 caches the state a framebuffer or binding set left it in) and `done` runs through the private `Renderer::RunAfterFrame` at the next `BeginFrame`/`SkipFrame` (before `Begin`, render thread parked) or at `Shutdown`. Outside a frame it executes its own list and resolves at once, but only while `Renderer::IsRenderThreadParked()` (from `BeginFrame`/`SkipFrame` to `EndFrame`, and before the first frame); between frames (event handlers, post-execution callbacks, `OnDestroy`) the render thread may be submitting, so the whole copy waits in `RunAfterFrame`. NVRHI's `mapStagingTexture` waits for the copy on every backend. Row 0 is the texture's first row: the top of a render target, the bottom of a file image (`ReadImage` flips on load). `SaveToFile` flips non-render-targets back, and `FileSystem::WriteImage` (stb_image_write v1.16, `vendor/stb/include`, encoded to memory and written through `std::ofstream` for Unicode paths) takes its own `flipVertically`. A render target drawn on a Renderer2D quad needs a negative height to stand upright.
- **Renderer3D**: CPU-transforms every submitted vertex every frame. Batches are grouped per `Material*` (null = built-in default); `MaxVertices`/`MaxIndices` (default 64k/96k, configurable) cap one batch = one draw, and a material that outgrows it spills into another chunk (v0.6.3). Only a single mesh bigger than a whole batch is dropped (warn once, `Statistics::DroppedMeshes`). `MeshRendererComponent::Visible = false` is per-entity culling. A batch whose material drew nothing for 300 scenes in a row (`k_MaxIdleBatchScenes`) is released.
- **Lighting** (v0.7): `Renderer3D::SubmitLight(Directional/Point/Spot)` + `SetAmbientLight` are scene-scoped (cleared at each `EndScene`); one renderer runs at most `k_MaxScenesPerFrame` (32) scenes a frame, the room its volatile scene buffer has on Vulkan. A scene that submits nothing gets `Renderer3DParams`' default light (`SetDirectionalLight` replaces it), pixel-identical to pre-v0.7; any submitted light, even an ignored one, switches it off. ≤ 4 directional; point + spot share `GetLocalLightBudget()` (`MaxLocalLights`, capped at 32): frustum-culled, then ranked with ties to the nearer light (distance / range), then submission order (still scenes never flicker), warn once on overflow. Point/spot lights with intensity/range ≤ 0 or non-finite values are ignored; directional lights only reject non-finite ones. No tone mapping until v0.9: lights clip (K17) and pop at the budget edge (K16).
- **Lit shader file** (v0.7): `src/DingoEngine/Graphics/Shaders/Renderer3D_Lit.glsl`, embedded into `DingoEngine.lib` by a premake rule running `scripts/embed.lua`; Release/Distribution always use that copy. Debug/Debug-ASan load it from `DE_ENGINE_SHADER_DIR` (silently using the embedded copy if the file is missing) and hot-reload it via `Internal::WatchUnmanagedShader`, only while the AssetManager's opt-in `EnableHotReload` is on. **Pitfall**: an OLD Debug exe runs the CURRENT .glsl; hide the file to A/B old code.
- **Lit materials** (v0.7): `Renderer3D::CreateLitMaterial(MaterialParams)` (lit shader, `CullMode::None`) with per-MATERIAL `Emissive*`, `Roughness` (0.5) and `Specular` (0 = off); `GetDefaultMaterial()` is shared by every mesh without its own. Texture/sampler **slot 0 only** (anything else warns once and the material is skipped: Vulkan would not reject the invalid binding set); alpha comes from the mesh colour only (lit draws are unsorted and write depth). `EndScene` rebuilds each drawn lit material's binding 1 from its settings every scene (the surface setters don't call `SetUniform`); any `Renderer3D` may draw one; the caller deletes it before the creating renderer shuts down. A custom shader brings its own emissive/specular. `Material::SetTexture/SetSampler` rebuild the cached passes when a slot's pointer changes. A texture created at a freed one's address is still caught at bind time, because every texture draws `GetGeneration()` from one shared counter (v0.8.3, #77, formerly K18); a sampler has no generation, so clear a sampler slot before reusing a freed sampler's address.
- **Skinned models** (v0.8 P4): `Model::LoadFromFile` reads once (`ReadFile(path, 0)`) and applies the static flags (`PreTransformVertices` included, byte-identical to before) unless a mesh has bones or the file is a clip library (clips, no meshes). Skinned files get a `Skeleton` (the subtree under the common ancestor of every bone and animated node; joints a skin vertex can reach come first and `GetSkinJointCount()` is the palette size; `Joint::RestPose`, `InverseBind`, `GetRootTransform()`), skinned `Mesh`es (`HasSkin`, `GetSkinVertices`, 56 B `SkinnedMeshVertex`; `GetVertices()` stays the rest pose in model space for Jolt and `SubmitMesh`) and `AnimationClip`s (T/R/S tracks in seconds, `GetSourceSkeleton`). Assimp gives every imported channel all three tracks. Details: the v0.8 plan's "As built in P4".
- **GPU skinning** (v0.8 P5): `Renderer3D::SubmitSkinnedMesh(mesh, transform, palette, color, material)` draws one skinned mesh per call after the static batches (so a translucent static in front hides it), from a `Mesh`-owned immutable VB/IB (made on the first draw, freed in `~Mesh`, so a `Mesh` is non-copyable). The palette (`Skeleton::GetRestPalette`, or `ComputeGlobalTransforms` + `ComputeSkinningPalette`) goes to a volatile `SkinData` UBO, uploaded only as far as the mesh's last joint (the whole block on D3D11, where partial constant-buffer updates aren't guaranteed). An *instance* is a run of calls with the same palette, transform and colour (a model's submeshes): it uploads once and counts once against `Renderer3DCapabilities::MaxSkinnedInstances` (64, at most `k_MaxSkinnedInstancesLimit` 256), the per-frame budget and the buffer's Vulkan writes; an instance past it is dropped whole (warn once, `Statistics::DroppedSkinnedDraws`). At most `k_MaxSkinJoints` (128) joints a draw; past that, without a skin, or with too few joints passed, it falls back to `SubmitMesh` (rest pose, with the default material if the given one is skinned-only). `SubmitMesh` itself checks each material once a scene and draws a skinned-only one's static meshes with the default material (warn once), so a `SkinnedMeshRendererComponent`'s custom skinned material never builds a static pipeline. The skinned lit shader (`Renderer3D_Lit.glsl` built with `ShaderParams::AddDefine("DE_SKINNED")`, vertex stage only, `SkinData` at binding 4) and the skin buffer are made on the first skinned draw, so apps that never skin don't compile it. Skinned normals use the cofactor of the blended joint matrix, and the loader poses rest normals the same way. A lit material draws through a "skinned twin" keyed by `Material::GetId()` (never reused; `Material` is non-copyable) and resynced every draw, its slot cleared first whenever the source's `GetBindingRevision()` moved, so a sampler slot the source cleared and refilled at a freed sampler's address reaches it. A custom skinned shader declares a `SkinData` block, found by name (`Shader::FindUniformBufferBinding`, bound by `Material::SetSkinUniformBuffer`; static batches bind none) at a binding from 2 to 13 (D3D11's constant-buffer slots) that its textures and samplers leave free, else it draws with the default lit material and a warning. Shader defines enter the bytecode-cache hash and file stem only when present, so define-less caches stayed valid (`k_ShaderCacheFormatVersion` unchanged). `SkinnedMeshRendererComponent { Model*, Color, Material*, Visible }` draws a model through it, posed by its animator (rest palette without one). Animation Test: `--test=anim`, `--anim=bind|bindstatic|pose|clip|blend|layers|events|crowd`, `--anim-clip=Survey|Walk|Run`, `--anim-time=S` (clip, layers: freeze), `--anim-speed=X` and `--anim-phase=F` (blend: the Speed parameter, a frozen phase), `--anim-count=N`, `--anim-static`, `--anim-skeleton` (bones as boxes in a see-through Fox), `--anim-reload` (clip: edits a managed copy on disk); the test app also takes `--no-vsync`.
- **Animator** (v0.8 P6, layers and blends P7): `Graphics/Animator.h`, usable without a scene. `AnimationState::Clip(clip)` or `Blend1D(parameter, {{value, clip}...})` (two neighbouring clips by `SetFloat` value, synced on normalised phase: a blend's `Time` is the shared 0–1 phase advanced at the lerped cycle length). Layers: `m_Layers[0]` full body from the rest pose; `SetLayer(i, AnimationLayer().SetMask(root).Exclude(j).SetWeight(w))` overrides masked joints in index order, every sample starting from the pose underneath so unanimated joints keep it; a null clip on a layer above 0 is "transparent" (the pose below), which is how a layer fades in from nothing and how `Stop` fades out. `PlayOneShot(clip, in, out, layer)` keeps a copy of the interrupted state advancing (time only) and pushes it back `out` seconds before the clip ends (`IsOneShotPlaying` until then; `Stop` always cancels it; marks in the last `out` seconds don't fire); a public `Play` of that same state is a no-op, of anything else cancels the return. Layer 0 samples straight into `m_LocalPoses`; while upper layers apply, its own result is copied to `m_Layers[0].Pose` so an overflow freeze of layer 0 never bakes the upper layers in. A blend side with zero length (no clip, one key) takes the other side's cycle. `Play(state, fadeSeconds, layer)` pushes onto that layer's stack of at most 4 states, each fading in over the ones below (lerp/shortest-path nlerp of local T/R/S); past 4 the current pose is frozen into one entry (`FreezeSource`; a layer above 0 that the last `Evaluate` skipped, at weight 0, is `PoseStale` and is evaluated then, over the layers below re-applied from their cached `Pose` at their `AppliedWeight`, v0.8.3, #82). Playing the state that already plays (even a finished one-shot) is a no-op, so scripts may call it every frame; with fade 0 it completes that state's fade-in. Key cursors per channel step forward and binary-search on a jump. Clip bindings are cached per `AnimationClip::GetId()` (never reused) and looked up by id, never pointed at, so an `Animator` copies safely. At most `k_MaxLayers` (32) layers: a larger index is ignored with a warning. A non-looping state catches up from `CatchUpFrom` (its start, or its latest seek) when it first leads, and its pending one-shot copy shares its `Led`. `AnimationClip` trims tracks whose times and values differ in count. A clip whose `GetSourceSkeleton()` isn't the animator's skeleton is retargeted by name: rotations from the clip, translation only on root-most moving joints (a translation track holding only its rest offset, as exporters key a still `root`, moves nothing and never shadows the hips; `targetRest + (key − sourceRest) × ratio`, ratio = the two rest offsets of that joint from its parent, so units and root scale cancel), every other joint at the target's rest translation and scale. ECS: `AnimatorComponent { DefaultClip, PlayOnStart, Speed, Enabled }` (in `DE_INSTANTIATE_COMPONENT` and the duplicate list) + engine-internal `AnimatorRuntime { unique_ptr<Animator>, SkeletonId }` (`RuntimeComponents.h`), made by `AnimationSystem` on the first `Scene::GetAnimator` or update, or before a body is built (`EnsureAnimators` in `OnPhysicsStart`, `EnsureAncestorAnimators` in `CreateRigidBody`, so a body on a socket starts at `DefaultClip`'s first frame), rebound (back to `DefaultClip`, evaluated at once) when the model's `Skeleton::GetId()` changes (ids, never addresses: a reloaded model can land at the old one's), surviving `OnStop`/`OnStart`, freed by an `on_destroy<AnimatorComponent>` hook (its pool is created in `Connect` so the hook never creates a pool mid-destroy). `Scene::OnUpdate`: scripts → destroy flush → `AnimationSystem::Update` (dt × Speed while Enabled; then each entity's events, copied, to `ScriptableEntity::OnAnimationEvent` via `ScriptSystem::DeliverAnimationEvent`, started scripts only, with `Updating` set so destroys defer) → destroy flush → physics → audio. `Animator::GetStates(layer)` reports a layer's states (clip or blend, fade weight, time) for tooling; the F7 tab lists every live scene's animators (`Scene` joins `Internal::AnimationDebug` on construction) and its last 20 events, which `AnimationSystem::Update` records into a per-scene ring (`EventScratch::Recent`).
- **Animation events** (v0.8 P8): `AnimationClip::AddEvent(t, name)` / `AddEventRange(a, b, name)`, kept as time-sorted `EventMark`s (end before instant before begin at one time). `Model::LoadFromFile` reads `<model stem>.events` beside a model with clips (`Model::LoadEvents`: `<clip> <seconds> <event>` or `<clip> <a>..<b> <event>`, `#` comments, quoted names; bad lines warn with their number). Per layer each `Update`, only the dominant contribution fires (`Animator::Dominant`: the largest fold share `w × Π(1 − w above)`, ties to the newer state; a one-shot's pushed-back `Resume` is flagged `Returning` and takes over at once, after the one-shot's own marks for that frame are collected; a blend's heavier side; a layer above 0 only at weight ≥ 0.5): marks crossed in `(PreviousTime, Time]` (inclusive on a state's first `Update` or after a seek, `Fresh`; a non-looping state catches up from its start the first time it leads, `Led`), with loop wrap (`Wrapped`, set in `Advance` from the unwrapped target, so a step longer than the clip still laps) and reversed playback (begin/end swap). A zero step never touches `Time`. Seeks (`MarkSeek`) close the leading state's ranges at the next `Update`. `OpenRange` keeps the begin's interned name and end time, so every early close sends its `RangeEnd`; when the dominant clip's `GetEventRevision()` moves (a reload, `ClearEvents`), a range whose event is gone or renamed ends at once, and a range matches its marks by index and name. The (state `Serial`, clip) pair identifies the contribution; when it changes, open ranges get a `RangeEnd` (`CloseRanges`), and an end with no begin fires nothing. `AnimationEvent::Name` views an interned copy (`EventMark::Name`, never freed), so a held name outlives `ClearEvents` and a model reload. `GetEventsThisFrame`, `ForEachEventThisFrame`, `IsEventActive`. `AnimationSystem::EnsureAnimator` poses a new or rebound animator with the public `Evaluate()` (no time, no events), so its first real update still fires the clip's start. Delivery copies every event (`EventScratch::Deliveries`) before any handler runs; events for a script that hasn't started (spawned this frame) wait in `EventScratch::Waiting`, as do the `RangeEnd`s the `on_destroy<AnimatorComponent>` hook queues for an animator removed mid-range (`Animator::GetOpenRangeEnds`). `SetSkeleton` (a rebind) keeps the open ranges with a null `Clip` (the old model may be freed) and sets `CloseRangesOnUpdate`, so they end at the next `Update`, which runs `CollectEvents` for them even with no skeleton bound (v0.8.3, #80). `AnimationSystem::Update` calls `Animator::ClearEventsThisFrame` for every animator it skips as disabled, so a poller never re-reads the frame it stopped on (v0.8.3, #81). The Fox's `test/assets/models/Fox/Fox.events` holds its real footfalls (each foot's lowest point) and a Survey range.
- **Model hot-reload** (v0.8 P9): `Model::Reload()` reads `GetFilePath()` (absolute, set by `LoadFromFile`) into a temporary model (`Model::Load(path, refresh)`) and `Adopt`s it, so every object a game holds survives: `Mesh` per submesh index (`Mesh::Reinitialize`: new `GetId()`, GPU skin copy freed; extra submeshes appended, missing ones `Clear()`ed), `Material` per index (slot 0 retargeted), textures per resolved path (the loader's `TextureCache::Reusable` re-reads them in place with `Texture::Reinitialize`; unused ones stay alive, since games copy `DiffuseTexture` into their own materials), clips per name, n-th to n-th (`AnimationClip::Reinitialize`: new id, keys, events; a vanished clip is `Clear()`ed to zero length; new ones appended), and the `Skeleton` while every joint keeps its name and parent (`Skeleton::Reinitialize`, same id, `GetRevision()` bumped; otherwise the old one moves to `m_RetiredSkeletons` and a new one with a new id is adopted, so a Scene rebinds its animators to `DefaultClip`). `GetGeneration()` counts successful reloads; a file that fails to load changes nothing. The Animator takes a reload up by itself: `SyncSkeleton` (rest poses, bindings cleared on a revision change) at the top of `Update`/`Evaluate`, `SampleClip` binds by id on demand, `Sample` resizes key cursors when a clip's channel count changed, and `Advance` wraps a state whose clip shrank under it before stepping (no burst of marks). `AnimatorRuntime::ModelGeneration` makes `EnsureAnimator` re-`Evaluate` a paused animator. The AssetManager's Model policy has `ReloadInPlace` and is watched, with `<stem>.events` as a `Companion` file (`Internal::CompanionWatch`; a missing file reads as the epoch) whose change alone runs `ReloadCompanion` = `Model::ReloadEvents()` (events only, meshes untouched). A reload re-reads a texture only when its file's write time moved; reused textures sit in the temporary model as `Borrowed` (never freed by it). Code-added events are dropped by a reload; bodies already built keep their old shape. Animation Test: `RunReloadChecks` edits a copy in `%TEMP%/DingoAnimationTest`, and `--anim=clip --anim-reload` edits a managed copy on disk while it plays.
- **Marionette** (v0.8 P13, `examples/Marionette`): one `ArenaDirector` script owns the order (brains → fighters → combat → camera → HUD, reading last frame's poses); `Fighter` is one class for the player and the AI, each brain writing a `FighterIntent`. Every combat window is a clip event from the `.events` files beside the five KayKit `Rig_Medium` libraries (`windup`, `hitbox`, `combo`, `dash`, `iframes`, `parry`, `step_l/r`; `Moveset` is the data, `ValidateMoveset` warns about a window that ends after its one-shot's `duration − fadeOut`, where it never fires). Hits are game-side swept spheres on joint sockets, counted only while the attacker is in `Attack` (controllers aren't bodies, so no cast finds a fighter). Block is layer 1 masked from `spine` (`Melee_Block` non-looping so its t≈0 `parry` fires), death a non-looping `Play`, locomotion a `Blend1D` on `Move`. Embedded GLB textures are skipped by the loader, so each PNG goes into a lit material on slot 0. `GameAssets::PollEventChanges` watches `AnimationClip::GetEventRevision()` to re-validate on a live edit. Flags: `--check` (asset, movement, combat and AI checks, read from the log; a failure doesn't change the exit code), `--drive=duel|ramp|circle|strafe|wall`, `--autoplay`, `--tournament=N` (with `--seed` and `--player-tier=1..3`: the stronger tier must win 8 of 10, a mirror is logged only), `--fixed-dt=<s>`, `--steps-per-frame=K` (with `--fixed-dt` and `--autoplay`), `--freeze` with `--pose=<clip>@<s>` / `--move` / `--phase`, `--debug-hitbox`, `--break-hitbox`, `--bout=1..3`, `--lineup`, `--overview`, `--end`, `--hot-reload`, `--live-edit-demo`, `--perf` (with `--autoplay`: mean frame, `Scene::OnUpdate` and render ms over 600 frames), `--graphics=`, `--vsync=`. `--freeze` implies a fixed delta (frozen captures on a real delta differ run to run as the controllers settle). Scripted and `--hot-reload` runs set `UpdateInBackground`, since an unfocused app pauses (a long check hangs; an edit made in another window wouldn't land).
- **Swap-chain render pass** (`VulkanFramebuffer::CreateRenderPass`): a frame is many instances of it — NVRHI ends the pass on every buffer write — so colour is `eLoad`/`eStore` and depth `eLoad`/`eStore` (v0.6.3). Never go back to `eNone`/`eDontCare`: the HUD blends over the 3D world and later batches depth-test against earlier ones. The clears run outside the pass.
- **Swap-chain acquire** (Vulkan, v0.8.3, #79): NVRHI attaches a queued semaphore wait to the next submission from *any* command list, so `VulkanSwapChain::AcquireNextImage` only marks the wait pending and `SwapChain::QueueImageWait()` queues it just before the commands that draw into the image execute: `Renderer::Execute` on the render thread, `ImGuiRenderer::RenderToSwapchain` for a viewport's own list, and `Present` as a fallback. Never queue it at the acquire again. GPU submissions the main thread makes between `EndFrame` and the next `BeginFrame` (event handlers, post-execution callbacks) still race the render thread, the wait included. A failed acquire (a minimized window) leaves `IsImageAcquired()` false; the next `BeginFrame` applies the pending resize and acquires on the main thread while the render thread is parked, or skips the frame (`IsFrameSkipped()`, though the command list is open; ImGui's main viewport isn't drawn), and an ImGui viewport without an image draws nothing.
- **Small Vulkan buffer writes**: NVRHI's `writeBuffer` records a write of up to 64 KiB to a non-volatile buffer with `vkCmdUpdateBuffer`, rounded up to a multiple of 4 bytes read from the source and written to the buffer. `NvrhiGraphicsBuffer` allocates its Vulkan buffers rounded up to 4 bytes, and `NvrhiGraphicsBuffer::Write`, which every `GraphicsBuffer` upload goes through, pads a source whose size isn't a multiple of 4 (v0.8.3). Raw NVRHI buffers pad their own (the ImGui index buffer, #86); volatile buffers are copied byte for byte.
- Custom material shader binding convention: **0** = scene UBO, **1** = the material's own `SetUniform` params, **2+** = textures/samplers, interleaved. The binding set must match shader reflection exactly. The scene UBO (`Renderer3D::CameraData`, std140, volatile, uploaded at the top of `EndScene`) starts with a frozen 96-byte prefix (`ViewProjection`, `LightDirection`, `Ambient`) that custom shaders may declare alone; the lights follow, mirrored by `CameraData` in `Renderer3D_Lit.glsl`. Only ever append. The prefix carries only the first directional light. A binding reflected by more than one stage enters the layout once (`NvrhiShader::CreateBindingLayoutHandle`).
- **Volatile uniform buffers** (`CreateUniformBuffer`, every `Material` UBO, both renderers' camera/scene UBOs) must be written in every frame that binds them (unwritten, Vulkan reads a stale version and D3D12 removes the device). `Renderer::DrawIndexed(Material*)` does this for materials — it re-uploads a material's UBO on its first draw of each frame (`Renderer::Begin` bumps a frame index) and after every `SetUniform` — so a game sets params only when they change; a raw `CreateUniformBuffer` needs its own `Renderer::Upload` every frame it is bound. On Vulkan each holds `GraphicsBufferParams::MaxWritesPerFrame` (default 8) × 4 versions — NVRHI can't recycle a version until it has seen the GPU finish that frame, and up to four frames can look unfinished. A write beyond that is dropped (`[NVRHI] ... maxVersions = N, which is insufficient`) and later draws read the earlier data; before this was sized, a second `Renderer3D` pass in one frame drew with the first pass's camera and lights. D3D11/12 have no such limit.
- Prefer `RGBA8_UNORM` for standard color textures.
- **Blending** (`NvrhiPipeline`, every pipeline): straight-alpha "over", colour `SrcAlpha`/`OneMinusSrcAlpha` and alpha `One`/`OneMinusSrcAlpha`, so a target stays as opaque as what lies under a translucent draw. Before v0.8.2 the alpha factor was `Zero`: text quads (alpha 0 outside the glyph, no discard) made the test app's viewport framebuffer see-through, and ImGui showed its panel as a box around each letter. Swap chains ignore alpha, so games drawing to the window never showed it.
- **Winding** (v0.8.1, GitHub #68/#69): `CreateBox` and `CreateSphere` are counter-clockwise seen from outside (so are well-formed model files; the loader keeps a file's winding), and `MaterialParams` defaults to `CullMode::Back` + `FrontCounterClockwise = true`. NVRHI flips the Vulkan viewport to D3D's, so the flag means the same on all three backends. Before v0.8.1 `Material` dropped the flag (clockwise fronts) and `CreateSphere` was wound inward, so `CullMode::Back` drew boxes and models inside out. Lit materials and the skinned twin still force `CullMode::None`. Renderer3D keeps a mirrored (negative-determinant) transform's index order, so a culling material draws such an entity inside out. The Mesh 3D Test (`--test=mesh`, `--mesh=box|sphere`, `--mesh-angle=<deg>`) checks both primitives' winding at start.

## Failure contracts

- `Model::LoadFromFile`, `Font::Create` and (v0.6) `Texture::CreateFromFile` return `nullptr` on failure, so a wrong path fails loudly, not with a broken object. Since v0.6.3 every raw file factory (those three, `Shader::Create`/`CreateFromFile`, `AudioEngine::LoadClip`) resolves a relative path through `Internal::ResolveRawAssetPath` (`src/DingoEngine/Asset/AssetPath.h`): under the asset root if the file exists there, else unchanged, i.e. cwd-relative. The `AssetManager` layers its own contract on top: failed loads stay registered with `State == Failed` and `Get*` returns nullptr.
- Physics per-body calls are no-ops (getters return identity) on invalid/stale handles.
