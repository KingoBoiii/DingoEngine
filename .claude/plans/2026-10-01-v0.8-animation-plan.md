## 2. Design

### 2.1 Transform hierarchy

**Storage is engine-internal.** An `Internal::HierarchyComponent { Parent, FirstChild, NextSibling,
PrevSibling, ChildCount, ParentJoint }` (EnTT handles, `src/` only, like the runtime components). It is
emplaced on the first `SetParent`, so a flat scene pays nothing. It is never in
`DE_INSTANTIATE_COMPONENT`. Links are kept consistent by the API; no public component can point an
entity at a parent that doesn't list it as a child.

**Public API** (`Entity.h`, implemented in `Entity.cpp` and `Systems/HierarchySystem.cpp`):

```cpp
void   SetParent(Entity parent, bool keepWorldTransform = true);
void   SetParent(Entity parent, std::string_view joint, bool keepWorldTransform = false); // socket, §2.5
void   RemoveParent(bool keepWorldTransform = true);
Entity GetParent() const;                  // invalid for a root
uint32_t GetChildCount() const;
void   ForEachChild(const std::function<void(Entity)>& fn) const;
std::vector<Entity> GetChildren() const;
Entity FindChild(std::string_view name, bool recursive = true) const;

glm::mat4 GetWorldTransform() const;
glm::vec3 GetWorldPosition() const;
glm::quat GetWorldRotation() const;
glm::vec3 GetWorldScale() const;
void SetWorldPosition(const glm::vec3& position);   // writes the local value that produces it
void SetWorldRotation(const glm::quat& rotation);
```

**Semantics**:

- `Transform3DComponent` becomes **local to the parent**. A root's local *is* its world, so every
  existing scene is unchanged. World = `parentWorld × local` (full T·R·S).
- 2D (if D2 is accepted): world position = parent position + R(parent rotation) · child position,
  rotation adds, z adds. `Size` is a dimension, not a scale, so it is **not** inherited.
- A 3D child of a parent with no `Transform3DComponent` treats that parent as identity.
- **World transforms are computed on demand** by walking up the parent chain (depth × one mat4
  multiply). Nothing caches them past a single pass, so a script or layer that edits a transform
  between `OnUpdate` and render can never draw a stale world. A pass over many entities memoizes
  each world for that pass only (added in P3 after the 10k-entity case cost 1.57x, §7).
- `SetParent` rejects cycles and cross-scene parents (`DE_CORE_ERROR`, no-op). Child order is
  insertion order.
- `keepWorldTransform` decomposes the new local from the world. Rotation plus non-uniform parent
  scale produces shear that T·R·S can't hold; it is approximated and documented.
- `DestroyEntity` **destroys the subtree**, children first, so a child's `OnDestroy` can still read
  its parent. Deferred destroy during scripts defers the whole subtree.
- `DuplicateEntity` **duplicates the subtree**; the clone gets the source's parent.
- Visibility is **not** inherited (`MeshRendererComponent::Visible` stays per entity). Out of scope
  for v0.8 (§2.9).

**Every world reader switches to world values**: `RenderEntities3D`, `RenderEntities` (2D),
`LightSystem` (position and spot aim), `CameraUtils` (one shared view helper instead of the copy
in `ScreenPointToRay`), `AudioSync` (listener position and orientation, source positions).

**Physics under a parent**:

| Body | Rule |
|---|---|
| Any | Created from the **world** transform; collider sizes use world scale |
| Dynamic | Simulated in world space; write-back stores `local = inverse(parentWorld) × simulated`. Moving the parent does not drag it |
| Kinematic with a parent | The engine `MoveKinematic`s it to its world transform every step, so a hitbox on a sword or a part of a moving platform follows. A kinematic root is unchanged (scripts drive it) |
| Static | Placed once; does not follow |
| Character controller | Placed from world; write-back as Dynamic. Docs: keep controllers on roots |

No existing scene has a parent, so none of these rules changes current behaviour.

**As built in P1** (2026-10-01, after the P1 review):

- `HierarchyComponent` also stores `LastChild`, so appending a child is O(1). `ParentJoint` waits
  for P6. Storage and the world maths live in `src/DingoEngine/Scene/Systems/HierarchySystem.*`.
- World transforms are composed root-first, so a child's world is bit-for-bit
  `parentWorld × local`; a root returns its component's values untouched (no identity multiply,
  no decompose), which is what keeps flat scenes pixel-identical.
- `SetParent(Entity())` detaches, like `RemoveParent`; setting the current parent is a no-op that
  keeps child order. `keepWorldTransform` on an entity without a `Transform3DComponent` can't keep
  anything, so its 3D descendants move and the engine warns once per call. A parent with a
  zero-scale axis can't be inverted: `keepWorldTransform`, `SetWorldPosition/Rotation` and the
  physics write-back keep the old local.
- `DestroyEntity` destroys children before the entity's own `OnDestroy` and again after it, so a
  child parented to the entity inside that `OnDestroy` dies with it; every step re-checks that a
  script didn't destroy the entity meanwhile.
- Dynamic and controller children are written back after the step, shallowest first, so nested
  simulated bodies are solved against their parent's new pose.
- Kinematic children (review M2): `MoveKinematic`'d before the step to their *end-of-step* world
  pose. The nearest ancestor with a moving body or a controller is extrapolated by its velocity
  (`Physics3D::GetLinearVelocity/GetAngularVelocity`, the same integration Jolt applies), which is
  exact for a `MoveKinematic`'d ancestor (measured gap 1e-6 vs 0.04 without the prediction) and
  approximate for a dynamic ancestor or a controller (this step's contacts and gravity are unknown).
- Primitive collider sizes use `abs(world scale)`; a mesh collider keeps the sign.
- Bodies in one hierarchy collide with each other (review M3, deferred to P6, see §2.5).

**As built in P2** (2D, D2):

- `HierarchySystem::WorldPose2D` composes `TransformComponent`s root-first: position turns with
  the parent's rotation, z and rotation add, `Size` is never inherited; a root returns its values
  untouched. Readers: `RenderEntities` (sprites sort by world z), circles, text, the ortho camera,
  2D audio, 2D physics bake and write-back.
- The unsuffixed `Entity::GetWorld*`/`SetWorld*` stay 3D only (P2 review: a "3D if present, else
  2D" switch broke grouping nodes without a `Transform3DComponent`). 2D has
  `GetWorldPosition2D`/`SetWorldPosition2D`/`GetWorldRotation2D`/`SetWorldRotation2D`.
  `keepWorldTransform` rewrites the 3D local of a 3D entity and the 2D local of any other.
- Mixed trees need no special case: a parent with no transform in a dimension is identity there,
  and a 3D entity's `TransformComponent` stays at the origin.
- Sprites sort by world z, then depth (a child at its parent's z draws on top). Readers check
  `HierarchySystem::AnyLinks` once per pass and keep the plain component path when nothing is
  linked.
- The render and audio readers have no automated check: the engine can't read pixels back or
  query the audio listener. The 2D render proof is the Hierarchy Test's `--hierarchy=probe2d` view,
  measured from captures; the menu A/B covers text and the ortho camera.
- `Physics2D` gains `MoveKinematic` (Box2D `b2Body_SetTargetTransform`) and `GetAngularVelocity`,
  so 2D kinematic children follow with the same prediction as 3D. Box2D's approximate sin/cos/atan2
  leave a body's angle about 0.1° from its transform.

**As built in P3**:

- `--hierarchy=stress` / `stressflat`: 10,110 box meshes in depth-4 trees (10 x 10 x 10 x 9), the
  top three levels spinning, against the same entities flattened to roots at the same world
  transforms with the same entities spinning in place. Means over 120 frames after a 2 s warm-up,
  two runs each, Release, VSync off, RX 7900 XTX, Vulkan:

  | Readers | Flat: frame / `RenderEntities3D` | Parented: frame / `RenderEntities3D` | Ratio (`RenderEntities3D`) |
  |---|---|---|---|
  | On demand (every entity walks its ancestors) | 5.3, 4.8 / 3.8, 3.5 ms | 7.5, 6.8 / 6.0, 5.5 ms | 1.57x |
  | Per-pass memo | 4.9, 4.7 / 3.6, 3.4 ms | 5.0, 4.7 / 3.7, 3.5 ms | 1.04x |

  `HierarchySystem::WorldMemo`: each pass that reads many entities (`RenderEntities3D`,
  `RenderEntities`, `LightSystem`, `AudioSync`, the physics bake, child write-back and kinematic
  follow) works out each linked entity's world at most once, parents first, into a scratch buffer
  the next pass invalidates; without a single link it is the plain component read. Only a parent's
  world is stored (0.82 -> 0.65 ms of transform work in the parented scene). A temporary memcmp
  against the on-demand functions at every reader found 0 mismatches (36.4M render transforms in the
  stress scene; the Hierarchy Test's write-back and kinematic follow; sprites, circles, text,
  lights, audio and the bake in the test app, DungeonCrawler3D, EchoVault and AngryBirds).
  What is left (temporary in-engine profile, 10,110 entities): ~0.1 ms for the parent x local
  multiply and ~0.1 ms for the two `HierarchyComponent` lookups per entity; the bulk of
  `RenderEntities3D` is Renderer3D's CPU vertex transform (~3 ms) in both scenes.
  A flat scene costs what it did on v0.7: the same flat scene in a temporary harness built against
  `510c27a` and against this tree, six alternating runs each, measured `RenderEntities3D`
  3.47 vs 3.60 ms and frame 4.41 vs 4.55 ms (means), with per-run differences of -0.02 to +0.33 ms
  inside the 3.3-4.2 ms spread of single runs; the in-engine profile puts the flat path's own cost
  at +0.01-0.02 ms.
- DungeonCrawler3D's `Character` is a parented rig: a root at the feet (yaw, lean, bob), a joint
  entity per hip and shoulder, each part mesh under its joint and the sword under the right
  shoulder. `Update` only sets the root pose and joint rotations; the per-part world maths
  (`PlaceBone`) is gone. A temporary side-by-side check over ~151k part samples per run (walking,
  attacking, recoiling, by day and by night) measured at most 2.1e-6 position and 2.4e-5 deg
  rotation against the old maths. The night lantern and the attack ring stay hand-placed: both
  follow the player's body, a rolling dynamic sphere that would swing children around, and the
  lantern must not lean or bob with the rig.
- EchoVault's sentry eye is parented to the sentry on its front face (local values divided by the
  sentry's non-uniform scale to keep it round), and line of sight starts at the eye's world
  position. The old ray started inside the sentry's own box, which Jolt's ray cast (convex shapes
  are solid) reports as a hit at distance 0, so line of sight was always blocked; from the eye, just
  outside the box, it no longer is. Observed in play (temporary spawn beside a sentry): detections
  every ~2.7 s and SPOTTED! on the HUD.

### 2.2 Loading skeletons, skins and clips

**One `ReadFile`, two paths.** Read without `PreTransformVertices`. If no mesh has bones, apply
`importer.ApplyPostProcessing(aiProcess_PreTransformVertices)` and continue down today's path. P4
proves the static output is byte-identical (hash the vertex and index arrays of Duck, the five
DungeonCrawler3D part OBJs and every other model in `examples/`); if it isn't, fall back to a
second `ReadFile` with today's flags.

**Skinned path** (`Triangulate | GenSmoothNormals | FlipUVs | JoinIdenticalVertices |
LimitBoneWeights`, `AI_CONFIG_IMPORT_FBX_PRESERVE_PIVOTS = false` so FBX joint names survive):

- **`Skeleton`** (new public class): joints = every bone node plus its ancestors below the armature
  root, **ordered parents first** so the global pose is one forward pass. Per joint: name, parent
  index, inverse bind matrix (`aiBone::mOffsetMatrix`), bind-pose local T/R/S. The transform above the
  armature root folds into `Skeleton::GetRootTransform()`.
- **Skinned `Mesh`**: vertices stay in mesh space (glTF ignores a skinned mesh's node transform);
  per-vertex joints remapped to skeleton indices, top 4 weights, renormalised. `Mesh` gains
  `HasSkin()` and `GetSkinVertices()`. `GetVertices()` keeps returning bind-pose `MeshVertex`es, so
  Jolt and the static path keep working: a skinned mesh drawn through `SubmitMesh` shows its bind
  pose.
- **Rigid meshes inside the skeleton** (a sword exported as a child of the hand bone) are bound to
  that joint with weight 1, so attached props animate with no extra setup.
- **`AnimationClip`** (new public class, owned by its `Model`): name, duration in seconds
  (`mDuration / mTicksPerSecond`, 25 ticks/s when 0), one channel per target joint *name* with
  T/R/S keys and step or linear interpolation. Channels for nodes outside the skeleton are dropped
  (warn once per clip).
- **`Model`** gains `IsSkinned()`, `GetSkeleton()`, `GetAnimationCount()`, `GetAnimation(i)`,
  `FindAnimation(name)`. A file with a skeleton and clips but no meshes is a **clip library**, which
  is how several characters share one set of animations.

### 2.3 GPU skinning

**Shader**: `Renderer3D_Lit.glsl` gets `#ifdef DE_SKINNED` in its **vertex stage only**, so the lit
fragment code exists once and v0.9's shadow pass can reuse the same skinned vertex stage. To compile
it twice, `ShaderParams` gains `Defines` (passed to ShaderC's `AddMacroDefinition`, included in the
disk-cache hash, kept across `Shader::Reload`; bump `k_ShaderCacheFormatVersion`). Custom shaders get
the same switch.

**Per-draw data** (`std140`, 8384 B, under Vulkan's guaranteed 16 KB):

```glsl
layout(std140, binding = 4) uniform SkinData   // any free binding <= 13; found by name
{
    mat4 Model;
    mat4 NormalMatrix;
    vec4 Color;
    mat4 Joints[128];    // model space: RootTransform x global x inverseBind
};
```

- **Bound by name.** `Material` looks for a reflected uniform block called `SkinData` and binds the
  renderer's palette buffer there (`Material::SetSkinUniformBuffer`, mirroring
  `SetSceneUniformBuffer`). The binding-0/1/2+ convention is untouched. The lit skinned variant uses
  binding 4. Custom skinned materials pick any free binding ≤ 13 (D3D11 has `b0`–`b13`); the bake
  rejects a larger one with a clear error.
- **Upload**: one volatile UBO written once per skinned draw, with
  `MaxWritesPerFrame = Renderer3DParams::MaxSkinnedDraws` (default 64; 8 KB × 64 × 4 = 2 MB on
  Vulkan). Beyond the budget: skip the draw, warn once, count `Statistics::DroppedSkinnedDraws`.
  This is the established volatile-UBO path (CLAUDE.md, "Volatile uniform buffers"), not a new
  mechanism.
- **Vertex buffer**: 56 B skinned vertex (pos, normal, uv, `RGBA16_UINT` joints, `RGBA32_FLOAT`
  weights), immutable VB/IB owned by the `Mesh`, created once at load and freed in `Mesh::Destroy`.
  Colour comes from `SkinData`, not the vertex.
- **API**: `Renderer3D::SubmitSkinnedMesh(const Mesh*, const glm::mat4& transform,
  std::span<const glm::mat4> joints, const glm::vec4& color, Material* = nullptr)`. Joint data is
  copied into a per-frame arena; `EndScene` draws skinned submissions after the static batches.
- **Materials**: a skinned draw with a lit material (default or `CreateLitMaterial`) uses that
  material's skinned twin, made and cached by `Renderer3D`. A custom material without `SkinData`
  warns once and draws with the default skinned material.
- **Joint cap**: a skin with more than 128 joints warns once and draws its bind pose through the
  static path.
- Rejected: CPU skinning in `SubmitMesh` (D5).

### 2.4 ECS components

- **`SkinnedMeshRendererComponent { Model* Model; glm::vec4 Color{1}; Material* Material = nullptr;
  bool Visible = true; }`** draws every submesh of `Model`, posed by the entity's animator (bind
  pose without one).
- **`AnimatorComponent { std::string DefaultClip; bool PlayOnStart = true; float Speed = 1.0f;
  bool Enabled = true; }`**: settings only.
- **Runtime**: `Internal::AnimatorRuntime { std::unique_ptr<Animator> }`, created on the first
  `Scene::GetAnimator(entity)` or animate pass, removed with the entity or component. An
  `Animator*` stays valid while both live. Unlike a character controller it **survives
  `OnStop`/`OnStart`**, because animation doesn't depend on a physics world.
- **Order in `Scene::OnUpdate`**: dt cap → scripts → destroy flush → **animate** (events delivered
  here, with destroy deferred) → destroy flush → physics (so a kinematic hitbox on a socket follows
  this frame's pose) → audio.
- Both components go into `DE_INSTANTIATE_COMPONENT` and the `DuplicateEntity` list.
  `RenderEntities3D` submits skinned renderers.

### 2.5 The animator

```cpp
Animator* anim = scene->GetAnimator(entity);
anim->Play(AnimationState::Clip(model->FindAnimation("Idle")), 0.2f);
anim->Play(AnimationState::Blend1D("Speed", { {0.0f, idle}, {1.5f, walk}, {4.0f, run} }));
anim->SetFloat("Speed", velocity);
anim->SetLayer(1, AnimationLayer().SetMask("spine_01").SetWeight(1.0f)); // upper body
anim->Play(AnimationState::Clip(wave), 0.15f, /*layer*/ 1);
anim->PlayOneShot(slash, 0.1f, 0.2f);   // returns to whatever was playing underneath
```

- **Sampling**: per channel, a cached key cursor (binary search on a jump). Clips bind to a skeleton
  by joint name; the binding table is cached per (clip, skeleton) and rebuilt when the model's
  generation changes (§2.7).
- **Blending**: local T/R/S per joint; lerp and shortest-path nlerp. A cross-fade evaluates both
  states and blends by fade weight. A `Blend1D` blends the two neighbouring clips and syncs them on
  **normalised time**, so walk and run feet stay in phase.
- **Layers**: layer 0 is the full body; higher layers **override** within a joint mask (a subtree
  root plus optional exclusions) at a weight. Additive layers are out of scope (§2.9).
- **One-shots** play on a layer over its current state and fade back to it.
- **Retargeting by name** (the *Marionette* requirement: three fighters with one clip set). If the
  clip's source skeleton isn't the target: rotations from the clip; translation only on the
  root-most animated joint (the hips), scaled by target ÷ source bind hip height; every other
  joint keeps the target's bind translation. Needs the same joint names and rest orientations (one
  rig template, different proportions). Cross-topology retargeting is out of scope.
- **Sockets**: `child.SetParent(character, "hand_r")` puts the child at `characterWorld ×
  RootTransform × globalPose[joint] × local`, using this frame's pose. A sword in a hand, a lantern
  on a belt, a light on a staff. A kinematic child ignores collisions with its ancestors' bodies
  (Jolt group filter + controller body filter); deferred from P1 review M3, so a socketed hitbox
  doesn't shove its own character.
- **Pose → palette**: global forward pass → `Joints[i] = RootTransform × global[i] × inverseBind[i]`.
  `SkinData.Model` is the entity's world transform.

### 2.6 Timeline events

- **`AnimationEvent { std::string_view Name; float Time; AnimationEventType Type; const
  AnimationClip* Clip; uint32_t Layer; }`**, where `Type` is `Instant`, `RangeBegin` or `RangeEnd`.
- **Authoring** (D3): `clip->AddEvent(0.42f, "footstep")`, `clip->AddEventRange(0.32f, 0.48f,
  "hitbox")`, and a sidecar text file next to the model, `<model>.events`, reloaded with it:

  ```
  # clip     time         event
  Walk       0.10         footstep_l
  Walk       0.55         footstep_r
  Slash      0.32..0.48   hitbox
  ```

- **Which clip fires**: per layer, only the **dominant** contribution: the heavier side of a
  `Blend1D`, the incoming state once its fade weight passes 0.5, a one-shot until it starts fading
  out. Walk and run blended 50/50 never double a footstep, and a cancelled swing never opens a
  hitbox.
- **Crossing rule**: an event fires when playback crosses its time in `(previous, current]`,
  including loop wrap. A range fires `RangeEnd` when the clip stops being dominant mid-range, so a
  cancelled swing still closes its hitbox.
- **Delivery**: `ScriptableEntity::OnAnimationEvent(const AnimationEvent&)` (default no-op) on the
  entity's script during the animate pass, plus polling: `Animator::IsEventActive("hitbox")` and
  `Animator::ForEachEventThisFrame`.

### 2.7 Model hot-reload, in place

The roadmap promises rigs are "hot-reloadable assets like everything else". Today a model `Reload`
destroys and recreates it.

- `Model::Reinitialize` swaps contents inside the same object and bumps `GetGeneration()`, the
  same shape as `Texture::Reinitialize` and `Shader::Reload`.
- `Mesh` objects at the same submesh index are reinitialised in place and get a **new** `GetId()`
  (Jolt keys its shape cache on it). Extra submeshes are appended; missing ones become empty.
- `AnimationClip` objects are matched by name and reinitialised in place, so an `Animator` holding
  one keeps playing the new keys. A clip that disappears becomes zero-length. The `.events` sidecar
  is watched with its model.
- The model row in the `AssetManager` gains `ReloadInPlace`; the F6 checkbox label stops saying
  "textures & shaders".
- This is the **first phase to cut** if the milestone runs long; it isn't on any other phase's
  path.

## 4. Verification

**Hierarchy Test** (`--test=hierarchy`, MeshColliderTest pattern: a real `Scene`, `Check(bool, name)`
list, orbit camera):

- A solar-system chain (sun → planet → moon) with spinning parents; a hull with a turret and a barrel.
- Checks: world = parent × local; `keepWorldTransform` both ways; reparent across depths; cycle
  rejected; cascade destroy (also from a script's `OnDestroy`); subtree duplicate; a dynamic body
  under a moving parent stays where physics puts it; a kinematic child follows; a point light on a
  child lights from the child's world position.
- A 10k-entity, depth-4 tree with the F4 frame time recorded, to judge on-demand world transforms.

**Animation Test** (`--test=anim`, using `Fox.gltf`):

- Modes: `--anim=bind|clip|blend|layers|events|crowd`.
- Speed slider driving Survey→Walk→Run; an upper-body layer mask from `b_Spine01_02` playing Survey
  over Walk; a one-shot button; the event log; the skeleton overlay; a box socketed to `b_Head_05`.
- `crowd`: 64 foxes (the `MaxSkinnedDraws` default), then 65 → warn once, F4 shows one dropped.
- Pass criteria: no pop at fade boundaries; footsteps fire exactly once per step across the whole
  blend; frozen-frame captures stable (playback paused).

Also:

- **Backends**: Vulkan, DX11 and DX12 for P5 onwards. The skinned `SkinData` binding and `uvec4`
  joint inputs are where the DXBC path goes wrong.
- **A/B identical where nothing should change** (P1–P4) and **paired with a deliberately broken
  build**, because a passing "before" proves nothing on its own (`.claude/reviews/2026-07-29-v0.6.0-review.md`).
- **Hot-reload**: re-export a clip while running; break the file → the old model keeps playing and
  the reload logs one error.
- **Perf sanity**: F4 frame time for 1, 16 and 64 skinned foxes, recorded in the review.

## 6. *Marionette* (P13): scope sketch only

A new example under `examples/Marionette`, with the new-executable checklist: `copyAssimpRuntime()`
(`examples/<X>/premake5.lua`, last line), the root `premake5.lua` Examples group (`:313-321`),
a `build-release.yml` packaging job (EchoVault's at `:483-531` is the template), `.vscode`
`launch.json` and `tasks.json` entries, and the README/CLAUDE.md example lists.

The vertical slice: one arena, the player against three escalating fighters that share one clip
set and one rig template at different proportions (retargeting by name, §2.5).

- Reach and hit windows come only from `hitbox` range events; the game holds no combat timers.
- Telegraphs and recoveries are cross-fades long enough to read.
- Locomotion is one `Blend1D` on speed; a parry is an upper-body layer over it.
- Lunges move the fighter between `lunge` range events (no root motion in v0.8).
- Weapons are socketed to the hand joint; hit tests are v0.5 shape casts from the socket's world
  transform.

**Assets**: needs rigged, animated, redistributable characters on one shared skeleton. Candidates
are CC0 packs (Quaternius, Kenney); Mixamo's terms don't allow redistributing raw files in a
public repo. Downloading needs the user's go-ahead and a licence check, so it is decided in the
*Marionette* plan, written after P10.

## 7. Risks

| Risk | Mitigation |
|---|---|
| Splitting `PreTransformVertices` out of `ReadFile` changes static model output | Hash A/B on every repo model in P4; fall back to a second `ReadFile` |
| Assimp 5.3 skin quirks (FBX pivot nodes, non-topological joint lists, skinned-mesh node transforms) | `PRESERVE_PIVOTS = false`; reorder joints parents-first; Fox plus one CC0 humanoid in P4 |
| `SkinData` binding or `uvec4` inputs miscompile on DXBC | Test DX11/DX12 in P5, not at the end; the bake rejects bindings > 13 |
| Vulkan volatile-version exhaustion with many skinned draws | `MaxSkinnedDraws` sizes `MaxWritesPerFrame`; overflow warns and counts |
| On-demand world transforms get slow on deep trees | Measured in P3 (1.57x); a per-pass memo brought it to 1.04x |
| Physics under parents surprises users | Rules table in the docs; nothing changes for flat scenes |
| Events double-fire in blends or across loop wrap | Dominant-contribution rule; the Animation Test checks one fire per step |
| Model reload invalidates pointers (it does today) | In-place `Model::Reinitialize` (P9); cut P9 before shipping a half version |
| KNOWN-BUGS K14 (test app crashes when minimised) hits the new tests | Known; don't minimise during captures |

## 8. Decisions

D1–D4 settled 2026-10-01 by the user. D5 and D6 are proposed and stand unless the user objects.

| # | Decision | Chosen | Rejected |
|---|---|---|---|
| D1 | What a joint is | **Internal skeleton + sockets**: joints live in the skinned model's pose buffer; entities attach with `SetParent(entity, "joint")` | Joints as entities (Unity-style): 24–65 entities per character and ECS writes per joint per frame, the "pile of entities" v0.8 exists to remove |
| D2 | 2D parenting | **In v0.8** (+1 d, P2): otherwise `SetParent` silently does nothing for 2D entities | 3D only, 2D later |
| D3 | Event authoring | **Code API + a `.events` sidecar text file** next to the model (no new vendor) | Code only (timings drift with the art again); vendor a JSON library for a richer format |
| D4 | Release shape | **One v0.8.0 PR at the end**, like v0.7 | Hierarchy (P1–P3) as its own early PR |
| D5 | Skinning on GPU or CPU *(proposed)* | **GPU** (the roadmap's wording; per-draw volatile `SkinData`) | CPU skinning inside `SubmitMesh`: no shader work and every custom material works, but the vertex cost doubles for characters, and v1.0 would redo it |
| D6 | How components reference models *(proposed)* | **Raw `Model*` + in-place model reload** (P9), the existing `MeshRendererComponent` pattern | `AssetHandle` in components: a new pattern and a map lookup per entity per frame |
