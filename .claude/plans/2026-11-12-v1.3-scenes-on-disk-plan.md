# v1.3 — Scenes on Disk

The roadmap entry is [ROADMAP-1.x.md](../../ROADMAP-1.x.md#v13--scenes-on-disk). A minor release,
so it only adds API (`docs/versioning.md`). No header moves and no include goes away: the engine
layers are 2.0 (R4). Ships after v1.2.1 (#186).

## Context (master `be8a5d2`)

- **Components.** The built-ins are instantiated by hand in `src/DingoEngine/Scene/Entity.cpp:455-497`,
  and the same list is copied again in `Scene::DuplicateSubtree` (`Scene.cpp:180-209`). The templates
  in `Entity.h:43-56` have no bodies, so **a game can't add a component type of its own today**:
  `AddComponent<MyType>` fails to link. `IDComponent` and `TagComponent` are read-only
  (`Entity.cpp:461-464`).
- **Runtime state** is never on a public component (`.claude/rules/engine-invariants.md`,
  `RuntimeComponents.h`). A serializer walks the public components plus the hierarchy
  (`Entity.h:119-122`) and the active flag (`Entity.h:170-174`).
- **Asset references are raw pointers**:
  - `Texture*` (`Components.h:107`), `Font*` (`:138`), `Mesh*`/`Material*` (`:495`, `:506`),
    `Model*` (`:553`), `ParticleEffect*` (`:629`), the mesh collider's `Mesh` (`:789`), and
    `std::shared_ptr<AudioClip>` (`:936`).
  - Buses are an opaque `AudioBusId` (`AudioTypes.h:27`), named through `FindBus` (`AudioEngine.h:193`).
  - Meshes, materials and particle effects aren't AssetManager types (`AssetTypes.h:22-35`).
- **Asset handles change every run**: `AssetHandle::Generate()` on each import
  (`AssetManager.cpp:1003`). The stable identity is the logical VFS path
  (`AssetMetadata::FilePath`, `FindByPath` at `AssetManager.h:234`, the pack keys). There is no
  pointer→handle lookup.
- **Entity references are already UUIDs**: `Constraint3DComponent::Other` (`Components.h:818`) and
  `ParticleEventComponent::Binding::Emitter` (`:658`), remapped by hand in `DuplicateEntity`
  (`Scene.cpp:131-152`). `RagdollComponent::Recipe` is a name inside the model's `.ragdoll` sidecar
  (`:896`).
- **Scripts**: one per entity, in `std::unordered_map<entt::entity, std::unique_ptr<ScriptableEntity>>`
  (`Scene/Systems/ScriptSystem.h:73`). A second attach replaces the first with a warning. Scripts take
  constructor arguments, often a game context (`examples/EchoVault/src/GameScripts.cpp:174`). There
  is no name registry.
- **SaveData** (`Core/SaveData.h`) is a typed tree with JSON through vendored nlohmann 3.11.3
  (`SaveData.cpp:50`, `:88`), sorted keys and `int64` integers. `ReadFile` reads from disk, not the
  VFS (scenes need `VirtualFileSystem::ReadBytes`, `VirtualFileSystem.h:71`). No yaml-cpp in `vendor/`.
- **Duplication**: `DuplicateSubtree` is private (`Scene.h:465`) and works within one scene
  (`Scene.cpp:159-233`). `DuplicateEntity` doesn't clone scripts.
- **Start-up**: `OnStart` runs the scripts' `OnStart`, then `StartPhysics`, then PlayOnStart sounds
  (`Scene.cpp:934-962`). Bodies are built in registry view order (`PhysicsSync.cpp:64-94`). A loader
  creates components before `OnStart`, and calls `CreateRigidBody` (`Scene.cpp:1033-1040`) for
  anything added while the scene runs.

## Decisions (proposed; the alternative in italics)

- **D1 Text format: JSON through the vendored nlohmann.** A small emitter in `src/` writes it: 2-space
  indent, sorted keys, short numeric arrays inline (`[0, 1.2, -10]`), LF, and floats in their
  shortest `float` spelling (`std::to_chars`), so `0.1f` stays `0.1`. Reading goes through
  `SaveData`. *Alternative: YAML through yaml-cpp. A new vendor dependency, and slower.*
- **D2 Packed form: CBOR of the same tree** (nlohmann), starting with the magic `DSCNCBOR` and a
  `u32` version. The reader sniffs the first bytes, so one `Load` call reads loose and packed files.
  `AssetManager::Package` converts scenes when `PackageParams::CompileScenes` (appended, default
  true) is set, and fails the pack on a file that doesn't parse. *Alternative: a binary schema from
  reflection. Hard to version, and the packer would need the game's types.*
- **D3 Extensions `.dscene` and `.dprefab`.**
- **D4 Asset references are strings, never handles**:
  - a logical path (`"textures/a.png"`) for textures, fonts, models and clips;
  - `"<model>#mesh:N"` and `"#material:N"` for a model's parts;
  - `"builtin:box"`, `"builtin:sphere"`, `"builtin:white"`;
  - `"named:<n>"` for objects the game builds in code and registers in a `SceneAssetTable`;
  - buses by name.

  Saving uses new `AssetManager::FindByObject` overloads. A pointer it can't resolve is written as
  `null`, warned about with entity, component and field, and counted in the result. *Alternative:
  persist handles in a registry file. They change every run and packages don't carry them.*
- **D5 Stable files.** UUIDs are 16-digit hex strings. Entities are written in creation order, and
  the loader replays that order, so save→load→save is byte-identical and body and script order is the
  same on every load. Siblings keep their order.
- **D6 Component keys** are the C++ name without `Dingo::` (`"Transform3DComponent"`); a game's own
  name needs a dot (`"EchoVault.Orb"`). Every field is written. A missing field reads as `T{}`.
  Enums are written by name. An unknown field warns once. **An unknown component is kept** and written
  back, so a scene opened without the game's registrations loses nothing.
- **D7 Reflection API** in a new `include/DingoEngine/Scene/Reflection.h` (sketch below):
  - Fields are registered by member pointer, with the kind deduced from the type.
  - Defaults come from `T{}`.
  - Built-ins register from one explicit call, with no static initializers, because a static library
    drops translation units nothing references.
  - A private X-macro list (`src/DingoEngine/Scene/BuiltinComponents.h`) feeds
    `DE_INSTANTIATE_COMPONENT`, the `DuplicateSubtree` copy and a check that every built-in is
    reflected. That ends "forgot to add it to DuplicateSubtree".

  *Alternative: a hand-written serialize function per component. An editor inspector needs the
  metadata anyway.*
- **D8 Game components use the same `AddComponent<T>`.** `Entity.h` gains overloads constrained on
  `!IsBuiltinComponent<T>`, defined inline. A constrained template is more specialized, so built-ins
  still reach the explicit instantiations and nothing existing changes. Storage is a type-erased
  EnTT pool per registered type, and EnTT stays out of public headers. *Alternative: separate names
  (`AddGameComponent<T>`). Games would then use two spellings.*
- **D9 Scripts are named in a `ScriptRegistry`**: `Register<T>("EchoVault.Orb", factory)`. The
  optional factory captures the game's context in place of constructor arguments, and a script's own
  fields are reflected the same way as a component's. On load, scripts attach **last**, after every
  entity, component, link and active flag exists, so `OnCreate` sees the whole scene.
- **D10 Several scripts per entity, with the one-script API unchanged**:
  - `AddScript<T>` still replaces all of the entity's scripts.
  - New `AppendScript<T>` adds one beside them.
  - `GetScript<T>`/`HasScript<T>` find the first `T`.
  - `RemoveScript()` removes all; new `RemoveScript<T>()` removes the first `T`.
  - New `GetScripts()`.

  Scripts run in entity order, then in attach order, so a single-script entity runs exactly as
  before. *Alternative: `AddScript` replaces only the first slot. Confusing next to `AppendScript`.*
- **D11 Prefabs on `DuplicateSubtree`.**
  - `Prefab::Load(path)` holds a private, never-started `Scene`. Its scripts are recipes, not live
    objects, so no `OnCreate` runs in a template.
  - `Scene::InstantiatePrefab(const Prefab&, Entity parent = {})` uses `DuplicateSubtree`, extended to
    copy across scenes.
  - Instance UUIDs are deterministic (instance id mixed with the prefab-local id).
  - Entity references remap through reflection. This replaces `Scene.cpp:131-152` with the same
    results.

  *Alternative: decode the file for each instance. That reloads assets every time.*
- **D12 Overrides are sparse.** An instance is written as its prefab path plus only the fields that
  differ, added or removed components, and removed entities. Applying an override is the ordinary
  decoder on a partial object, the same code that reads old files. A prefab edit reaches a scene on
  its next load.
- **D13 Versioning.** Each file has `"Format"`, `"Version": 1` and `"Engine"` (for information).
  Version 1 freezes at the 1.3.0 release. A newer file fails with an error that names the version. An
  older one is upgraded step by step on the tree before decoding. Game components get
  `TypeBuilder::Version`/`Upgrade`. `docs/versioning.md` gets a "Scene files" rule.
- **D14 API**: `SceneSerializer::Save`/`Load` and the in-memory variants, which return
  `SceneFileResult{Success, Error, Warnings, UnresolvedReferences}`. The params are aggregates
  (`Format`, `Assets`, `Additive`). A replacing load needs a scene that isn't running. An additive
  load works at runtime and builds bodies. Scene settings are saved; runtime state isn't (tick,
  velocities, animator time, playing sounds). A scene file is authored content, not a save game.
  New `SceneManager::LoadScene(name, path)`. Main thread only.
- **D15 Showcase: EchoVault.**
  - Its course is built by hand (`BuildCourse`, `GameScripts.cpp:263-310`). Orbs, sentries with eye
    children and moving platforms make natural prefabs.
  - It covers hierarchy, a character controller, kinematic bodies, lights, audio and scripts with
    parameters.
  - It's about 900 lines, has no `--check` yet, and its meshes are built-in primitives.

  *Alternatives: Candlewick (4.3k lines, every change shows on screen), DungeonCrawler3D (procedural
  levels), Hearthvale and Marionette (too big). The roadmap named Hearthvale's valley as one option.*

## Phases (one session each; Linux Debug, llvmpipe under Xvfb)

### P1 — Reflection core and the built-ins
New `Scene/Reflection.h`, `src/DingoEngine/Scene/Reflection.cpp`, `BuiltinComponents.h`, and an
internal encoder/decoder between a reflected object and `SaveData`. Wire the X-list into
`Entity.cpp:455-497` and `Scene.cpp:180-209`. Name tables for every enum the components use.
**Risk**: float round trips; a test checks 10M random floats plus the special values (NaN and Inf
are written as null).
**Verify**: doctest. Every built-in is reflected, each default equals `T{}`, and random values
survive a round trip. Doxygen has no warnings. **GPU**: none.

### P2 — Saving and loading a scene as text (built-ins only)
New `Scene/SceneSerializer.h`, `SceneAssetTable.h`, the JSON writer, kept unknown components, and
`AssetManager::FindByObject`. Load passes: entities, then components, then links and sockets, then
active flags, then checking entity references, then bodies if the scene is running. Commit the
golden `test/assets/scenes/v1/basic.dscene`. Docs: new `docs/scene-files.md`; Limits in
`docs/scenes-and-ecs.md`; `.claude/reference/engine-patterns.md`.
**Verify**: a doctest round trip, field by field, with a byte-identical second save (if a `Scene`
can't be built headless, this moves into the test app). A new `--test=scenefile` loads textures, a
model, a font and audio through the VFS, starts physics and renders a frame with no `VUID-`.
**GPU**: `--test=scenefile` on Vulkan, DX11 and DX12.

### P3 — Game components
The `IsBuiltinComponent` trait, the constrained templates in `Entity.h:43-56`, the erased pools,
`Scene::ForEachComponent<T>`, `DuplicateSubtree` copying them, and `DuplicateEntity`'s remap through
reflection.
**Risk**: MSVC overload resolution on the constrained templates, which `lint.yml` only
syntax-checks; a compile test uses both kinds.
**Verify**: doctest add/get/remove/duplicate/save/load; every project builds. **GPU**: a Windows
MSBuild of all projects.

### P4 — Script registry and several scripts per entity
Vector slots in `ScriptSystem`, the `Entity.h` additions, `ScriptRegistry`, scripts in the
serializer (attached last), and `ForEachScript`/`GetScriptsOfType` visiting appended scripts.
**Risk**: re-entrancy, such as removing a script from a sibling's `OnDestroy`; keep the snapshot
rule.
**Verify**: the hierarchy and fixed-tick cases still pass. `--test=scenefile` gains an order check:
two scripts' `OnStart`/`OnUpdate`, removal mid-update, and an unchanged single-script order. Reflected
script fields survive a round trip. **GPU**: none; a play-through of SpaceInvaders and
DungeonCrawler3D by hand.

### P5 — Prefabs and overrides
`Scene/Prefab.h`, `DuplicateSubtree` across two scenes (`Scene.cpp:159`, `Scene.h:465`), the prefab
link, override diff and apply, and `Scene::InstantiatePrefab`.
**Verify** (test app): two instances get deterministic UUIDs; references inside an instance remap;
overrides and removed entities round-trip; a runtime instance gets bodies; a script's `OnCreate`
sees the instance's children. **GPU**: none beyond P2.

### P6 — Packed form, packing and versioning
CBOR, the format sniff, `PackageParams::CompileScenes` (`AssetPackage.h:43`,
`AssetPackaging.cpp:258-267`), the upgrade chain and per-type versions, and the newer-version error.
Freeze the `v1/` fixtures. Docs: `docs/versioning.md`, `docs/distribution.md`.
**Verify**: text and CBOR decode to equal trees; the v1 fixtures load; a version 2 file is rejected;
`--test=pack` with a scene inside. **GPU**: none.

### P7 — Showcase: EchoVault
Move `BuildCourse` into `assets/scenes/course.dscene`, with `orb`, `sentry` and `moving-platform`
prefabs. Register the scripts with factories that capture `GameContext`, and load audio through
AssetManager. Keep the code builder behind `--export-scene`, which writes the files. `--check`
builds the course in code, saves it, loads it into a fresh scene, compares entity by entity,
re-saves byte-identically, steps 120 frames, then checks the player is still on the course and
every orb is there. Add it to the smoke list, and run it packed too.
**GPU**: the course looks like it does in 1.2 on all three backends (lights, audio positions,
controller feel).

### P8 — Review and release prep
An `engine-reviewer` pass and its fixes; `.claude/reviews/2026-11-xx-v1.3-review.md`. Update
`.claude/rules/engine-invariants.md` (a new built-in goes in the X-list and gets reflected fields)
and `.claude/reference/scenes-ecs-physics.md`. Then the `release` skill for 1.3.0.

## Needs testing on a real GPU
- `--test=scenefile` and EchoVault render the same on Vulkan, DX11 and DX12, loose and packed.
  Synchronous loads on a cold shader cache make a long first frame; check the player doesn't fall
  through the start platform.
- `Static` meshes loaded from a file bake once.
- Lights and fog are picked in entity order; check the loaded course looks like the code-built one.
- MSVC: the constrained `AddComponent` overloads, and identical `std::to_chars(float)` output
  (the byte-identical re-save must hold on Windows too).

## Left out
- Not in 1.3:
  - an editor inspector (the metadata is ready for one);
  - async and streamed loading;
  - scenes and prefabs as AssetManager types with hot-reload;
  - nested prefabs, and prefab edits reaching a running scene;
  - `.material` and `.particle` files (`named:` covers them for now);
  - save-game state (velocities, animator time);
  - aliases for renamed fields and components.
- 2.0: renames, the engine layers, and `DuplicateEntity` cloning scripts.

## Reflection sketch (`include/DingoEngine/Scene/Reflection.h`)

```cpp
enum class FieldKind : uint8_t { Bool, Int, UInt, Float, Vec2, Vec3, Vec4, Quat, String, Enum, Entity, Asset, Struct, Optional, Array, Count };
enum class AssetKind : uint8_t { Texture, Font, Model, Mesh, Material, ParticleEffect, AudioClip, AudioBus, Count };
enum class FieldFlags : uint8_t { None = 0, Color = 1, Degrees = 2, Hidden = 4, ReadOnly = 8 };
struct FieldOptions { double Min = 0.0, Max = 0.0; FieldFlags Flags = FieldFlags::None; std::string_view Tooltip; AssetKind Asset = AssetKind::Count; };
struct FieldInfo { std::string_view Name; FieldKind Kind; FieldOptions Options; const class TypeInfo* Element = nullptr; const struct EnumInfo* Enum = nullptr; void* (*Access)(void* object) = nullptr; };
class TypeInfo { public: std::string_view GetName() const; std::span<const FieldInfo> GetFields() const; const void* GetDefault() const; uint32_t GetVersion() const; };
template<typename T> class TypeBuilder { public:
	template<auto Member> TypeBuilder& Field(std::string_view name, const FieldOptions& options = {});
	TypeBuilder& Version(uint32_t version);
	TypeBuilder& Upgrade(uint32_t fromVersion, std::function<void(SaveData&)> upgrade); };
template<typename E> void RegisterEnum(std::string_view name, std::initializer_list<std::pair<std::string_view, E>> values);
template<typename T> TypeBuilder<T> RegisterStruct(std::string_view name);
class ComponentRegistry { public:
	template<typename T> static TypeBuilder<T> Register(std::string_view name);
	template<typename T> static const TypeInfo* Find();
	static const TypeInfo* Find(std::string_view name);
	static std::vector<const TypeInfo*> GetAll(); };
class ScriptRegistry { public:
	template<typename T> static TypeBuilder<T> Register(std::string_view name, std::function<T*()> factory = {});
	static const TypeInfo* Find(std::string_view name); };
```
