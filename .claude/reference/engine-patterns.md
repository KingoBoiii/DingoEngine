# Engine patterns

Read on demand from CLAUDE.md. Core application, input, assets, audio and API patterns, plus failure contracts, the vendor list and the full text of the header and text conventions. Keep it in step when a public API changes.

## Key patterns

- **Entry point**: implement `CreateApplication()` returning a heap-allocated `Application*`; `EntryPoint.h` owns `main()`.
- **Layers**: override `OnAttach/OnDetach/OnUpdate(dt)/OnUIRender` (UI only if ImGui enabled).
- **Teardown**: `Application::OnDestroy()` runs once when `Run()`'s loop exits, with everything still live (v0.6.2 — before that it was called from `~Application()` → `Destroy()`, where virtual dispatch had already stripped the derived class, so overrides never ran; never move it back into `Destroy()`). GPU-resource teardown still belongs in `Layer::OnDetach`, which the engine deliberately runs while the renderer is still answerable: `Renderer::Shutdown()` parks the render thread → layers detach → `Renderer::Destroy()`. So `OnDetach` may still ask for the white texture, a sampler or the swap-chain framebuffer. Managed assets are freed after the layers that borrow them, and audio after that (an `AudioClip` must not outlive the engine that decoded it). The window goes last, after the swap chain and graphics context: `glfwTerminate` closes the X connection Mesa's X11 swap chain still uses while it is destroyed (#169: X errors, crashes and hangs on close).
- **Debug window**: one tabbed ImGui window, on unless `ApplicationParams.EnableDebugOverlays = false` (it forces the ImGui backend up even in a UI-less Distribution build). **F3** = Engine, **F4** = Renderer (v0.7: incl. the light budget; v0.8: skinning stats), **F5** = Input, **F6** = Assets, **F7** = Animation (v0.8), **F8** = Profiler (v0.9: GPU pass timers and the CPU frame split), **F9** = Scene (live scenes, the entity tree and a read-only component inspector; `Internal::SceneDebug` builds the plain-data snapshot, and owns the live-scene list the F7 tab reads too).
- **In the background** (v0.7.2, former known bug K20): minimized or unfocused. `ApplicationParams::UpdateInBackground` (default false; `Application::SetUpdateInBackground` at runtime) decides. Off, `Application::Run` pauses: no `OnUpdate`, no `AssetManager::Update`, no render, `WaitEvents(0.1)`, the paused time left out of the deltas (the loop also re-bases after the wait that ends a pause), audio still playing, and the first frame runs even unfocused unless minimized (a window that opens unfocused isn't blank). On, it keeps calling `AssetManager::Update` and every layer's `OnUpdate` with the real delta; an unfocused window renders normally, and a minimized one is paced by `Window::WaitEvents` at up to 60 Hz (about 35 on Windows' 15.6 ms timer) and swaps `BeginFrame`/`EndFrame` for `Renderer::SkipFrame()` and skips ImGui. `SkipFrame` waits for the render thread as `BeginFrame` does, so main-thread GPU work can't race it, and runs the GPU garbage collection itself. Until the next `BeginFrame`, `Renderer::IsFrameSkipped()` is true and `Renderer` uploads/clears/draws, `Renderer2D`/`Renderer3D` scenes (latched at `BeginScene`; a skipped 3D `EndScene` only clears its lights) and `SceneRenderer::Render` are no-ops, because every game renders from `OnUpdate`; a skipped `Renderer::Upload` is dropped, not deferred. v0.7.0–v0.7.1 always paused while minimized, which froze networked games. `Input::Update` runs once after each round of `OnUpdate`, before the next poll, so each edge reaches exactly one `OnUpdate`; on resume, the private `Input::Resume` refreshes gamepads and drops the scroll and cursor motion collected while paused. `Window::GetWidth/GetHeight` read 0 meanwhile (`Application::IsMinimized()`; `Renderer2D::GetViewportSize()` keeps the swap-chain size, `Window::GetAspectRatio()` the last aspect with both sides above 0 since v0.8.3, #97). Test: `--test=background` (`--update-in-background=off`); the test app sets the flag.
- **Input** (reworked v0.5.1): frame-coherent snapshot with standard semantics — `Is...Pressed` = edge ("just pressed"), `Is...Down` = held, plus `Released`/`Up` — uniform across keys, mouse buttons, and gamepad buttons (pre-0.5.1 code had `Pressed`/`Down` inverted). Gamepads: `GamepadButton`/`GamepadAxis` codes, `GetGamepadLeftStick/RightStick` (deadzone-filtered), triggers remapped to [0,1], up to 16 pads, `GamepadConnected/DisconnectedEvent`. Mouse adds `GetMouseDelta`/`GetMouseScrollDelta` + `MouseMoved/MouseScrolledEvent`. v0.6.2: `SetCursorMode(Normal/Hidden/Locked)` (raw motion while Locked; `GetMouseDelta` reads zero for 2 frames after a mode change or refocus, because GLFW warps the cursor), `IsAnyKey/MouseButton{Pressed,Down}`, `WindowFocusEvent` + `Window::IsFocused()`. Input reaches the GLFW window through a private `Input::AttachWindow` that `Window` calls. ImGui's GLFW backend would reset a Hidden cursor every frame, so `ImGuiLayer::Begin` sets `NoMouseCursorChange` while the mode isn't Normal. Rumble (v0.8.3, #88): `SetGamepadRumble(low, high, seconds, pad)`/`StopGamepadRumble`/`IsGamepadRumbleSupported`, XInput pads on Windows only (GLFW's gamepads are input only). `Internal::XInput` (`src/DingoEngine/Core/XInput.*`) loads the XInput DLL at run time; `Input` pairs each GLFW joystick id with its XInput user index by replaying GLFW's own assignment (it walks user indices in order, giving each new pad the lowest free id) on every connect and when the window attaches. `Application::Run` calls the private `Input::UpdateRumble` every pass, paused or not, so a rumble ends on time; detaching the window stops them all.
- **VSync** (#87): `Window::SetVSync/IsVSync` at runtime. `Renderer::QueueVSync` stores it beside the pending resize and applies it at the same two points (render thread after `Present`, or a `BeginFrame` without an image); with a resize pending only the flag is stored (`SwapChain::SetVSyncFlag`) and the resize's recreate takes it. `SwapChain::SetVSync`: D3D stores the flag (read every `Present`), Vulkan recreates the chain. Never call it from the main thread while the render thread runs; read the setting from `Window::IsVSync`. ImGui viewport swap chains stay vsynced and pace the frame. F3 has a checkbox.
- **Params/builder**: resources are built from fluent `*Params` structs passed to static `Create()` factories: `Texture::Create(TextureParams().SetWidth(512)...)`.
- **Assets** (v0.6): `Application::Get().GetAssetManager()` — UUID `AssetHandle`s (a default-constructed `UUID`/`AssetHandle` is 0 = `k_InvalidAsset` since v0.6.3; fresh ids come from `UUID::Generate()`), path dedup against a configurable asset root (`ApplicationParams.Assets`), `Load`/`LoadAsync` (textures+audio decode on a worker thread, GPU publish in the main-thread pump; shader/model/font async requests amortize one-per-frame on the main thread), typed `Get*` returning nullptr until the object exists, failure keeps the registration (`State == Failed`). A **texture** hot-reload moves the asset to `State == Reloading`, **not** back to `Loading`, while the new pixels decode on the worker: the object stays alive, `Get*` keeps returning the same live pointer and `IsReady()` stays true, so a game gating draws on `IsReady()` never blinks a sprite out while an artist saves. (A shader hot-reload recompiles synchronously inside the poll and never leaves `Ready`.) `GetPendingCount()` counts `LoadAsync` requests only (reloads are counted separately by `GetReloadingCount()`), so it stays usable as a loading-screen gate. Opt-in hot-reload polls timestamps and reloads textures/shaders (and, since v0.8 P9, models with their `.events` sidecar) IN PLACE: `Texture::Reinitialize` swaps contents inside the same object; `Shader::Reload` recompiles past the name-keyed disk cache, bumps `GetGeneration()`, and pipelines/render passes lazily rebuild at bind time (`NvrhiCommandList::SetPipeline`/`SetRenderPass`). A shader compile error during reload keeps the old program (no assert). `AssetManager::Reload` uses the same in-place path for textures/shaders/models (fonts and audio are recreated, invalidating pointers); `Unload` always frees the object, so it invalidates pointers games cache — that's why the debug panel offers Reload but no Unload. The manager OWNS what it loads — never `Destroy()`/`delete` a managed asset; raw factories remain for unmanaged resources. The F6 tab is built from `UI::AssetSummarySection`/`AssetRegistrySection`. See docs/asset-pipeline.md.
- **Asset packages** (`feat/asset-packing`, plan `.claude/plans/2026-10-11-asset-packing-plan.md`, docs/distribution.md): every engine file read (AssetManager, raw factories, shader `#include`s, assimp through `Internal::AssimpVfsIOSystem`, miniaudio through `MiniAudioVfs`) goes through `Internal::VirtualFileSystem`: ordered mounts, newest wins, UTF-8 root-relative logical keys; the asset root is a directory mount, a package an archive (`VfsArchive`). A path starting with the root folder's name (`"assets/x.png"`) has it stripped (Debug warns once); write paths root-relative. `.dpak` (`src/DingoEngine/Asset/Pack/`): 64-byte header, entry blobs, then the table of contents; stb deflate (stored when it saves < 5%, never for png/jpg/ogg/mp3), CRC32 per entry and for the TOC, ChaCha20 (RFC 8439, in-house `Pack/ChaCha20`) with a nonce per entry from a random per-package salt (TOC and key-check use reserved indices). `AssetManager::Package` (static, no app needed) / `Unpackage(path, key)` → `PackageHandle` (imports every entry, reloads what it overrides) / `GetPackageAssets` / `IsPackageMounted` / `ClosePackage` / `GetAssetSource` (F6's Source column). At start-up the manager mounts `<exe dir>/<exe stem>.dpak` with `AssetManagerParams::PackageKey` (`AutoUnpackage`, default on) and then mounts the loose root only with `AllowLooseFiles`; never leave a `.dpak` in `build/bin/`. Keys: `embedPackKey([file])` in a game's `premake5.lua` (after `copyAssimpRuntime()`) reads `dpak.key` at premake time into `build/generated/<prj>/DingoPackKey.h` (XOR-masked halves; `Dingo::Generated::GetPackageKey()`); re-run premake after changing a key. The examples commit theirs on purpose. Tool `tools/DingoPack` (`genkey/pack/list/verify`), `scripts/pack-assets.sh|.ps1`, `.dpakignore` in a source root. Shader and font-atlas cache names use the logical key, so a cache survives the game moving; caches are not encrypted. Pack Test `--test=pack`; the Linux smoke test also runs Marionette `--check` and Candlewick packed from another cwd.
- **Audio** (v0.5): `Application::Get().GetAudioEngine()` — `LoadClip` once, then `Play` (returns an `AudioSoundId` for Stop/Pause/volume/pitch/loop/position) or `PlayOneShot` (fire-and-forget) per instance. Positional audio via the `glm::vec3` overloads + `SetListenerPosition`. In the ECS: `AudioSourceComponent` / `AudioListenerComponent`. v0.6.2: distance falloff via `SoundAttenuation` (per sound in `SoundPlayParams::Attenuation`, live via `SetAttenuation`, engine-wide via `SetDefaultAttenuation`). Its defaults equal miniaudio's own (`MaxDistance` = float max), so behaviour is unchanged until a game opts in. `AudioAttenuationModel::None` is miniaudio's inverse model with rolloff 0 (v0.8.3, #96): miniaudio's own `none` bypasses the spatializer, and with it the panning and the sound's volume, which miniaudio keeps there. **Buses** (#95): `CreateBus(name, parent)`/`DestroyBus`/`FindBus`, per-bus volume, mute (keeps the volume), pause and `StopBus`; `SoundPlayParams::Bus`, the `PlayOneShot` bus overloads and `AudioSourceComponent::Bus` route a sound (a stale bus plays on master, warned once). `AudioBusId` is a strong enum so the bus overloads can't be ambiguous with the float-volume ones. Each bus is an `ma_sound_group`; `k_MasterBus` is an internal root group in slot 0 (never freed, so no created bus packs to 0) that only mutes and pauses, its level staying `ma_engine_set_volume`. Destroying a group with live children would leave them attached to nothing, silent and never reaped, so `DestroyBus` and `Shutdown` release the sounds first and uninit buses by descending creation serial. **Streams** (#218): `CreateStream(AudioStreamDesc, SoundPlayParams)` / `PushStreamFrames` (int16 or float) / `GetQueuedStreamFrames`; a custom `ma_data_source` (`Internal::MiniAudioStream`, owned by its `SoundSlot` and freed after the `ma_sound`) over an SPSC `ma_pcm_rb` of f32; `ma_sound` resamples from the stream's rate. Its read always returns every frame asked for (miniaudio turns an empty or short read into `MA_AT_END`, which ends the sound): a dry ring holds the last frame and fades out over 5 ms, data fades in, and a silent stream resumes only once a whole read (the device period's frame count at the stream's rate, capped at `BufferFrames`) is queued. Push and queue calls belong to the thread driving the engine: they read the slot table the main thread reallocates and frees. See docs/audio.md; Audio Bus Test (`--test=bus`).
- **Bindables**: `Texture`, `GraphicsBuffer`, `Sampler` implement `IBindableShaderResource` for slot binding in a `RenderPass`.
- **Events**: `EventDispatcher dispatcher(event); dispatcher.Dispatch<WindowResizeEvent>(DE_BIND_EVENT_FN(OnResize));`
- **Backend hiding** (hard requirement): EnTT, Box2D, Jolt, ImGui, miniaudio, NVRHI must never appear in a public header. Public APIs use abstract classes + static `Create()` + opaque handles (see `Physics3D`). GLM in public headers is fine.

## Failure contracts

- `Model::LoadFromFile`, `Font::Create` and (v0.6) `Texture::CreateFromFile` return `nullptr` on failure, so a wrong path fails loudly, not with a broken object. Since v0.6.3 every raw file factory (those three, `Shader::Create`/`CreateFromFile`, `AudioEngine::LoadClip`) resolves a relative path through `Internal::ResolveRawAssetPath` (`src/DingoEngine/Asset/AssetPath.h`): under the asset root if the file exists there, else unchanged, i.e. cwd-relative. The `AssetManager` layers its own contract on top: failed loads stay registered with `State == Failed` and `Get*` returns nullptr.
- Physics per-body calls are no-ops (getters return identity) on invalid/stale handles.

## Third-party vendors

| Vendor | Role |
|---|---|
| glfw / glm / spdlog / stb | Windowing+input, math, logging, image loading |
| nvrhi | Graphics API abstraction (Vulkan / D3D11 / D3D12) |
| imgui | Debug UI (behind `Dingo::UI` facade + `Layer::OnUIRender`) |
| msdf-atlas-gen | Font MSDF atlas generation |
| assimp | Model loading (`Model::LoadFromFile`): static meshes pre-transformed; v0.8 adds skeletons, skin weights and clips |
| entt / box2d / JoltPhysics | ECS / 2D physics / 3D physics backends (all hidden) |
| miniaudio | Audio backend (hidden behind the `Audio` interface; v0.5) |
| tracy | CPU zones and GPU plots, compiled in only with premake `--profile` (v0.9; hidden behind `Core/Profiler.h`) |

## Convention details

The full text behind the short rules in CLAUDE.md.

- **`<Windows.h>` macros**: Debug builds pull `<Windows.h>` in through `Log.h` without `NOMINMAX`. In the engine (`depch.h` includes it before GLM, whose `_fixes.hpp` undefines `min`/`max`) only `near` and `far` survive; in the test app (`Log.h` includes GLM first) `min`, `max`, `near` and `far` all do, and every header after it sees them. So write `(std::min)(a, b)` / `(std::max)(...)` / `(std::numeric_limits<T>::max)()` in test code and public headers, and never name anything `near` or `far`. The examples define `NOMINMAX`.
- `DE_CORE_ASSERT(cond, msg)` takes a **plain string only** — NOT `std::format` args (adjacent-literal pasting; format args fail to compile). `DE_CORE_WARN/ERROR` do take format args.
- In a public header, a member named after its own type spells the type qualified: `Dingo::Mesh* Mesh`, `Dingo::CullMode CullMode = Dingo::CullMode::Back`. MSVC accepts `Mesh* Mesh`, but GCC rejects it (`-Wchanges-meaning`) in every translation unit that includes the header.
- On-screen text is **UTF-8** (v0.6.2): `DrawText`/`GetStringWidth` share the decoder in `src/DingoEngine/Graphics/Utf8.h`, and invalid bytes read as Latin-1. The MSDF atlas bakes Latin-1, printable General Punctuation (U+2010–U+2027, U+2030–U+205E) and U+20AC; anything else draws `?`. Changing the charset must bump `k_FontAtlasCacheFormatVersion` in `Font.cpp`. Only the engine project builds with `/utf-8`, so non-ASCII literals in the test app/examples are hex-escaped.
- **Paths as text are UTF-8**: never call `path.string()`/`generic_string()` in the engine, nor build a `path` from a `std::string`. On Windows both go through the ANSI code page, and the first throws on a name it can't map (a Cyrillic folder under code page 1252 crashed every loose run). Use `Internal::PathToUtf8`/`PathToGenericUtf8`/`PathFromUtf8` (`src/DingoEngine/Core/PathText.h`); games and the test app follow the same rule through the public `FileSystem::PathToUtf8`/`PathToGenericUtf8`/`PathFromUtf8` (#172).
