# Engine patterns

Read on demand from CLAUDE.md. Core application, input, assets, audio and API patterns, plus failure contracts, the vendor list and the full text of the header and text conventions. Keep it in step when a public API changes.

## Key patterns

- **Entry point**: implement `CreateApplication(args)` returning `new MyApp(params)`; `EntryPoint.h` owns `main()` and calls `Internal::Main` (`src/DingoEngine/Core/EntryPoint.cpp`), which calls `Initialize()` (public, idempotent), `Run()` and `delete`, and loops for `RequestRestart` (the constructor applies the pending API). `Destroy()` is private (v1.0 P9, A101).
- **DingoUI** (v1.0, docs/game-ui.md): `Internal::DingoUIContext` is created by `Application::Initialize` unless headless or `ApplicationParams::DingoUI.Enabled` is off; every `DingoUI::` call is then a no-op. `Internal::DingoUILayer` and the `ImGuiLayer` are pushed as overlays at the end of `Initialize` (DingoUI first, so ImGui draws over it). Layout and draw run after all layers' `OnUpdate`. Input it takes goes through `Internal::InputBackend` (`Core/InputBackend.h`): the consume mask makes presses, scroll and navigation keys read as not happening in `Input` until released; engine F-keys and the UI itself read the `...Unconsumed` queries. `DingoUI::IsPointerOverUI/IsCapturingInput` are the game's side. Navigation is opt-in per root (modal, or `SetNavigable(true)`). Test: `--test=dingoui` (`--dingoui=stress`). Checks read the UI through `DingoUI::GetId(label)` (inside a frame, same hash as the widget), `GetFocusedId()` and `GetRect(id|name, UILayoutRect&)` (#266), which look in `m_LastTree`, the last finished frame, and give the rect clipped to its container as `VisibleMin/Max`.
- **Headless** (#244; v1.0 keeps it as the last `GraphicsAPI` enumerator, so `GraphicsAPI{}` is Vulkan): `GraphicsAPI::Headless` skips the window, GLFW, graphics context, swap chain, `Renderer` (no render thread), `Renderer2D/3D`, `SceneRenderer` and ImGui; `Application::RunHeadless` ticks layers at 60 Hz with no `Input` snapshot, and holds an `Internal::HeadlessSignalGuard` (`Core/HeadlessSignals.h`): SIGINT/SIGTERM or the Windows console events (`SetConsoleCtrlHandler`) only set an atomic that the loop turns into `Close()` (so `OnDetach`/`OnDestroy` run), a second signal falls back to the default, an ignored signal stays ignored, and the previous handlers return when the run ends, except after a Windows close/logoff/shutdown event, whose handler stays registered: removing it would wait out its 4.5 s grace sleep, after which the OS ends the process mid-teardown. A restarted run keeps that caught event and stops at once. `Application::IsHeadless()` gates anything that reaches those (`SceneManager::OnRender`), and `GetWindow`/`GetGraphicsContext`/`GetRenderer2D/3D`/`GetSceneRenderer` assert. No GPU resources: the `Texture/Shader/Sampler/Framebuffer/GraphicsBuffer/RenderPass/ComputePass/Font` factories return `nullptr` with one error (`Internal::RequireGraphicsDevice`, `Graphics/GraphicsDevice.h`), an `AssetManager` load of a texture, shader or font leaves the asset `Failed`, and `Model::Load` skips textures (meshes, skeleton and clips load). Any app's `--graphics=headless` starts it headless; the test app then runs `HeadlessCheckLayer` (`test/src/main.cpp`) instead of the test cases; `--headless-wait` keeps it running until a signal.
- **Layers**: override `OnAttach/OnDetach/OnUpdate(dt)/OnImGuiRender` (UI only if ImGui enabled).
- **Logs and crashes** (v1.0 P7): `Internal::InitializeLog` (`Core/LogLifecycle.h`, from `Internal::Main`) logs to the console and keeps what it logs in a 4096-message ring; the `Application` constructor calls `Internal::OpenLogFile(dir)`, which moves the earlier runs' `Dingo.log` up one name (`Dingo.1.log` … `Dingo.4.log`). `Dingo.log` first moves aside as `Dingo-<pid>-previous.log` and the shift stops at the first rename that fails, so nothing is overwritten and a half-done rotation leaves a side log; a `Dingo.log` another instance holds (Windows refuses the rename, Linux sees its `flock`) gives this run `Dingo-<pid>.log`; the newest four side logs are kept, and pruning never deletes one another instance holds (#211: Linux would unlink a live log). The file is the engine's own `FileSink` (a `std::ofstream` on the `std::filesystem::path`, so any Unicode user folder works, opened for appending since the crash handler writes the same file), and the ring is replayed into it and swapped out under the loggers' shared sink's lock (`LogSinks`, a `dist_sink`). `dir` = `--log-dir=<path>` (on Windows read from `CommandLineToArgvW(GetCommandLineW())`, as is `--save-dir=`, so paths outside the ANSI code page survive), else `--log-here` (the cwd), else `ApplicationParams::LogDirectory`, else `Platform::GetUserDataDir(Name)/logs` (`ApplicationParams::Name`, empty = the exe stem; `Application::GetName`; the folder name has `<>:"/\|?*` and control characters replaced by `_`, trailing dots and spaces trimmed and a device name like `CON` prefixed with `_`, on every platform; an existing folder under the unchanged relative name, such as a nested `Studio/Game` or a Linux `Game: X`, wins while the new one doesn't exist). Later calls (a restart) keep the file. Then `Internal::CrashHandler::Install` (`src/DingoEngine/Core/CrashHandler.*`): Linux `sigaction` on SIGSEGV, SIGBUS, SIGFPE, SIGILL, SIGABRT and SIGTRAP (`SA_RESETHAND`, re-raised so the exit status and core dump stay; not under ASan) writes `backtrace_symbols_fd` (frames as `exe(+offset)` for `addr2line`; no `-rdynamic`, which would let shared libraries interpose the executable's symbols) to the log through its own `O_APPEND` fd and to stderr; Windows `SetUnhandledExceptionFilter`, SIGABRT, `_set_purecall_handler` and `_set_invalid_parameter_handler` write `MiniDumpWriteDump` (from a thread made at Install, since an overflowed stack can't) to `Dingo-<date>-<time>-<pid>.dmp` beside the log (five kept) and a line through a `FILE_APPEND_DATA` handle, and a Distribution build shows a message box from a second thread made at Install (`MB_TOPMOST`, given up on if no box appears within 10 s) while the crashed thread waits (its own modal loop would dispatch the game window's events on the faulted state); `std::set_terminate` logs the exception's `what()` first (Windows: the filter chains the CRT's for a C++ exception, 0xE06D7363, so terminate runs with it current, and the dump keeps that exception's record; exit 3). The first crashing thread reports; any other waits for the exit. Every thread the engine starts runs `CrashHandler::PrepareThread()` first: the UCRT's terminate handler is per thread, Windows needs `SetThreadStackGuarantee` to report an overflow, Linux gives each thread its own alternate signal stack. The render thread and asset worker run their bodies through `CrashHandler::RunThread`, which on Windows adds an SEH filter (MSVC's `std::thread` entry is noexcept, so an escaping exception would otherwise reach terminate with none current); Jolt's workers get `PrepareThread` through `SetThreadInitFunction`. spdlog is flushed last in a report, so a second thread that crashed holding its lock can't stop the report. The handlers write from fixed buffers and flush spdlog first only when `Internal::IsLoggingOnThisThread()` (a thread-local count `Log::PrintInternal*` keeps) is false, since its mutex would deadlock. `FatalError(message)` (public, `Core/FatalError.h`, `std::source_location` default argument) waits for a report another thread is writing, then logs through `Internal::TryLogFatal` (a 200 ms try-lock on the sinks, every sink but the console, then the file flushed) and writes the console copy straight to stderr, never stdout's `FILE` lock, shows the box on Windows Distribution and `std::_Exit(1)`s; Distribution's `DE_VERIFY`/`DE_CORE_VERIFY` call it instead of `DE_DEBUG_BREAK`. docs/application-and-layers.md "Logs and crashes".
- **Teardown**: `Application::OnDestroy()` runs once when `Run()`'s loop exits, with everything still live (v0.6.2 — before that it was called from `~Application()` → `Destroy()`, where virtual dispatch had already stripped the derived class, so overrides never ran; never move it back into `Destroy()`). GPU-resource teardown still belongs in `Layer::OnDetach`, which the engine deliberately runs while the renderer is still answerable: `Renderer::Shutdown()` parks the render thread → layers detach → `Renderer::Destroy()`. So `OnDetach` may still ask for the white texture, a sampler or the swap-chain framebuffer. Managed assets are freed after the layers that borrow them, and audio after that (an `AudioClip` must not outlive the engine that decoded it). The window goes last, after the swap chain and graphics context: `glfwTerminate` closes the X connection Mesa's X11 swap chain still uses while it is destroyed (#169: X errors, crashes and hangs on close).
- **Debug window**: one tabbed ImGui window, on unless `ApplicationParams.EnableDebugOverlays = false` (it forces the ImGui backend up even in a UI-less Distribution build). **F3** = Engine, **F4** = Renderer (v0.7: incl. the light budget; v0.8: skinning stats), **F5** = Input, **F6** = Assets, **F7** = Animation (v0.8), **F8** = Profiler (v0.9: GPU pass timers and the CPU frame split), **F9** = Scene (live scenes, the entity tree and a read-only component inspector; `Internal::SceneDebug` builds the plain-data snapshot, and owns the live-scene list the F7 tab reads too).
- **In the background** (v0.7.2, former known bug K20): minimized or unfocused. `ApplicationParams::UpdateInBackground` (default false; `Application::SetUpdateInBackground` at runtime) decides. Off, `Application::Run` pauses: no `OnUpdate`, no `AssetManager::Update`, no render, `WaitEvents(0.1)`, the paused time left out of the deltas (the loop also re-bases after the wait that ends a pause), audio still playing, and the first frame runs even unfocused unless minimized (a window that opens unfocused isn't blank). On, it keeps calling `AssetManager::Update` and every layer's `OnUpdate` with the real delta; an unfocused window renders normally, and a minimized one is paced by `Window::WaitEvents` at up to 60 Hz (about 35 on Windows' 15.6 ms timer) and swaps `BeginFrame`/`EndFrame` for `Renderer::SkipFrame()` and skips ImGui. `SkipFrame` waits for the render thread as `BeginFrame` does, so main-thread GPU work can't race it, and runs the GPU garbage collection itself. Until the next `BeginFrame`, `Renderer::IsFrameSkipped()` is true and `Renderer` uploads/clears/draws, `Renderer2D`/`Renderer3D` scenes (latched at `BeginScene`; a skipped 3D `EndScene` only clears its lights) and `SceneRenderer::Render` are no-ops, because every game renders from `OnUpdate`; a skipped `Renderer::Upload` is dropped, not deferred. v0.7.0–v0.7.1 always paused while minimized, which froze networked games. `Input::Update` runs once after each round of `OnUpdate`, before the next poll, so each edge reaches exactly one `OnUpdate`; on resume, the private `Input::Resume` refreshes gamepads and drops the scroll and cursor motion collected while paused. `Window::GetWidth/GetHeight` read 0 meanwhile (`Application::IsMinimized()`; `Renderer2D::GetViewportSize()` keeps the swap-chain size, `Window::GetAspectRatio()` the last aspect with both sides above 0 since v0.8.3, #97). Test: `--test=background` (`--update-in-background=off`); the test app sets the flag.
- **Input** (reworked v0.5.1): frame-coherent snapshot with standard semantics — `Is...Pressed` = edge ("just pressed"), `Is...Down` = held, plus `Released`/`Up` — uniform across keys, mouse buttons, and gamepad buttons (pre-0.5.1 code had `Pressed`/`Down` inverted). Gamepads: `GamepadButton`/`GamepadAxis` codes, `GetGamepadLeftStick/RightStick` (deadzone-filtered), triggers remapped to [0,1], up to 16 pads, `GamepadConnected/DisconnectedEvent`. Mouse adds `GetMouseDelta`/`GetMouseScrollDelta` + `MouseMoved/MouseScrolledEvent`. v0.6.2: `SetCursorMode(Normal/Hidden/Locked)` (raw motion while Locked; `GetMouseDelta` reads zero for 2 frames after a mode change or refocus, because GLFW warps the cursor), `IsAnyKey/MouseButton{Pressed,Down}`, `WindowFocusEvent` + `Window::IsFocused()`. Input reaches the GLFW window through a private `Input::AttachWindow` that `Window` calls. Consume mask (v1.0, DingoUI U0): `Internal::InputBackend` (`src/DingoEngine/Core/InputBackend.h`, a friend of `Input`) consumes keys, mouse buttons, gamepad buttons and scroll; a consumed button reads up to every query (`IsAny*` too) until released, the release frame included (`Input::Update` drops a bit once the previous state is up), and scroll reads zero for the frame. `ConsumeNewPresses(mouse, keyboard)` takes only this frame's new presses. Engine hotkeys use `IsKeyPressedUnconsumed`; the DingoUI context's destructor and `Application::Destroy` clear the mask (Input statics survive `RequestRestart`). ImGui wins: `Application::BeginDingoUIFrame` (after `AssetManager::Update`, before the `OnUpdate`s) consumes new presses while `ImGuiLayer::WantsMouse/WantsKeyboard` (one frame late) and `ImGuiParams::BlockGameInput`, and `ImGuiLayer::OnEvent` marks presses/scroll `Handled`; `io.ConfigNavCaptureKeyboard = false`, so a merely focused ImGui window doesn't take the keyboard. Layer order top-down: ImGuiLayer, `Internal::DingoUILayer` (Handled on last frame's blocking rects), then game overlays pushed in the constructor or `OnInitialize` (both engine layers are pushed at the end of `Application::Initialize`, so an overlay pushed later sits above them in event order; polled input is protected either way). ImGui's GLFW backend would reset a Hidden cursor every frame, so `ImGuiLayer::Begin` sets `NoMouseCursorChange` while the mode isn't Normal. Rumble (v0.8.3, #88): `SetGamepadRumble(low, high, seconds, pad)`/`StopGamepadRumble`/`IsGamepadRumbleSupported`, XInput pads on Windows only (GLFW's gamepads are input only). `Internal::XInput` (`src/DingoEngine/Core/XInput.*`) loads the XInput DLL at run time; `Input` pairs each GLFW joystick id with its XInput user index by replaying GLFW's own assignment (it walks user indices in order, giving each new pad the lowest free id) on every connect and when the window attaches. `Application::Run` calls the private `Input::UpdateRumble` every pass, paused or not, so a rumble ends on time; detaching the window stops them all. Games and checks drive a pad through the public `Input::SetGamepadSimulated(slot, on)` plus `SetSimulatedGamepadButton/Axis` (#265): they write a pending state that `PollGamepads` copies in at the next snapshot, so edges show a frame later like a real pad, a real pad in that slot sends no events or rumble, and it needs a window (headless takes no snapshot); the test app's private `InputBackend` hooks still apply immediately.
- **Saves and settings** (v1.0 P8, docs/saves-and-settings.md): `SaveData` (`Core/SaveData.h`) is a typed tree (null, bool, `int64_t`, `double`, string, array, object with sorted keys; glm vectors and quaternions as number arrays; enums as integers) with `As*`/`Get(key, fallback)` reads that never throw, `ToJson`/`FromJson` (nlohmann/json in the .cpp only; non-finite floats written as null, nesting capped at 256). `WriteFile` writes `<path>.tmp` with `fsync`/`FlushFileBuffers`, renames the current file to `<path>.bak`, renames the tmp over it (`MoveFileExW` with `REPLACE_EXISTING | WRITE_THROUGH`, retried for scanners) and `fsync`s the directory on Linux, one write at a time (they share the tmp); `ReadFile` falls back to a complete `.tmp` when the main file is missing (killed between the renames), then the `.bak`; the next `WriteFile` first moves such a `.tmp` into place, so the `.bak` keeps it, and `SaveSlots::Exists`/`List` count it (#189). Numbers outside `float`/`int` read as the fallback (#192); slot names reject Windows device names (`CON`, `COM1`…) on every platform (#194). Non-const `operator[]`/`Push`/`At` never corrupt the tree (a wrong type becomes the right one, logged); `nullptr` is Null and other pointers are deleted constructors. `SaveSlots` keeps `<slot>.json` in `Application::GetSaveDirectory()` (`ApplicationParams::SaveDirectory`, `--save-dir=`, default `GetUserDataDir(Name)/saves`). `Settings` (`Core/Settings.h`: `Display`, `Audio`, `Input`, `Game`) is `Capture`/`Apply` (only what differs)/`Save`/`Load` (the slot over `Capture()`), and `ApplicationParams::SettingsSlot` opens the window in the slot's display settings and sets its master volume and deadzone at start (bus volumes wait for the game's `Apply`). No scene serialization.
- **Window modes** (v1.0 P8): `WindowMode { Windowed, BorderlessFullscreen, ExclusiveFullscreen }` and `DisplayMode` (`Windowing/DisplayMode.h`, with the pure `SortDisplayModes`/`ChooseDisplayMode`). `Window::SetWindowMode(mode, fullscreenMode)` on the monitor the window is on (glfwGetWindowMonitor, else most overlap): borderless = a GLFW fullscreen window at the desktop mode, exclusive = the nearest listed mode (cached desktop mode kept while it runs); `GetDisplayModes`, `GetDesktopDisplayMode`, `GetFullscreenDisplayMode`, `SetSize` (kept while fullscreen), `GetWindowedWidth/Height` (`WindowData::WindowedWidth/Height`, the size callback's last windowed size, set to the restore size as soon as `SetWindowMode` leaves fullscreen, #193). `SetFullscreen(bool)` is borderless/windowed. `WindowParams::Mode`/`FullscreenMode` replaced `Fullscreen`. Display Mode Test (`--test=display`, `--display-exclusive=next|<W>x<H>[@<Hz>]`).
- **VSync** (#87): `Window::SetVSync/IsVSync` at runtime. `Renderer::QueueVSync` stores it beside the pending resize and applies it at the same two points (render thread after `Present`, or a `BeginFrame` without an image); with a resize pending only the flag is stored (`SwapChain::SetVSyncFlag`) and the resize's recreate takes it. `SwapChain::SetVSync`: D3D stores the flag (read every `Present`), Vulkan recreates the chain. Never call it from the main thread while the render thread runs; read the setting from `Window::IsVSync`. ImGui viewport swap chains stay vsynced and pace the frame. F3 has a checkbox. `--no-vsync` sets the private `Window::m_VSyncForcedOff`: the swap chain starts and stays off, while `IsVSync` keeps the request so `Settings::Capture` never saves the flag's effect.
- **Standard launch flags** (#237): the `Application` constructor reads `--graphics=` (before `RequestRestart`'s back-end, which wins) and, after the `SettingsSlot`, `--window=WxH` (windowed, 640x360 to 16384x16384). While `--window` holds the window, `Window::m_DisplayRequest` keeps the game's mode and size: `Settings::Apply` writes it instead of the window and `Settings::Capture` reads it, so saved settings never take the flag's size (same idea as `m_VSyncForcedOff`). Parsing lives in `Core/LaunchFlags.h` (unit-tested). Apps don't parse these themselves.
- **Params/builder**: resources are built from fluent `*Params` structs passed to static `Create()` factories: `Texture::Create(TextureParams().SetWidth(512)...)`.
- **Lifetime** (v1.0 P9, A201, docs/conventions.md): a factory returns a ready object or `nullptr` (`[[nodiscard]]`), and `delete` frees everything: backend destructors drop their GPU handles (`~NvrhiFramebuffer` runs `Destroy`, which frees its attachment `Texture`s), `~Renderer2D/3D` call the idempotent `Shutdown`, `Initialize` is protected (private on the renderers and `Font`), and `DestroyAndDelete` is delete-and-null. Engine-only surface is private or `Internal`: `Renderer`'s frame control (Begin/EndFrame, SkipFrame, Queue*, the command list) through `Internal::RendererBackend` (`Graphics/RendererBackend.h`), `Material`'s renderer plumbing (scene/skin/shadow/object/instance buffers, uniform upload, `GetOrCreateRenderPass`) through `Internal::MaterialAccess` (`Graphics/MaterialAccess.h`), `Internal::SwapChain` and `Internal::CommandList` under `src/`, `ShaderType` under `src/`; `GraphicsParams` lost `NativeWindowHandle` and the never-read `FramesInFlight`. Enums replaced bools and the index-only `GraphicsFormat`: `SamplerFilter`, `IndexFormat` (`CreateIndexBuffer(size, format, ...)`, Uint32 by default in params) and `BufferUpload { Direct, Deferred }`. Deprecated: `Renderer3D::SetDirectionalLight`, the `SkinData` skinning block (warned once at run time; `k_MaxSkinDataBinding` → `k_MaxSkinUniformBinding`).
- **Assets** (v0.6): `Application::Get().GetAssetManager()` — UUID `AssetHandle`s (a default-constructed `UUID`/`AssetHandle` is 0 = `k_InvalidAsset` since v0.6.3; fresh ids come from `UUID::Generate()`), path dedup against a configurable asset root (`ApplicationParams.Assets`), `Load`/`LoadAsync` (textures+audio decode on a worker thread, GPU publish in the main-thread pump; shader/model/font async requests amortize one-per-frame on the main thread), typed `Get*` returning nullptr until the object exists, failure keeps the registration (`State == Failed`). A **texture** hot-reload moves the asset to `State == Reloading`, **not** back to `Loading`, while the new pixels decode on the worker: the object stays alive, `Get*` keeps returning the same live pointer and `IsReady()` stays true, so a game gating draws on `IsReady()` never blinks a sprite out while an artist saves. (A shader hot-reload recompiles synchronously inside the poll and never leaves `Ready`.) `GetPendingCount()` counts `LoadAsync` requests only (reloads are counted separately by `GetReloadingCount()`), so it stays usable as a loading-screen gate. Opt-in hot-reload polls timestamps and reloads textures/shaders (and, since v0.8 P9, models with their `.events` sidecar) IN PLACE: `Texture::Reinitialize` swaps contents inside the same object; `Shader::Reload` recompiles past the name-keyed disk cache, bumps `GetGeneration()`, and pipelines/render passes lazily rebuild at bind time (`NvrhiCommandList::SetPipeline`/`SetRenderPass`). A shader compile error during reload keeps the old program (no assert). `AssetManager::Reload` uses the same in-place path for textures/shaders/models (fonts and audio are recreated, invalidating pointers); `Unload` always frees the object, so it invalidates pointers games cache — that's why the debug panel offers Reload but no Unload. The manager OWNS what it loads — never `Destroy()`/`delete` a managed asset; raw factories remain for unmanaged resources. The F6 tab is built from `Internal::AssetSummarySection`/`AssetRegistrySection` (`src/DingoEngine/UI/DebugPanels.h`; every debug section and window is engine-internal since v1.0 P9, A113). See docs/asset-pipeline.md.
- **Asset packages** (`feat/asset-packing`, plan `.claude/plans/2026-10-11-asset-packing-plan.md`, docs/distribution.md): every engine file read (AssetManager, raw factories, shader `#include`s, assimp through `Internal::AssimpVfsIOSystem`, miniaudio through `MiniAudioVfs`) goes through `Internal::VirtualFileSystem`: ordered mounts, newest wins, UTF-8 root-relative logical keys; the asset root is a directory mount, a package an archive (`VfsArchive`). A path starting with the root folder's name (`"assets/x.png"`) has it stripped (Debug warns once); write paths root-relative. `.dpak` (`src/DingoEngine/Asset/Pack/`): 64-byte header, entry blobs, then the table of contents; stb deflate (stored when it saves < 5%, never for png/jpg/ogg/mp3), CRC32 per entry and for the TOC, ChaCha20 (RFC 8439, in-house `Pack/ChaCha20`) with a nonce per entry from a random per-package salt (TOC and key-check use reserved indices). `AssetManager::Package` (static, no app needed) / `Unpackage(path, key)` → `PackageHandle` (imports every entry, reloads what it overrides) / `GetPackageAssets` / `IsPackageMounted` / `ClosePackage` / `GetAssetSource` (F6's Source column). At start-up the manager mounts `<exe dir>/<exe stem>.dpak` with `AssetManagerParams::PackageKey` (`AutoUnpackage`, default on) and then mounts the loose root only with `AllowLooseFiles`; never leave a `.dpak` in `build/bin/`. Keys: `embedPackKey([file])` in a game's `premake5.lua` (after `copyAssimpRuntime()`) reads `dpak.key` at premake time into `build/generated/<prj>/DingoPackKey.h` (XOR-masked halves; `Dingo::Generated::GetPackageKey()`); re-run premake after changing a key. The examples commit theirs on purpose. Tool `tools/DingoPack` (`genkey/pack/list/verify`), `scripts/pack-assets.sh|.ps1`, `.dpakignore` in a source root. Shader and font-atlas cache names use the logical key, so a cache survives the game moving; caches are not encrypted. Pack Test `--test=pack`; the Linux smoke test also runs Marionette `--check` and Candlewick packed from another cwd.
- **Audio** (v0.5): `Application::Get().GetAudioEngine()` — `LoadClip` once, then `Play` (returns an `AudioSoundId` for Stop/Pause/volume/pitch/loop/position) or `PlayOneShot` (fire-and-forget) per instance. Positional audio via the `glm::vec3` overloads + `SetListenerPosition`. In the ECS: `AudioSourceComponent` / `AudioListenerComponent`. v0.6.2: distance falloff via `SoundAttenuation` (per sound in `SoundPlayParams::Attenuation`, live via `SetAttenuation`, engine-wide via `SetDefaultAttenuation`). Its defaults equal miniaudio's own (`MaxDistance` = float max), so behaviour is unchanged until a game opts in. `AudioAttenuationModel::None` is miniaudio's inverse model with rolloff 0 (v0.8.3, #96): miniaudio's own `none` bypasses the spatializer, and with it the panning and the sound's volume, which miniaudio keeps there. **Buses** (#95): `CreateBus(name, parent)`/`DestroyBus`/`FindBus`, per-bus volume, mute (keeps the volume), pause and `StopBus`; `SoundPlayParams::Bus`, the `PlayOneShot` bus overloads and `AudioSourceComponent::Bus` route a sound (a stale bus plays on master, warned once). `AudioBusId` is a strong enum so the bus overloads can't be ambiguous with the float-volume ones. Each bus is an `ma_sound_group`; `k_MasterBus` is an internal root group in slot 0 (never freed, so no created bus packs to 0) that only mutes and pauses, its level staying `ma_engine_set_volume`. Destroying a group with live children would leave them attached to nothing, silent and never reaped, so `DestroyBus` and `Shutdown` release the sounds first and uninit buses by descending creation serial. **Streams** (#218): `CreateStream(AudioStreamDesc, SoundPlayParams)` / `PushStreamFrames` (int16 or float) / `GetQueuedStreamFrames`; a custom `ma_data_source` (`Internal::MiniAudioStream`, owned by its `SoundSlot` and freed after the `ma_sound`) over an SPSC `ma_pcm_rb` of f32; `ma_sound` resamples from the stream's rate. Its read always returns every frame asked for (miniaudio turns an empty or short read into `MA_AT_END`, which ends the sound): a dry ring holds the last frame and fades out over 5 ms, data fades in, and a silent stream resumes only once a whole read (the device period's frame count at the stream's rate, capped at `BufferFrames`) is queued. Push and queue calls belong to the thread driving the engine: they read the slot table the main thread reallocates and frees. See docs/audio.md; Audio Bus Test (`--test=bus`). **Capture** (#300, v1.1): `StartCapture`/`ReadCaptured` on `AudioEngine`; `Internal::MiniAudioCapture` opens a capture `ma_device` on the engine's own context (f32, miniaudio resamples) feeding an SPSC f32 `ma_pcm_rb` (the device thread writes, the main thread reads); gain and the noise gate run in `ProcessCapture` on the device thread, settings through atomics. `Update` calls `PollCaptureDevice`, which polls `ma_device_is_started` (not miniaudio's stopped notification: WASAPI skips it when an unplugged device's stop fails, and Pulse sends it on a suspend), falls back to the default device once, and returns `Lost` to `Running` if the OS restarts the device. Device ids are the hex of the `ma_device_id` bytes. Test hooks on `MiniAudioEngine` feed frames without a device; Audio Capture Test (`--test=capture`).
- **Bindables**: `Texture`, `GraphicsBuffer`, `Sampler` implement `IBindableShaderResource` for slot binding in a `RenderPass`.
- **Events**: `EventDispatcher dispatcher(event); dispatcher.Dispatch<WindowResizeEvent>(DE_BIND_EVENT_FN(OnResize));`
- **Backend hiding** (hard requirement): EnTT, Box2D, Jolt, ImGui, miniaudio, NVRHI must never appear in a public header. Public APIs use abstract classes + static `Create()` + opaque handles (see `Physics3D`). GLM in public headers is fine.

## Failure contracts

- `Model::LoadFromFile`, `Font::Create` and (v0.6) `Texture::CreateFromFile` return `nullptr` on failure, so a wrong path fails loudly, not with a broken object. Since v0.6.3 every raw file factory (those three, `Shader::Create`/`CreateFromFile`, `AudioEngine::LoadClip`) resolves a relative path through `Internal::ResolveRawAssetPath` (`src/DingoEngine/Asset/AssetPath.h`): under the asset root if the file exists there, else unchanged, i.e. cwd-relative. The `AssetManager` layers its own contract on top: failed loads stay registered with `State == Failed` and `Get*` returns nullptr.
- Physics per-body calls are no-ops (getters return identity) on invalid/stale handles.

## Convention details

The full text behind the short rules in CLAUDE.md.

- **`<Windows.h>` macros**: no public header includes `<Windows.h>` since v1.0 P9 (A103: the assert message box moved into `Log.cpp`); `EntryPoint.h` includes it, with `WIN32_LEAN_AND_MEAN` and `NOMINMAX`, only in its Windows Distribution `WinMain` branch. The engine's `depch.h` includes it before GLM (whose `_fixes.hpp` undefines `min`/`max`), so in engine code `near` and `far` survive. Still write `(std::min)(a, b)` / `(std::max)(...)` / `(std::numeric_limits<T>::max)()` in public headers, which a game may include after its own `<Windows.h>`, and never name anything `near` or `far`. The examples define `NOMINMAX`.
- `DE_CORE_ASSERT(cond, msg)` takes a **plain string only** — NOT `std::format` args (adjacent-literal pasting; format args fail to compile). `DE_CORE_WARN/ERROR` do take format args.
- In a public header, a member named after its own type spells the type qualified: `Dingo::Mesh* Mesh`, `Dingo::CullMode CullMode = Dingo::CullMode::Back`. MSVC accepts `Mesh* Mesh`, but GCC rejects it (`-Wchanges-meaning`) in every translation unit that includes the header.
- On-screen text is **UTF-8** (v0.6.2): `DrawText`, `Font::GetStringWidth`/`MeasureText` and DingoUI share one layout walk, `Internal::TextLayout::Walk` (`src/DingoEngine/Graphics/TextLayout.h`, templated on a glyph source so doctests use a fixed-advance one; wraps at `MaxWidth`, a missing glyph with no `?` is skipped), over the decoder in `src/DingoEngine/Graphics/Utf8.h`, and invalid bytes read as Latin-1. The MSDF atlas bakes Latin-1, printable General Punctuation (U+2010–U+2027, U+2030–U+205E) and U+20AC; anything else draws `?`. Changing the charset must bump `k_FontAtlasCacheFormatVersion` in `Font.cpp`. Only the engine project builds with `/utf-8`, so non-ASCII literals in the test app/examples are hex-escaped.
- **Paths as text are UTF-8**: never call `path.string()`/`generic_string()` in the engine, nor build a `path` from a `std::string`. On Windows both go through the ANSI code page, and the first throws on a name it can't map (a Cyrillic folder under code page 1252 crashed every loose run). Use `Internal::PathToUtf8`/`PathToGenericUtf8`/`PathFromUtf8` (`src/DingoEngine/Core/PathText.h`); games and the test app follow the same rule through the public `FileSystem::PathToUtf8`/`PathToGenericUtf8`/`PathFromUtf8` (#172).
