# Build details

Read on demand from CLAUDE.md, which has the everyday commands. Linux, profiling, ASan, versioning, packaging and the test app.

- **Linux** (GCC ≥ 13, x86-64): `./Generate-Linux.sh` (= `vendor/premake/bin/premake5 gmake`, 5.0.0-beta8; unlike the `.bat` it doesn't pause), then `make -j"$(nproc)" config=<debug|debug-asan|release|distribution> [Project]`; outputs land in `build/bin/<Config>-linux-x86_64/`, the vendor projects' makefiles in `build/make/` (inside their submodules they would overwrite FreeType's tracked `Makefile`). `VULKAN_SDK` must be LunarG's tarball (Ubuntu's Vulkan headers and shaderc are too old), and assimp 6.0.4 is built from source into the git-ignored `vendor/assimp/lib/linux-x86_64/` (LINUX-SUPPORT.md Appendix A). The Vulkan loader is never linked (`vk::DynamicLoader`), D3D sources are left out, and `DE_DEBUG_BREAK` raises `SIGTRAP`. Headless check: `xvfb-run scripts/ci/linux-smoke-test.sh <Config>` (needs `mesa-vulkan-drivers` and `python3-xlib`; with `gdb`, a hung app's thread stacks land in `build/smoke/<Config>/<name>.stacks.log`). For a tester on a real desktop, `scripts/linux-tester/make-bundle.sh <Config> <out.tar.gz>` packs the test app and examples with `run-checks.sh` (the same runs on the tester's desktop, closing only its own windows, into a report archive), `play.sh` and a checklist README; CI's Distribution job uploads it as the `DingoEngine-linux-tester` artifact. LINUX-SUPPORT.md tracks what is done and what's left.
- **New executable checklist**: any project linking the engine must call `copyAssimpRuntime()` (shared helper in the root `premake5.lua`) from its own `premake5.lua`, or it dies with `STATUS_DLL_NOT_FOUND` (`0xC0000135`) before `main` — in Debug-ASan it also copies the ASan runtime DLL. On Linux the same call gives the executable the engine's whole link list in a link group, since `make` links only the libraries a project names. A game that ships packed assets also calls `embedPackKey()` (after `copyAssimpRuntime()`; it reads the project's `dpak.key`, made by `DingoPack genkey`, when premake runs) and passes `Dingo::Generated::GetPackageKey()` (`<DingoPackKey.h>`) as `ApplicationParams.Assets.PackageKey`. Also add it to `.github/workflows/build-release.yml`'s Windows packaging (one job per example, zipping the Distribution job's `<Example>/` folder: exe, DLLs and the `<Example>.dpak` its "Pack example assets" step writes for every `examples/*` with `scripts/pack-assets.ps1`; on Linux `scripts/package-linux-programs.sh` packs every `examples/*` with `scripts/pack-assets.sh`, and the test framework with its loose assets, for the release and for `build-linux.yml`'s Distribution artifacts) and the `.vscode` build/launch entries. On Linux the engine's post-build step also merges the engine, every vendor lib and the static assimp into `build/dist/<cfg>/libDingoEngine.a` (`scripts/merge-static-libs.sh`), the twin of Windows' `lib.exe` merge.
- **Profiling** (v0.9 P1): `premake5 --profile vs2026` compiles Tracy v0.11.1 (`vendor/tracy`, upstream `wolfpld/tracy`, not a fork yet) into the engine with `TRACY_ON_DEMAND`; `DE_PROFILE` is workspace-wide so games' `DE_PROFILE_*` zones (`Core/Profiler.h`, Tracy-free) compile in too. Without the option the macros are empty and no Tracy code links. CI's master build adds one Release `--profile` job. GPU pass timers (`Renderer::BeginGpuTimer/EndGpuTimer`, `Internal::GpuTimers`) are always on: NVRHI timer queries in a 4-frame ring, read in `BeginFrame` while the render thread is parked (D3D11 reads them through the immediate context), at most 32 a frame. See docs/profiling.md.
- **Debug-ASan** links and runs (v0.6.3). Neither CI builds it. The Linux workflow (`build-linux.yml`) builds Debug, Release and Distribution with GCC, like the Windows job's configurations, and runs `scripts/ci/linux-smoke-test.sh` in each, under Xvfb and llvmpipe, on every push to master, like the Windows build (`build-windows.yml`). The Vulkan SDK's shaderc/SPIRV prebuilts are non-ASan, so the configuration defines `_DISABLE_STRING_ANNOTATION` / `_DISABLE_VECTOR_ANNOTATION` workspace-wide; dropping them brings back ~500 `LNK2038 annotate_*` mismatches. The MSVC linker needs no `-fsanitize` flag (cl embeds `/INFERASANLIBS`); GCC does, so Linux adds it.
- **Version**: `VERSION` holds `major.minor`; CI appends the commit count and overwrites `include/DingoEngine/BuildInfo.h` (`DE_ENGINE_VERSION_*`, read by `Application::GetEngineVersion/GetEngineBuildNumber`). The checked-in `BuildInfo.h` is a `0.1.0` placeholder and `VERSION` trails the release branch — neither is a reliable "what am I on" source; the branch/tag is.
- **PCH**: `depch.h` / `depch.cpp`.

## Test app and devices

The test framework takes `--test=<name substring>` (case-insensitive) to boot straight into one case — `--test=asset`, `--test="text test"` (plain `text` would match "Texture Quad Test" first) — otherwise it starts on the first.

Device and adapter selection lives in `Graphics/NVRHI/` (`VulkanGraphicsContext.cpp` for Vulkan). Without a hardware GPU (a VM), D3D11 takes the default adapter, which is WARP, and D3D12 falls back to WARP with a warning (v0.8.2); Vulkan without a driver stops at instance creation with a `DE_CORE_VERIFY` and logs the missing extensions or layers. WARP rasterizes on the CPU: fine for running the test app, meaningless for timings. `GraphicsContext::SupportsWireframe()` is false on a Vulkan GPU without `fillModeNonSolid`; `NvrhiPipeline` then builds `FillMode::Wireframe` solid and warns once (v0.8.3, #78).
