# Rendering notes

Read on demand from CLAUDE.md. Shaders, Renderer2D/3D, lighting, skinning and animation, render targets, post, shadows, compute, particles and the Vulkan/NVRHI rules behind them.

- Shaders are authored as GLSL, compiled to SPIR-V (ShaderC) and cross-compiled to HLSL/DXBC for D3D. `GLM_FORCE_DEPTH_ZERO_TO_ONE` is workspace-global: SPIR-V already emits [0,1] depth — never enable SPIRV-Cross `fixup_clipspace`. Depth targets must set `isShaderResource = false`.
- **Shader disk cache** (`.cache/shaders/` beside the executable since v0.6.2 — `CacheManager` falls back to `GetUserDataDir("DingoEngine")/cache/<exe stem>` when that is read-only; it used to follow the cwd) is validated at load: each `.spv`/`.dxbc` carries a header with a source hash (+ entry point/shader model) and a format version, so edited inline or file shaders recompile automatically — no manual cache clearing. Bump `k_ShaderCacheFormatVersion` in `NvrhiShader.cpp` when compile options or the shader toolchain change.
- **Renderer2D**: auto-batching quads/circles/MSDF text; default 2000 quads per batch, overflow flushes (configurable via `ApplicationParams`). `EndScene` draws quads, then circles, then text; `Flush()` (v0.8.3) draws what is queued so far. Each flush claims another batch vertex buffer from a pool sized for `MaxQuads`, so a stream that switches kind often costs buffers, not just draw calls. One renderer runs at most `k_MaxScenesPerFrame` (32) `BeginScene`s a frame, the room its volatile camera buffer has on Vulkan (it was 8 before v0.8.3). Each batch pass keeps a pipeline per target format (`Internal::GetFramebufferFormatKey`, `Graphics/FramebufferFormat.h`), picked at flush from the current target: a render target need not match the swap chain, which is BGRA8 on most Linux drivers (L16; before it, 2D drawn into an RGBA8 target there was `VUID-vkCmdDrawIndexed-renderPass-02684`). Examples whose HUD text must stay above a fade or a flying body give it a `HUD_TEXT_Z` (Candlewick and Marionette 0.6, AngryBirds 0.5), since text no longer always draws last.
- **Readback** (v0.8.3, #90): `Texture::ReadPixels(done)` (RGBA8 2D only) records a copy into a staging texture. Inside a frame it joins the frame list (never a list of its own mid-frame: D3D11's `ClearState`), puts back the texture's previous resource state (D3D12 caches the state a framebuffer or binding set left it in) and `done` runs through the private `Renderer::RunAfterFrame` at the next `BeginFrame`/`SkipFrame` (before `Begin`, render thread parked) or at `Shutdown`. Outside a frame it executes its own list and resolves at once, but only while `Renderer::IsRenderThreadParked()` (from `BeginFrame`/`SkipFrame` to `EndFrame`, and before the first frame); between frames (event handlers, post-execution callbacks, `OnDestroy`) the render thread may be submitting, so the whole copy waits in `RunAfterFrame`. NVRHI's `mapStagingTexture` waits for the copy on every backend. Row 0 is the texture's first row: the top of a render target, the bottom of a file image (`ReadImage` flips on load). `SaveToFile` flips non-render-targets back, and `FileSystem::WriteImage` (stb_image_write v1.16, `vendor/stb/include`, encoded to memory and written through `std::ofstream` for Unicode paths) takes its own `flipVertically`. A render target drawn on a Renderer2D quad needs a negative height to stand upright.
- **Renderer3D**: CPU-transforms every submitted vertex every frame. Batches are grouped per `Material*` (null = built-in default); `MaxVertices`/`MaxIndices` (default 64k/96k, configurable) cap one batch = one draw, and a material that outgrows it spills into another chunk (v0.6.3). Only a single mesh bigger than a whole batch is dropped (warn once, `Statistics::DroppedMeshes`). `MeshRendererComponent::Visible = false` is per-entity culling. A batch whose material drew nothing for 300 scenes in a row (`k_MaxIdleBatchScenes`) is released. **Translucent pass** (Headstone #91): a `MaterialParams::Translucent` material's meshes (not `ShadowsOnly`, which batch as before) skip `m_DrawOrder` (`MaterialBatch::Translucent`); `SubmitMesh` transforms them into `m_TranslucentVertices/Indices` with a `TranslucentSubmission` keyed by its transformed bounds' centre (#160; `TranslucentSortKey`: squared eye distance, or `-dot(centre, CameraPosition.xyz)` orthographic), and a translucent `SubmitSkinnedMesh` marks its `SkinnedSubmission::Translucent` and adds one keyed by its rest bounds' centre (an instance's later translucent meshes reuse its first key, so they stay adjacent and upload once). `PrepareTranslucentPass` (after the opaque uploads, before the shadow pass) `stable_sort`s far to near, writes the static ones' indices in that order per `TranslucentSlice` (a run of `m_TranslucentVertices` cut at submission to fit one pooled buffer pair, uploaded straight from there, so a vertex is written once on the CPU, #160) (one ranged `DrawIndexed` per run of one material in one buffer; a `CullMode::None` material's mesh, every lit one, puts its triangles facing away from the camera by vertex normal first, #150) and, for a shadowed scene, notes each run of casters of one mask lying back to back in a buffer as a `TranslucentCasterDraw`, a `firstIndex` range of those same buffers that the shadow pass draws (#158; they used to be copied and uploaded again). `DrawTranslucentPass` runs after the opaque skinned draws and before particles (in a post scene `EndScene` calls `ApplyAmbientOcclusion` once before it when it or particles have anything to draw, since neither writes depth, #153; particles never join the translucent sort, so one behind glass draws over it, a documented limitation) (`DrawSkinnedSubmission` is the shared skinned body; a translucent two-sided one draws twice through `Renderer::DrawIndexed(material, cullMode, ...)`, `CullMode::Front` then `Back`, swapped for a mirrored transform, which `Material::GetOrCreateRenderPass(layout, target, cullMode)` caches beside the material's own passes); the skin buffer holds 2 writes an instance of the budget and `ResolveSkinnedBudget(shadows)` charges each instance one per pass it uploads in (shadow, opaque, translucent), dropping one whose writes don't fit (#159: 3 writes an instance cost every skinning renderer, translucent or not). `Statistics::TranslucentMeshes/TranslucentDraws`. Batch Test (`--test=batch`) checks it by stats and readback (incl. a closed two-quad mesh lit from the camera, static and skinned, plain and mirrored), `--batch-alpha=<a>` draws three overlapping translucent boxes.
- **Lighting** (v0.7): `Renderer3D::SubmitLight(Directional/Point/Spot)` + `SetAmbientLight` are scene-scoped (cleared at each `EndScene`); one renderer runs at most `k_MaxScenesPerFrame` (32) scenes a frame, the room its volatile scene buffer has on Vulkan. A scene that submits nothing gets `Renderer3DParams`' default light (`SetDirectionalLight` replaces it), pixel-identical to pre-v0.7; any submitted light, even an ignored one, switches it off. ≤ 4 directional; point + spot share `GetLocalLightBudget()` (`MaxLocalLights`, capped at 32): frustum-culled, then ranked with ties to the nearer light (distance / range), then submission order (still scenes never flicker), warn once on overflow. `Renderer3DCapabilities::LightBudgetFade` (v0.9 P6, #75; 0 = off, the default, so nothing changes) ranks by one continuous `Priority` = score / (1 + nearness) instead and dims each drawn light by a smoothstep of its priority over the first dropped light's (`BudgetFade`), so lights trading places at the edge are both dark when they trade; `SetLightBudgetFade`, `Statistics::FadedLights`. Point/spot lights with intensity/range ≤ 0 or non-finite values are ignored; directional lights only reject non-finite ones. No tone mapping until v0.9: lights clip (K17) and pop at the budget edge (K16).
- **Lit shader file** (v0.7): `src/DingoEngine/Graphics/Shaders/Renderer3D_Lit.glsl`, embedded into `DingoEngine.lib` by a premake rule running `scripts/embed.lua`; Release/Distribution always use that copy. Debug/Debug-ASan load it from `DE_ENGINE_SHADER_DIR` (silently using the embedded copy if the file is missing) and hot-reload it via `Internal::WatchUnmanagedShader`, only while the AssetManager's opt-in `EnableHotReload` is on. **Pitfall**: an OLD Debug exe runs the CURRENT .glsl; hide the file to A/B old code.
- **Lit materials** (v0.7): `Renderer3D::CreateLitMaterial(MaterialParams)` (lit shader, `CullMode::None`) with per-MATERIAL `Emissive*`, `Roughness` (0.5) and `Specular` (0 = off); `GetDefaultMaterial()` is shared by every mesh without its own. Texture/sampler **slot 0 only** (anything else warns once and the material is skipped: Vulkan would not reject the invalid binding set); alpha comes from the mesh colour only (ordinary lit draws are unsorted and write depth; `MaterialParams::Translucent`, Headstone #91, turns the depth write off whatever `DepthWrite` says, the twin inherits it, and Renderer3D draws it in the sorted translucent pass under Renderer3D above). `EndScene` rebuilds each drawn lit material's binding 1 from its settings every scene (the surface setters don't call `SetUniform`); any `Renderer3D` may draw one; the caller deletes it before the creating renderer shuts down. A custom shader brings its own emissive/specular. `Material::SetTexture/SetSampler` rebuild the cached passes when a slot's pointer changes. A texture created at a freed one's address is still caught at bind time, because every texture draws `GetGeneration()` from one shared counter (v0.8.3, #77, formerly K18); a sampler has no generation, so clear a sampler slot before reusing a freed sampler's address.
- **Skinned models** (v0.8 P4): `Model::LoadFromFile` reads once (`ReadFile(path, 0)`) and applies the static flags (`PreTransformVertices` included, byte-identical to before) unless a mesh has bones or the file is a clip library (clips, no meshes). `ModelLoadParams::ClipsOnly` (#100; `LoadFromFile` and the AssetManager's `Load`/`LoadAsync` overloads, kept across reloads) skips a skinned file's meshes; on a boneless file it fails. Textures embedded in a GLB (`*N`) or FBX load through `FileSystem::ReadImageFromMemory`, keyed `modelPath#name` and dated by the model file (#99). Skinned files get a `Skeleton` (the subtree under the common ancestor of every bone and animated node; joints a skin vertex can reach come first and `GetSkinJointCount()` is the palette size; `Joint::RestPose`, `InverseBind`, `GetRootTransform()`), skinned `Mesh`es (`HasSkin`, `GetSkinVertices`, 56 B `SkinnedMeshVertex`; `GetVertices()` stays the rest pose in model space for Jolt and `SubmitMesh`) and `AnimationClip`s (T/R/S tracks in seconds, `GetSourceSkeleton`). Assimp gives every imported channel all three tracks. Details: the v0.8 plan's "As built in P4".
- **GPU skinning** (v0.8 P5): `Renderer3D::SubmitSkinnedMesh(mesh, transform, palette, color, material)` draws one skinned mesh per call after the opaque static batches (a translucent material's in the sorted translucent pass instead), from a `Mesh`-owned immutable VB/IB (made on the first draw, freed in `~Mesh`, so a `Mesh` is non-copyable). The palette (`Skeleton::GetRestPalette`, or `ComputeGlobalTransforms` + `ComputeSkinningPalette`) goes to a volatile `SkinData` UBO, uploaded only as far as the mesh's last joint (the whole block on D3D11, where partial constant-buffer updates aren't guaranteed). An *instance* is a run of calls with the same palette, transform and colour (a model's submeshes): it uploads once and counts once against `Renderer3DCapabilities::MaxSkinnedInstances` (64, at most `k_MaxSkinnedInstancesLimit` 256), the per-frame budget and the buffer's Vulkan writes; an instance past it is dropped whole (warn once, `Statistics::DroppedSkinnedDraws`). At most `k_MaxSkinJoints` (128) joints a draw; past that, without a skin, or with too few joints passed, it falls back to `SubmitMesh` (rest pose, with the default material if the given one is skinned-only). `SubmitMesh` itself checks each material once a scene and draws a skinned-only one's static meshes with the default material (warn once), so a `SkinnedMeshRendererComponent`'s custom skinned material never builds a static pipeline. The skinned lit shader (`Renderer3D_Lit.glsl` built with `ShaderParams::AddDefine("DE_SKINNED")`, vertex stage only, `SkinData` at binding 4) and the skin buffer are made on the first skinned draw, so apps that never skin don't compile it. Skinned normals use the cofactor of the blended joint matrix, and the loader poses rest normals the same way. A lit material draws through a "skinned twin" keyed by `Material::GetId()` (never reused; `Material` is non-copyable) and resynced every draw, its slot cleared first whenever the source's `GetBindingRevision()` moved, so a sampler slot the source cleared and refilled at a freed sampler's address reaches it. A custom skinned shader declares a `SkinData` block, found by name (`Shader::FindUniformBufferBinding`, bound by `Material::SetSkinUniformBuffer`; static batches bind none) at a binding from 2 to 13 (D3D11's constant-buffer slots) that its textures and samplers leave free, else it draws with the default lit material and a warning. Shader defines enter the bytecode-cache hash and file stem only when present, so define-less caches stayed valid (`k_ShaderCacheFormatVersion` unchanged). `SkinnedMeshRendererComponent { Model*, Color, Material*, Visible }` draws a model through it, posed by its animator (rest palette without one). Animation Test: `--test=anim`, `--anim=bind|bindstatic|pose|clip|blend|layers|events|crowd`, `--anim-clip=Survey|Walk|Run`, `--anim-time=S` (clip, layers: freeze), `--anim-speed=X` and `--anim-phase=F` (blend: the Speed parameter, a frozen phase), `--anim-count=N`, `--anim-static`, `--anim-skeleton` (bones as boxes in a see-through Fox), `--anim-reload` (clip: edits a managed copy on disk); the test app also takes `--no-vsync`.
- **Animator** (v0.8 P6, layers and blends P7): `Graphics/Animator.h`, usable without a scene. `AnimationState::Clip(clip)` or `Blend1D(parameter, {{value, clip}...})` (two neighbouring clips by `SetFloat` value, synced on normalised phase: a blend's `Time` is the shared 0–1 phase advanced at the lerped cycle length). Layers: `m_Layers[0]` full body from the rest pose; `SetLayer(i, AnimationLayer().SetMask(root).Exclude(j).SetWeight(w))` overrides masked joints in index order, every sample starting from the pose underneath so unanimated joints keep it; a null clip on a layer above 0 is "transparent" (the pose below), which is how a layer fades in from nothing and how `Stop` fades out. `PlayOneShot(clip, in, out, layer)` keeps a copy of the interrupted state advancing (time only) and pushes it back `out` seconds before the clip ends (`IsOneShotPlaying` until then; `Stop` always cancels it; marks in the last `out` seconds don't fire); a public `Play` of that same state is a no-op, of anything else cancels the return. Layer 0 samples straight into `m_LocalPoses`; while upper layers apply, its own result is copied to `m_Layers[0].Pose` so an overflow freeze of layer 0 never bakes the upper layers in. A blend side with zero length (no clip, one key) takes the other side's cycle. `Play(state, fadeSeconds, layer)` pushes onto that layer's stack of at most 4 states, each fading in over the ones below (lerp/shortest-path nlerp of local T/R/S); past 4 the current pose is frozen into one entry (`FreezeSource`; a layer above 0 that the last `Evaluate` skipped, at weight 0, is `PoseStale` and is evaluated then, over the layers below re-applied from their cached `Pose` at their `AppliedWeight`, v0.8.3, #82). Playing the state that already plays (even a finished one-shot) is a no-op, so scripts may call it every frame; with fade 0 it completes that state's fade-in. Key cursors per channel step forward and binary-search on a jump. Clip bindings are cached per `AnimationClip::GetId()` (never reused) and looked up by id, never pointed at, so an `Animator` copies safely. At most `k_MaxLayers` (32) layers: a larger index is ignored with a warning. A non-looping state catches up from `CatchUpFrom` (its start, or its latest seek) when it first leads, and its pending one-shot copy shares its `Led`. `AnimationClip` trims tracks whose times and values differ in count. A clip whose `GetSourceSkeleton()` isn't the animator's skeleton is retargeted by name: rotations from the clip, translation only on root-most moving joints (a translation track holding only its rest offset, as exporters key a still `root`, moves nothing and never shadows the hips; `targetRest + (key − sourceRest) × ratio`, ratio = the two rest offsets of that joint from its parent, so units and root scale cancel), every other joint at the target's rest translation and scale. ECS: `AnimatorComponent { DefaultClip, PlayOnStart, Speed, Enabled }` (in `DE_INSTANTIATE_COMPONENT` and the duplicate list) + engine-internal `AnimatorRuntime { unique_ptr<Animator>, SkeletonId }` (`RuntimeComponents.h`), made by `AnimationSystem` on the first `Scene::GetAnimator` or update, or before a body is built (`EnsureAnimators` in `OnPhysicsStart`, `EnsureAncestorAnimators` in `CreateRigidBody`, so a body on a socket starts at `DefaultClip`'s first frame), rebound (back to `DefaultClip`, evaluated at once) when the model's `Skeleton::GetId()` changes (ids, never addresses: a reloaded model can land at the old one's), surviving `OnStop`/`OnStart`, freed by an `on_destroy<AnimatorComponent>` hook (its pool is created in `Connect` so the hook never creates a pool mid-destroy). `Scene::OnUpdate`: scripts → destroy flush → `AnimationSystem::Update` (dt × Speed while Enabled; then each entity's events, copied, to `ScriptableEntity::OnAnimationEvent` via `ScriptSystem::DeliverAnimationEvent`, started scripts only, with `Updating` set so destroys defer) → destroy flush → physics → audio. `Animator::GetStates(layer)` reports a layer's states (clip or blend, fade weight, time) for tooling; the F7 tab lists every live scene's animators (`Scene` joins `Internal::AnimationDebug` on construction) and its last 20 events, which `AnimationSystem::Update` records into a per-scene ring (`EventScratch::Recent`).
- **Animation events** (v0.8 P8): `AnimationClip::AddEvent(t, name)` / `AddEventRange(a, b, name)`, kept as time-sorted `EventMark`s (end before instant before begin at one time). `Model::LoadFromFile` reads `<model stem>.events` beside a model with clips (`Model::LoadEvents`: `<clip> <seconds> <event> [payload]` or `<clip> <a>..<b> <event> [payload]`, `#` comments, quoted names; the payload (#103) is interned `key=value`/flag text, read through `AnimationEvent::Payload` (`AnimationEventPayload::GetFloat/GetInt/GetString/Has`), and a `RangeEnd` carries its begin's; bad lines warn with their number). Per layer each `Update`, only the dominant contribution fires (`Animator::Dominant`: the largest fold share `w × Π(1 − w above)`, ties to the newer state; a one-shot's pushed-back `Resume` is flagged `Returning` and takes over at once, after the one-shot's own marks for that frame are collected; a blend's heavier side; a layer above 0 only at weight ≥ 0.5): marks crossed in `(PreviousTime, Time]` (inclusive on a state's first `Update` or after a seek, `Fresh`; a non-looping state catches up from its start the first time it leads, `Led`), with loop wrap (`Wrapped`, set in `Advance` from the unwrapped target, so a step longer than the clip still laps) and reversed playback (begin/end swap). A zero step never touches `Time`. Seeks (`MarkSeek`) close the leading state's ranges at the next `Update`. `OpenRange` keeps the begin's interned name and end time, so every early close sends its `RangeEnd`; when the dominant clip's `GetEventRevision()` moves (a reload, `ClearEvents`), a range whose event is gone or renamed ends at once, and a range matches its marks by index and name. The (state `Serial`, clip) pair identifies the contribution; when it changes, open ranges get a `RangeEnd` (`CloseRanges`), and an end with no begin fires nothing. `AnimationEvent::Name` views an interned copy (`EventMark::Name`, never freed), so a held name outlives `ClearEvents` and a model reload. `GetEventsThisFrame`, `ForEachEventThisFrame`, `IsEventActive`. `AnimationSystem::EnsureAnimator` poses a new or rebound animator with the public `Evaluate()` (no time, no events), so its first real update still fires the clip's start. Delivery copies every event (`EventScratch::Deliveries`) before any handler runs; events for a script that hasn't started (spawned this frame) wait in `EventScratch::Waiting`, as do the `RangeEnd`s the `on_destroy<AnimatorComponent>` hook queues for an animator removed mid-range (`Animator::GetOpenRangeEnds`). `SetSkeleton` (a rebind) keeps the open ranges with a null `Clip` (the old model may be freed) and sets `CloseRangesOnUpdate`, so they end at the next `Update`, which runs `CollectEvents` for them even with no skeleton bound (v0.8.3, #80). `AnimationSystem::Update` calls `Animator::ClearEventsThisFrame` for every animator it skips as disabled, so a poller never re-reads the frame it stopped on (v0.8.3, #81). The Fox's `test/assets/models/Fox/Fox.events` holds its real footfalls (each foot's lowest point) and a Survey range.
- **Root motion** (#104): `Animator::SetRootMotion(RootMotionMode::Off|XZ|Full)` (`Graphics/Enums/RootMotion.h`; Off, the default, is bit-identical to before). Each `ClipBinding` gets a `RootChannel` (`BindRootMotion`): the root-most bound joint whose translation track moves (the retargeting test, against the source rest when retargeted), or `SetRootMotionJoint(name)`'s (clears the bindings), with that joint's parent frame taken at REST (`RootTransform × restGlobal[parent]`) and its model-space pose at t = 0. `SampleClip` ends with `HoldRoot`, which takes the root's travel and turn since the start out of the pose on every layer (XZ: horizontal position and the yaw of `rotation × start⁻¹`, height and tilt stay; Full: the whole frame). `Update` resets `GetRootMotionDelta()` and, before `Evaluate`, `CollectRootMotion` folds layer 0's states like the pose (each over the ones before at its fade weight; a blend mixes its two sides at `T`; frozen/transparent states move nothing): per state `ClipMotion(PreviousTime → UnwrappedTime)` (`Advance` keeps the unwrapped target), out to the loop's edge, whole laps (≤ 64), then in from the other edge; `SegmentMotion` = `Frame(start)·Frame(a)⁻¹·Frame(b)·Frame(start)⁻¹`, so a turn pivots about the held root. Only played time counts: a seek or a new state moves nothing; `SetSkeleton` clears it. `AnimatorComponent::RootMotion` (pushed to the animator by `EnsureAnimator` every pass) + `ApplyRootMotion` (default true): `AnimationSystem::Update` (now taking the `PhysicsSync`) applies it after the animator's `Update`, as `local × delta`: a controller gets `SetLinearVelocity(worldRot × (worldScale × T) / dt)` (XZ keeps its y velocity) and `SetRotation`; a kinematic root body `MoveKinematic`; a dynamic or static body warns once and stays; anything else (a kinematic child too) its `Transform3DComponent`. A controller it stops driving (`AnimatorRuntime::DroveController`) gets its horizontal velocity zeroed once; a disabled animator's delta is cleared (`ClearRootMotionDelta`) like its events. Warned once: an unknown `SetRootMotionJoint` name, and a clip keying a joint above its root joint (measured at rest, so those keys stay in the pose). Animation Test: `RunRootMotionChecks` (clips built from Walk with travelling, bobbing or turning hips) and `--anim=root` (a Fox walking a circle). docs/animation.md "Root motion".
- **Model hot-reload** (v0.8 P9): `Model::Reload()` reads `GetFilePath()` (absolute, set by `LoadFromFile`) into a temporary model (`Model::Load(path, refresh)`) and `Adopt`s it, so every object a game holds survives: `Mesh` per submesh index (`Mesh::Reinitialize`: new `GetId()`, GPU skin copy freed; extra submeshes appended, missing ones `Clear()`ed), `Material` per index (slot 0 retargeted), textures per resolved path (the loader's `TextureCache::Reusable` re-reads them in place with `Texture::Reinitialize`; unused ones stay alive, since games copy `DiffuseTexture` into their own materials), clips per name, n-th to n-th (`AnimationClip::Reinitialize`: new id, keys, events; a vanished clip is `Clear()`ed to zero length; new ones appended), and the `Skeleton` while every joint keeps its name and parent (`Skeleton::Reinitialize`, same id, `GetRevision()` bumped; otherwise the old one moves to `m_RetiredSkeletons` and a new one with a new id is adopted, so a Scene rebinds its animators to `DefaultClip`). `GetGeneration()` counts successful reloads; a file that fails to load changes nothing. The Animator takes a reload up by itself: `SyncSkeleton` (rest poses, bindings cleared on a revision change) at the top of `Update`/`Evaluate`, `SampleClip` binds by id on demand, `Sample` resizes key cursors when a clip's channel count changed, and `Advance` wraps a state whose clip shrank under it before stepping (no burst of marks). `AnimatorRuntime::ModelGeneration` makes `EnsureAnimator` re-`Evaluate` a paused animator. The AssetManager's Model policy has `ReloadInPlace` and is watched, with `<stem>.events` as a `Companion` file (`Internal::CompanionWatch`; a missing file reads as the epoch) whose change alone runs `ReloadCompanion` = `Model::ReloadEvents()` (events only, meshes untouched). A reload re-reads a texture only when its file's write time moved; reused textures sit in the temporary model as `Borrowed` (never freed by it). Code-added events are dropped by a reload; bodies already built keep their old shape. Animation Test: `RunReloadChecks` edits a copy in `%TEMP%/DingoAnimationTest`, and `--anim=clip --anim-reload` edits a managed copy on disk while it plays.
- **Marionette** (v0.8 P13, `examples/Marionette`): one `ArenaDirector` script owns the order (brains → fighters → combat → camera → HUD, reading last frame's poses); `Fighter` is one class for the player and the AI, each brain writing a `FighterIntent`. Every combat window is a clip event from the `.events` files beside the five KayKit `Rig_Medium` libraries (`windup`, `hitbox`, `combo`, `dash`, `iframes`, `parry`, `step_l/r`; `Moveset` is the data, `ValidateMoveset` warns about a window that ends after its one-shot's `duration − fadeOut`, where it never fires). Hits are game-side swept spheres on joint sockets, counted only while the attacker is in `Attack` (controllers aren't bodies, so no cast finds a fighter). Block is layer 1 masked from `spine` (`Melee_Block` non-looping so its t≈0 `parry` fires), death a non-looping `Play`, locomotion a `Blend1D` on `Move`. Each PNG goes into a lit material on slot 0 (the loader skipped GLB-embedded textures until #99). `GameAssets::PollEventChanges` watches `AnimationClip::GetEventRevision()` to re-validate on a live edit. Flags: `--check` (asset, movement, combat and AI checks, read from the log; a failure doesn't change the exit code), `--drive=duel|ramp|circle|strafe|wall`, `--autoplay`, `--tournament=N` (with `--seed` and `--player-tier=1..3`: the stronger tier must win 8 of 10, a mirror is logged only), `--fixed-dt=<s>`, `--steps-per-frame=K` (with `--fixed-dt` and `--autoplay`), `--freeze` with `--pose=<clip>@<s>` / `--move` / `--phase`, `--debug-hitbox`, `--break-hitbox`, `--bout=1..3`, `--lineup`, `--overview`, `--end`, `--hot-reload`, `--live-edit-demo`, `--perf` (with `--autoplay`: mean frame, `Scene::OnUpdate` and render ms over 600 frames), `--graphics=`, `--vsync=`. `--freeze` implies a fixed delta (frozen captures on a real delta differ run to run as the controllers settle). Scripted and `--hot-reload` runs set `UpdateInBackground`, since an unfocused app pauses (a long check hangs; an edit made in another window wouldn't land).
- **Render targets** (v0.9 P2): `TextureFormat` adds `RGBA16F`, `R11G11B10F`, `R8`, `R16F`, `R32F`, `D32` (`GetBytesPerPixel` sizes uploads; RGBA32F used to upload with pitch 0). `FramebufferParams::SetDepthSampleable` wraps the depth in a D32 `Texture` (`GetDepthAttachment`), typeless with an SRV (`TextureParams::IsShaderResource`); every depth is an `NvrhiTexture` now, built exactly as before when not sampleable. - **Swap-chain acquire** (Vulkan, v0.8.3, #79): NVRHI attaches a queued semaphore wait to the next submission from *any* command list, so `VulkanSwapChain::AcquireNextImage` only marks the wait pending and `SwapChain::QueueImageWait()` queues it just before the commands that draw into the image execute: `Renderer::Execute` on the render thread, `ImGuiRenderer::RenderToSwapchain` for a viewport's own list, and `Present` as a fallback. Never queue it at the acquire again. GPU submissions the main thread makes between `EndFrame` and the next `BeginFrame` (event handlers, post-execution callbacks) still race the render thread, the wait included. A failed acquire (a minimized window) leaves `IsImageAcquired()` false; the next `BeginFrame` applies the pending resize and acquires on the main thread while the render thread is parked, or skips the frame (`IsFrameSkipped()`, though the command list is open; ImGui's main viewport isn't drawn), and an ImGui viewport without an image draws nothing. The render thread acquires right after each present, so at teardown the last acquire is still signalling: `VulkanSwapChain::Destroy` consumes it (`m_AcquireSignalPending`, set by a successful acquire and cleared by `Present`'s submit) with `QueueImageWait()` plus an empty `executeCommandLists` before its `waitIdle`, since `waitIdle` doesn't cover an acquire (#182). An ImGui viewport's window destroys its own swap chain (#181).
- **Small Vulkan buffer writes**: NVRHI's `writeBuffer` records a write of up to 64 KiB to a non-volatile buffer with `vkCmdUpdateBuffer`, rounded up to a multiple of 4 bytes read from the source and written to the buffer. `NvrhiGraphicsBuffer` allocates its Vulkan buffers rounded up to 4 bytes, and `NvrhiGraphicsBuffer::Write`, which every `GraphicsBuffer` upload goes through, pads a source whose size isn't a multiple of 4 (v0.8.3). Raw NVRHI buffers pad their own (the ImGui index buffer, #86); volatile buffers are copied byte for byte. After the write, `Write` puts a non-volatile buffer back into its initial state and commits the barrier at once (#145): NVRHI moves vertex and index buffers out of `CopyDest` only when the bound buffer changes, so a scene that rewrites the batch buffers the last scene left bound drew without a barrier; a pending barrier would be ORed with the next state, which D3D12 rejects for a read state plus a write state. `NvrhiCommandList::UploadTexture` does the same for a texture (#154: a mid-frame `Texture::Upload` between two draws of one binding set left it in `CopyDest`; the Render Target Test draws one material twice around an upload).
- Custom material shader binding convention: **0** = scene UBO, **1** = the material's own `SetUniform` params, **2+** = textures/samplers, interleaved. The binding set must match shader reflection exactly. The scene UBO (`Renderer3D::CameraData`, std140, volatile, uploaded at the top of `EndScene`) starts with a frozen 96-byte prefix (`ViewProjection`, `LightDirection`, `Ambient`) that custom shaders may declare alone; the lights follow, then the fog, mirrored by `CameraData` in `Renderer3D_Lit.glsl`. Only ever append. The prefix carries only the first directional light. A binding reflected by more than one stage enters the layout once (`NvrhiShader::CreateBindingLayoutHandle`).
- **Volatile uniform buffers** (`CreateUniformBuffer`, every `Material` UBO, both renderers' camera/scene UBOs) must be written in every frame that binds them (unwritten, Vulkan reads a stale version and D3D12 removes the device). `Renderer::DrawIndexed(Material*)` does this for materials — it re-uploads a material's UBO on its first draw of each frame (`Renderer::Begin` bumps a frame index) and after every `SetUniform` — so a game sets params only when they change; a raw `CreateUniformBuffer` needs its own `Renderer::Upload` every frame it is bound. On Vulkan each holds `GraphicsBufferParams::MaxWritesPerFrame` (default 8; a material's from `MaterialParams::UniformWritesPerFrame`, which the particle draw materials set to `k_MaxScenesPerFrame`) × 4 versions — NVRHI can't recycle a version until it has seen the GPU finish that frame, and up to four frames can look unfinished. A write beyond that is dropped (`[NVRHI] ... maxVersions = N, which is insufficient`) and later draws read the earlier data; before this was sized, a second `Renderer3D` pass in one frame drew with the first pass's camera and lights. D3D11/12 have no such limit.
- Prefer `RGBA8_UNORM` for standard color textures.
- **Blending** (`NvrhiPipeline`, every pipeline): straight-alpha "over", colour `SrcAlpha`/`OneMinusSrcAlpha` and alpha `One`/`OneMinusSrcAlpha`, so a target stays as opaque as what lies under a translucent draw. Before v0.8.2 the alpha factor was `Zero`: text quads (alpha 0 outside the glyph, no discard) made the test app's viewport framebuffer see-through, and ImGui showed its panel as a box around each letter. Swap chains ignore alpha, so games drawing to the window never showed it.
- **Winding** (v0.8.1, GitHub #68/#69): `CreateBox` and `CreateSphere` are counter-clockwise seen from outside (so are well-formed model files; the loader keeps a file's winding), and `MaterialParams` defaults to `CullMode::Back` + `FrontCounterClockwise = true`. NVRHI flips the Vulkan viewport to D3D's, so the flag means the same on all three backends. Before v0.8.1 `Material` dropped the flag (clockwise fronts) and `CreateSphere` was wound inward, so `CullMode::Back` drew boxes and models inside out. Lit materials and the skinned twin still force `CullMode::None`. Renderer3D keeps a mirrored (negative-determinant) transform's index order, so a culling material draws such an entity inside out. The Mesh 3D Test (`--test=mesh`, `--mesh=box|sphere`, `--mesh-angle=<deg>`) checks both primitives' winding at start.
