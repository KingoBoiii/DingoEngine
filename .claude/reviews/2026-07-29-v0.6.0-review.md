# Code review — v0.6.0 (asset pipeline) + engine sweep

**Date:** 2026-07-29 · **Branch:** `v0.6.0` (14 commits ahead of `master`, +2960/-102) · **Scope:** the v0.6 asset pipeline diff *plus* a structural/perf sweep of the existing engine.

**Method:** four parallel read-only reviewers (asset core / hot-reload & shader cache / example+test+debug-UI / engine-wide sweep). Every Critical and High item below was then re-verified by hand against the source. Static review only — **nothing was built or run**, so all runtime claims are code-traced, not observed.

Findings are marked **CONFIRMED** (code path traced end to end) or **PLAUSIBLE** (needs a runtime repro). Two bugs were found independently by two reviewers and are flagged as such.

## Correctness bugs

### B1 — PSO rebuild dereferences a freed swap-chain framebuffer {#b1}
**Critical · S · CONFIRMED · found independently by 2 reviewers**
`src/DingoEngine/Graphics/NVRHI/NvrhiCommandList.cpp:107` → `NvrhiPipeline.cpp:74`, `:106`

`SetPipeline` does `Destroy(); Initialize();` on a shader-generation bump, and `Initialize()` dereferences `m_Params.Framebuffer` (captured at `Pipeline::Create`) twice. For any pipeline built against `Renderer::GetSwapChainFramebuffer()` that object is `delete`d on every resize (`VulkanSwapChain.cpp:490-498`, `DirectX11SwapChain.cpp:196`).

The irony: the comment at `NvrhiCommandList.cpp:117-119` documents exactly this hazard ("for swap-chain pipelines it dies on every resize") for the *binding* case — the new rebuild path three lines above it ignores its own warning.

**Repro:** run ArenaShooter → resize the window once (its background pipeline is created against the swap-chain framebuffer, `GameLayer.cpp:157`) → save `assets/shaders/background.glsl`. The next draw rebuilds through freed memory.
**Fix:** don't retain a `Framebuffer*`. Store `nvrhi::FramebufferInfoEx`, or hold the swap chain + `GetResizeGeneration()` and re-resolve — `ImGuiRenderer::GetOrCreatePipeline` (`ImGuiRenderer.cpp:444-448`) already implements the correct pattern.

### B2 — `Reload` on a Font/Model deletes the object games cache {#b2}
**Critical · S · CONFIRMED · found independently by 2 reviewers**
`src/DingoEngine/Asset/AssetManager.cpp:205-209` + `:256-257`; `UI/ImGui/ImGuiDebugPanels.cpp:450`, `:463`; `examples/ArenaShooter/src/GameLayer.cpp:135`

`ReloadInPlace` only handles `Texture2D` and `Shader`; the `default` returns false, so `Reload` falls through to `UnloadInternal` (which does `Destroy(); delete;`) + `LoadInternal`. The F6 Assets panel offers **Reload** on *every* row plus **"Reload all loaded"**, with a comment claiming it is "safe to press at any time". ArenaShooter caches `m_Font` once at `GameLayer.cpp:135` and dereferences it every frame (`:395-400`, `:407-408`).

`EnableDebugOverlays` defaults to `true` **in Distribution too**, so this is reachable in a shipped build: press F6, click Reload on the font row, and the next `DrawText` is a use-after-free.
**Fix:** two-sided. (a) Gate the button on a new `SupportsInPlaceReload(AssetType)` so Font/Model/AudioClip rows don't offer it (or warn); (b) have ArenaShooter re-fetch `GetFont(m_FontHandle)` at point of use — which it already does correctly for audio clips.

### B3 — A null `Texture*` crashes `Renderer2D` on the second quad {#b3}
**Critical · S · CONFIRMED**
`src/DingoEngine/Graphics/Renderer2D.cpp:555` (engine) + `examples/ArenaShooter/src/GameLayer.cpp:317`, `:320` (trigger)

`ResetQuadTextureSlots` nulls slots 1..N (`:646-647`). `GetTextureIndex` stores whatever it is given, unchecked (`:565`), then on the next call dereferences every occupied slot: `m_TextureSlots[i]->NativeEquals(texture)` — a **virtual call through null**. `FlushQuad` *does* have a null→white fallback (`:673`), but it runs at flush time, long after the crash.

ArenaShooter guards `m_PlayerTexture` (`:330`) but passes `m_BulletTexture`/`m_EnemyTexture` unguarded, and `OnAssetsReady` only *warns* on a failed load before transitioning to `Playing` (`:138-139`). One missing `enemy.png` (or the wrong cwd) = crash as soon as two enemies are on screen.
**Fix:** engine-side is the valuable half — redirect null to slot 0 (the white texture) inside `GetTextureIndex`, so no game can trigger this. Then add the two missing guards in ArenaShooter for parity with `m_PlayerTexture`.

### B4 — "Draw call will be skipped" is false {#b4}
**High · S · CONFIRMED**
`src/DingoEngine/Graphics/NVRHI/NvrhiCommandList.cpp:111-115` + `Renderer.cpp:280-284`

`SetPipeline` logs and returns on a null PSO handle — but it has already reset `m_GraphicsState` (`:99`), and the caller unconditionally continues to `SetFramebuffer` + `DrawIndexed`, which unconditionally calls `setGraphicsState`. NVRHI's Vulkan backend dereferences the pipeline without checking (`vulkan-graphics.cpp:671`). So the error message promises a skip that never happens.

Now live via reload: delete a `#type fragment` block, `Build()` succeeds vertex-only, `NvrhiPipeline.cpp:89` inserts a null pixel handle via `operator[]`, the guarding `DE_CORE_ASSERT` is compiled out in Release/Distribution, `createGraphicsPipeline` returns null → AV on the next draw.
**Fix:** have `SetPipeline`/`SetRenderPass` return a validity bool and make `Draw`/`DrawIndexed` bail when `m_GraphicsState.pipeline` is null.

### B5 — `Texture::Reinitialize` invalidates nothing that `Material` cached {#b5}
**High · S · CONFIRMED**
`src/DingoEngine/Graphics/NVRHI/NvrhiTexture.cpp:100-111`; `Material.cpp:64-68`, `:177`

There is no texture generation counter — the only lazy-rebuild trigger is `Shader::GetGeneration()`. `Renderer2D` self-heals only incidentally, because `FlushQuad` re-sets all 32 slots every batch and `SetTexture` compares handles. `Material` does not: `GetOrCreateRenderPass` bakes once and `Material::SetTexture` deliberately does *not* invalidate the cache.

So reloading a model's diffuse or any material texture creates a new `nvrhi::ITexture` while the cached binding set keeps referencing the old one: the stale image renders forever **and** its `VkImage` is never freed (the binding set holds the last reference). `Texture.h:100-102` claims "binding caches keyed via NativeEquals re-bake naturally" — that is only true of `Renderer2D`.
**Fix:** add `Texture::GetGeneration()`, bump it in `Reinitialize`, and check it in `SetPipeline`/`SetRenderPass` next to the shader generation.

### B6 — Render-pass re-bake feeds a stale desc to the new layout {#b6}
**High · M · CONFIRMED**
`src/DingoEngine/Graphics/NVRHI/NvrhiRenderPass.cpp:71-84`

The re-bake hands the *old* `m_BindingSetDesc` to `createBindingSet` against the *new* `m_BindingLayoutHandle`. NVRHI writes descriptors driven by the desc into a set allocated from the layout and never reports a mismatch — desc entries whose slot vanished are written to non-existent bindings; new layout items absent from the desc stay unwritten. Hot-reload a shader that adds a `sampler2D` and `Material`-cached passes are silently wrong (Renderer2D heals only because its owner re-populates the desc each flush).

Secondary defect in the same function: on a failed bake it still stamps `m_BuiltShaderGeneration` (`:82`) and sets `m_Valid = true` (`:83`) — the assert at `:80` is compiled out in Release — so the pass latches a null binding set and never retries.
**Fix:** give `RenderPass` an owner-repopulate hook (`Invalidate()`) for reloads, and leave `m_Valid = false` when the bake fails.

### B7 — `Font::GetStringWidth` is wrong {#b7}
**High · S · CONFIRMED**
`src/DingoEngine/Graphics/Font.cpp:168-210`

Three compounding bugs: it sums per-glyph **ink** widths (`:200`) instead of pen advances; `fontGeometry.getAdvance(x, ...)` (`:205`) is an **out-parameter** that *overwrites* `x` with one pair advance rather than accumulating it (compare the correct loop at `Renderer2D.cpp:544-546`, which does `x += fsScale * advance + kerning`); and `x` is added to both `quadMin` and `quadMax` so it cancels out anyway. Spaces have no plane bounds → they contribute **zero** width.

Consumed by `Scene.cpp:474` for `TextComponent::Centered` and by six examples — so every centered HUD string in the engine is offset, and the more spaces it contains the worse it gets.
**Fix:** mirror `Renderer2D::DrawText`'s advance loop and return `x * size`.

### B8 — Two fonts in one frame → wrong atlas {#b8}
**High · M · CONFIRMED by construction**
`src/DingoEngine/Graphics/Renderer2D.cpp:445` + `:872-876`

`DrawText` overwrites the single `m_FontAtlasTexture` per call, but `FlushText` binds and bakes the atlas only when `BatchIndex == 0`. Absent a mid-frame overflow, all text in the frame draws in one batch sampling the **last** font's atlas — every earlier font's glyph UVs index the wrong atlas and render as garbage. Latent only because no shipped example uses two fonts in one scene.
**Fix:** flush the text batch when the atlas handle changes, or key text batches by atlas.

### B9 — The new nullptr contract null-derefs FlappyBird {#b9}
**High · S · CONFIRMED**
`examples/FlappyBird/src/GameLayer.cpp:45`, `:52` (and `:182`)

`Texture::CreateFromFile` now returns `nullptr` on failure (`Texture.cpp:14-15`), but `m_GroundTexture->GetWidth()` and `m_BirdTexture->GetWidth()` are dereferenced with no check right after the four loads at `:37-40`. `Font::Create` at `:42` has the same exposure. Launching from the wrong cwd — a documented footgun in this repo — used to give blank quads; it now crashes in `OnAttach`. Worth grepping the other examples for the same pattern while fixing.
**Fix:** null-check and fall back to `Renderer::GetWhiteTexture()`, or bail with a clear error.

### B10 — Hot-reload never recovers a `Failed` asset {#b10}
**High · S · CONFIRMED**
`src/DingoEngine/Asset/AssetManager.cpp:521` vs `include/DingoEngine/Asset/AssetManager.h:72-74`

`PollHotReload` skips everything that is not `Ready`, so a first-load failure is never watched again. The header promises the opposite in as many words: "Load failures keep the asset registered with `State == Failed` … so a later Reload — **or hot-reload, once the file is fixed** — can recover without re-registering." Start with a syntax error in a shader, fix it on disk, and nothing happens until you hit "Retry failed" or restart.
**Fix:** poll `Ready || Failed` (a failed entry has an empty `LastWriteTime`, so the first poll fires immediately) and route failed textures through the queue, failed shaders through `LoadInternal`.

### B11 — `Scene::Clear` invalidates its own iterator {#b11}
**High · S · CONFIRMED**
`src/DingoEngine/Scene/Scene.cpp:220-221` and `:399-403`, with `:163-167`

`Clear` runs `for (auto& [handle, script] : m_Data->Scripts) script->OnDestroy();` with `m_Data->Updating == false`, so a `DestroyEntity` from inside `OnDestroy` takes the immediate path into `DestroyEntityNow`, which calls `OnDestroy` **a second time** and then erases from the map being iterated → `++it` on an erased node is UB. A script destroying its own entity in `OnDestroy` is the most natural thing to write. Same exposure via the public `ForEachScript`. `Scene::OnUpdate` already snapshots handles for exactly this reason (`:248-253`); `Clear` does not.
**Fix:** snapshot in both, and make `DestroyEntityNow` erase before calling `OnDestroy` (or guard with a per-script destroying flag).

### B12 — Worker-thread exception → `std::terminate` {#b12}
**Medium · S · CONFIRMED** — `src/DingoEngine/Asset/AssetManager.cpp:415-435`
`WorkerLoop`'s switch has no `try`/`catch` and calls into stb and miniaudio, whose `std::filesystem::exists` uses the throwing overload (`MiniAudioEngine.cpp:131`). `LoadAsync` a `.wav` with a path the OS rejects (bad character, >MAX_PATH) → `filesystem_error` escapes the thread function → hard process kill, no log line, no chance to mark the asset Failed.
**Fix:** wrap the switch body and route the failure back through `AsyncResult` like every other failure.

### B13 — Timestamp committed before the reload runs {#b13}
**Medium · S · CONFIRMED path, timing-dependent trigger** — `src/DingoEngine/Asset/AssetManager.cpp:531`
`metadata.LastWriteTime = writeTime;` is written unconditionally *before* the reload is attempted, and no failure path rolls it back. Windows mtime granularity is the ~15.6 ms clock tick, so an editor that truncates-then-writes inside one tick gives the partial and the final file the **same** mtime: the poll reads a 0-byte PNG, logs "keeping the loaded version", and every later poll sees no change — the edit is lost until the next save.
**Fix:** commit `LastWriteTime` only after a successful reload (in `FinalizeResult` for the async path), and/or require a stable mtime across two consecutive polls.

### B14 — Truncated shader cache passes validation {#b14}
**Medium · S · CONFIRMED** — `src/DingoEngine/Graphics/NVRHI/NvrhiShader.cpp:113`, `:258-263`
`ReadShaderCache` sizes the body from the file length, so a short file with an intact header validates cleanly — magic, format version and the *source* hash are all unaffected by truncation. The writer uses a bare `ofstream`, checks `is_open()` only via an assert compiled out in Release, never checks `good()`, and does not write-then-rename. Kill the process mid-write and the next launch feeds truncated SPIR-V to `vkCreateShaderModule` (UB).
**Fix:** put the payload byte count (ideally + a bytecode hash) in the header and require an exact match; write to `.tmp` and `std::filesystem::rename`.

### B15 — `Reinitialize` upload `ClearState()`s the D3D11 context mid-frame {#b15}
**Medium · S · CONFIRMED** — `src/DingoEngine/Graphics/NVRHI/NvrhiTexture.cpp:120-128`
`Upload` creates and immediately executes its own command list. On D3D11, NVRHI's `open()`/`close()` each call `immediateContext->ClearState()`, while the frame's command list still believes its graphics state is valid and so skips re-binding the render target that was just wiped. The async path is safe (the pump runs before any layer draws, `Application.cpp:207-208`), but the **Assets-panel Reload button runs at `:227-228`** — after every layer has recorded its draws.
**Fix:** route the reinit upload through `Renderer::GetCommandList()`, or defer it to the next frame boundary.

### B16 — Material PSO cache keyed on framebuffer pointer {#b16}
**Medium · S · CONFIRMED** — `src/DingoEngine/Graphics/Material.cpp:16-28`, `:179`
`MakeCacheKey` hashes `reinterpret_cast<uintptr_t>(framebuffer)`, and the material draw path passes `GetCurrentTarget()` — the rotating swap-chain framebuffer, whose objects are deleted and reallocated on every resize. Nothing is ever evicted, so dragging a window leaks ~3 pipelines + render passes per material per resize (hundreds of PSOs after a few seconds). Secondary hazard: address reuse yields a stale cache hit against a destroyed framebuffer, benign today only because all swap-chain framebuffers share a format.
**Fix:** fold in `SwapChain::GetResizeGeneration()`, or key on back-buffer index + generation.

### B17 — Post-execution callbacks can invalidate their iterator {#b17}
**Medium · S · PLAUSIBLE (no current nesting caller)** — `src/DingoEngine/Core/Application.cpp:236-240`
A callback that calls `SubmitPostExecution` push_backs into the vector being range-iterated; on reallocation the iterator dangles, and the following `clear()` drops the new entry regardless. `RequestRestart` is itself a `SubmitPostExecution` caller, so the pattern is one nesting away.
**Fix:** swap into a local vector and drain that.

## Optimizations

### O1 — Renderer3D: 2 throwaway command lists + queue submits per material per frame {#o1}
**High · M · CONFIRMED** — `src/DingoEngine/Graphics/NVRHI/NvrhiGraphicsBuffer.cpp:66-80`, called from `Renderer3D.cpp:199-200`
The `DirectUpload` branch does `createCommandList` → `open` → `writeBuffer` → `close` → `executeCommandList` on **every** call, and `EndScene` calls it twice (VB + IB) per non-empty material batch on buffers created with `directUpload = true`. That is 2N command-list allocations and 2N `vkQueueSubmit`s per frame for N materials — the same class of waste the v0.5 audit fixed in `ImGuiRenderer::UpdateGeometry`, simply not looked for here.
**Fix:** create the pooled batch buffers with `directUpload = false` and upload via `Renderer::Upload`, as `Renderer2D::FlushQuad` does. Safe: `EndScene` runs with the render thread parked, and pooled buffers are only rewritten a frame later.

### O2 — `dynamic_cast` in the per-quad texture-slot loop {#o2}
**High · S · CONFIRMED** — `src/DingoEngine/Graphics/Renderer2D.cpp:555` → `NvrhiTexture.h:23-32`
`NativeEquals` is a virtual call performing `dynamic_cast<const NvrhiTexture*>` — RTTI traversal, ~20-50 ns on MSVC — and `GetTextureIndex` runs it once per occupied slot for every textured quad. At 2000 sprites over 8 textures that is ~16k `dynamic_cast`s/frame, on the order of 0.5 ms.
**Fix:** short-circuit on pointer identity first (`m_TextureSlots[i] == texture || ...`), which eliminates nearly all of them since games reuse `Texture*` objects. `static_cast` is also defensible here — the type is engine-internal and known. Pairs naturally with the [B3](#b3) null guard.

### O3 — Sprite z-sort: per-frame alloc + 2 lookups per comparison {#o3}
**Medium · S · CONFIRMED (still open from v0.5)** — `src/DingoEngine/Scene/Scene.cpp:433-450`
`std::vector<entt::entity> sprites(view.begin(), view.end())` allocates every frame; the `stable_sort` comparator re-fetches `TransformComponent` through `Registry.get<>` for **both** operands on every comparison (~9,000 lookups at N=500); the draw loop then re-fetches both components again (`:442-443`) instead of using the `view.get` it already has.
**Fix:** a reusable member `vector<pair<float, entt::entity>>` filled from the view, sorted on the float; draw through `view.get`.

### O4 — `GetScriptsOfType<T>` allocates and `dynamic_cast`s everything {#o4}
**Medium · M · CONFIRMED** — `include/DingoEngine/Scene/Scene.h:123-133`
Each call builds a `std::function`, walks the whole `Scripts` map, `dynamic_cast`s every entry, and returns a fresh `std::vector`. Confirmed per-frame use from inside a script's `OnUpdate` (`examples/DungeonCrawler/src/GameScripts.cpp:102`), and two call sites allocate a vector just to read `.size()` (`GameLayer.cpp:220`, `:225`). The API shape invites accidental O(N²).
**Fix:** a per-type index maintained on attach/detach, or at minimum an overload taking a caller-owned `std::vector<T*>&`.

### O5 — Hot-reload polling cost {#o5}
**Medium · S · CONFIRMED** — `src/DingoEngine/Asset/AssetManager.cpp:519-527`
Each poll walks the entire registry and, per Ready texture/shader, rebuilds the absolute path via `ResolvePath` (1-2 allocations) and calls `last_write_time` (a `GetFileAttributesEx` syscall). A few hundred assets = a few hundred syscalls in one frame, a visible hitch every 30 frames — and `HotReloadInterval = 0.0f` is a legal value that makes it per-frame.
**Fix:** cache the resolved absolute path in `AssetMetadata` (it is recomputed in five other places too), and amortize the walk round-robin or hand the `stat` work to the existing worker thread.

### O6 — Jolt shapes never shared {#o6}
**Medium · M · CONFIRMED (still open from v0.5)** — `src/DingoEngine/Physics/3D/JoltPhysics/JoltPhysics3D.cpp:135-141`
One `new JPH::*Shape` per body; `JPH::ShapeRefC` exists precisely to share immutable shapes. Re-ranked **down** from the earlier audit's "load-time stall": shape construction is cheap, so the real cost is memory and cache pressure, biting at the thousands-of-static-colliders scale (a Gloomdelve-style baked dungeon).
**Fix:** a `unordered_map<shape-params-key, JPH::ShapeRefC>` inside `JoltPhysics3D`.

### O7 — Script bookkeeping: 2 heap allocs per frame {#o7}
**Medium · S · CONFIRMED (still open from v0.5)** — `src/DingoEngine/Scene/Scene.cpp:409-413`, `:250-260`
`StartScripts()` runs unconditionally from `OnUpdate` and calls `handles.reserve(Scripts.size())` — allocating and traversing the whole map every frame **even in steady state with nothing unstarted**. The `OnUpdate` snapshot allocates again. Re-ranked: the malloc/free churn matters more than the hash lookups.
**Fix:** a persistent member vector (`clear()` keeps capacity) + a `bool m_HasUnstartedScripts` gate.

### O8 — Sync audio `Load` blocks the main thread on the worker {#o8}
**Medium · S · CONFIRMED** — `src/DingoEngine/Asset/AssetManager.cpp:614` and `:428`
`m_AudioLoadMutex` is held across the whole `LoadClip` on both sides, and `MA_SOUND_FLAG_DECODE` decodes fully. `LoadAsync("music.ogg")` followed by `Load("click.wav")` stalls the main thread until the multi-MB Vorbis decode finishes. This is the only place in the design where the main thread can block on the worker, and it is invisible from the API.
**Fix:** miniaudio's resource manager is internally synchronized, so the mutex looks defensive rather than required — verify and drop it, or route sync clip loads through the same queue.

## Refactoring

### R1 — `AssetManager`: four parallel switches over `AssetType` {#r1}
`src/DingoEngine/Asset/AssetManager.cpp:212-259`, `:444-501`, `:549-631`, `:633-691`
`LoadInternal`, `UnloadInternal`, `ReloadInPlace` and `FinalizeResult` each switch over the same six types, and the drift is already visible: the RGBA `TextureParams` builder is written out three times (`:232`, `:457`, and again inside `Texture::CreateFromFile`), where the first two hard-code `TextureFormat::RGBA` and the third derives it from `channels` — they agree only because `ReadImage` forces `channels = 4`. `UnloadInternal`'s five cases are the same find/`Destroy`/`delete`/`erase` body five times; `LoadInternal`'s five cases repeat the same success tail.
**Suggested:** one `MakeTextureParams(...)` helper, a `template<typename T> void DestroyFrom(map&, handle)`, and a per-type policy table (`load`, `reloadInPlace`, `unload`, `isAsyncDecodable`) replacing all four switches. This also makes [B2](#b2) structurally impossible — `SupportsInPlaceReload` becomes a field.

### R2 — `Renderer2D`: ~250 lines of triplicated batch plumbing {#r2}
`src/DingoEngine/Graphics/Renderer2D.cpp:601-915` (+ the three resets in `BeginScene`, `:297-307`)
The quad, circle and text quadruples (`Create*Pipeline` / `Create*VertexBuffer` / `Flush*` / `Destroy*Pipeline`) are the same algorithm with a different vertex type. They have **already drifted**: the quad pass re-bakes per batch, the circle pass bakes once at creation, the text pass bakes only on batch 0 — and that last divergence *is* bug [B8](#b8).
**Suggested:** `template<typename TVertex> struct BatchPass` with `Reset()/Flush()/Destroy()`; removes ~200 lines and makes further drift impossible.

### R3 — `Scene` is a god-object {#r3}
`src/DingoEngine/Scene/Scene.cpp` (1093 lines)
One class owns entity lifecycle + duplication, script scheduling, the 2D world, the 3D world, character-controller storage, audio source/listener sync, camera selection and view-projection math, and screen-to-ray picking. `OnUpdate` alone (`:240-390`) is 150 lines running five unrelated systems inline. Three separate `// MAINTENANCE:` comments exist (`:90`, `:123`, `Components.h:176`) because adding a component means editing three hand-maintained lists in this file.
**Suggested:** extract `ScriptSystem`, `PhysicsSync` (2D+3D+controllers), `AudioSync`, `CameraUtils`, leaving `Scene` as registry ownership + entity lifecycle. This is also the precondition for fixing [O3](#o3)/[O7](#o7) cleanly.

### R4 — Delete `DeviceManager.{h,cpp}` {#r4}
**CONFIRMED dead: 1806 lines, still compiled**
`DeviceManager.cpp` is `#include "depch.h"` at line 51, `#if 0` at line 52, matching `#endif` at line **1322** (last line). `DeviceManager.h` is `#if 0` at line 3 → `#endif` at line **484**. Its only includer is inside its own dead region. It is an unported Hazel copy — 25 references to `Hazel::`/`HZ_CORE_*`, plus placeholder `#if OLD` / `#if TODO` guards — which could not compile in this project even if enabled. The live Vulkan device/adapter selection lives in `VulkanGraphicsContext.cpp`.

### R6 — `AssetManager` public header leaks its implementation {#r6}
`include/DingoEngine/Asset/AssetManager.h:5-15`, `:184-243`

## Low severity {#low-severity}

**Asset pipeline**
- `AssetManager.cpp:281-309` — `Get*` never checks `State`, contradicting `AssetManager.h:124` ("nullptr unless Ready"). Worse, `PollHotReload:536` flips a Ready texture back to `Loading`, so a game that gates drawing on `IsReady()` (as the header advises) drops that sprite for several frames every time an artist saves — the opposite of the "pointers stay valid" promise. Add a distinct `Reloading` state, or fix the docs.
- `AssetManager.cpp:693-696` — `NormalizePathKey` does no case folding, but NTFS is case-insensitive: `Textures/Player.png` and `textures/player.png` produce two handles, two GPU textures and two hot-reload watches for one file, and `FindByPath` misses. Same for relative-vs-absolute spellings of the same file.
- `AssetManager.cpp:135-142` — handle inserted with no collision check; `m_Registry[handle] = ...` would silently overwrite. Probability is negligible (2^-64) but the guard is one line and the failure is silent corruption.
- `AssetManager.cpp:205-209` + `:449` — `Reload` during an in-flight async load runs `Unload` + sync `LoadInternal`; the completed background decode is then discarded because `stillWanted` requires `State == Loading`. Make it a no-op or re-queue instead.

- `docs/asset-pipeline.md:54` — comments `Load()` as "ready when the call returns", but `Load` on a path already `Queued`/`Loading` returns without loading. The header comment gets this right; the doc drops the caveat.

**Graphics**
- `Renderer.cpp:277`, `:294` — the `indexCount == 0` fallback computes `GetByteSize() / sizeof(uint16_t)`, but every index buffer in the engine is `uint32` → **double** the real count and out-of-range fetches. Harmless today (all four in-tree callers pass an explicit count) but the default argument advertises it. Derive the stride from the buffer format or drop the default.

- `Renderer2D.cpp:205-217` — `CreateTransform` builds a full 4×4 and does four `mat4 * vec4` for every axis-aligned quad (~128 multiplies where 12 would do); ~250k needless multiplies at 2000 quads/frame, and `glm::scale` inlines poorly in Debug. Fast-path `rotation == 0`.

## Confirmed healthy

Checked and found sound — recorded so a future reader knows these were not skipped.

**Asset pipeline (the design's strong points)**
- **Worker/main-thread partition.** `QueueDecodeJob` deep-copies handle, type, path and name into `AsyncJob`; the worker touches only `m_Jobs`, `m_StopWorker`, `m_Results`, `m_AudioLoadMutex` and its own copy. It never reads the registry, the asset maps, or any managed object pointer — so main-thread `Unload`/`Remove`/rehash cannot invalidate anything it holds.
- **Shutdown lifetime.** Stop flag → clear queue → notify → **join**, all before touching `m_Results` or any map, so post-join unlocked access is safe and a mid-decode job is drained with its `Pixels` freed. `~AssetManager` calls `Shutdown`, and the double-`Shutdown` from `Application::Destroy` is a harmless no-op. `Application.cpp:104-119` orders teardown correctly: render thread joined → layers detached → assets freed → audio engine shut down, so `AudioClip`s never outlive `ma_engine` and GPU objects are freed with the GPU idle.
- **`m_PendingCount` balance.** Every increment has exactly one matching decrement across all six interleavings, including the discard paths — no underflow, no permanent leak.
- **Pump placement.** `Renderer::BeginFrame` waits on `FrameConsumed`, which the render thread sets only after `Execute` + `Present` + `RunGarbageCollection` + `AcquireNextImage`. The render thread really is parked when `AssetManager::Update` runs, so the uploads and recompiles in the pump cannot race NVRHI's GC.
- **No reference invalidation across mutation.** `Load`/`LoadAsync`/`Reload` hold an `AssetMetadata&` across calls that never insert into `m_Registry` — no rehash, no dangling reference. `Remove`'s `m_PathLookup.erase` key round-trips exactly to what `Import` stored.
- **stb global state.** `FileSystem::ReadImage`'s new `static std::mutex` correctly serializes `stbi_set_flip_vertically_on_load` + `stbi_load` across the worker and the main thread. Logging from the worker is safe (both sinks are `_mt`).
- **The debug panel does not invalidate iterators** — it snapshots, then applies actions past `EndTable` against the copy.
- **No backend types in any of the three new public headers.**

**Hot-reload / graphics**
- **NVRHI deferred release across a reload.** Old shaders, PSOs, binding sets and textures stay alive while frames are in flight — NVRHI pushes every bound resource onto `referencedResources` and frees them in `runGarbageCollection` after `Present`. No device wait is needed and none is missing.
- **The generation check is cheap and monotonic.** `GetParams()` returns a const ref, so the per-draw cost is one `uint32_t` compare. Counters are captured at build time, so a pipeline created *after* a reload is correctly current; the counter bumps only on success, so a failed reload cannot spin a rebuild loop.
- **No bind path bypasses the check** — all `Renderer::Draw*` overloads funnel through `SetPipeline`/`SetRenderPass`. `ImGuiRenderer` keeps its own PSO cache but its shaders come from `CreateFromSource`, which `Reload()` rejects.
- **PSO pointer-reuse (ABA) after a mid-frame rebuild is unreachable** — NVRHI's `open()` clears the cached graphics state, and a PSO bound earlier in the list is pinned by `referencedResources`.
- **`Shader::Build()` is genuinely all-or-nothing** — handles and cache writes accumulate in locals committed only after every stage succeeds, so every early return leaves the previous program and cache files untouched. The downgraded missing/empty-file asserts are what make reloading during an editor's save-truncate window safe.
- **Cache header validation** (apart from length, [B14](#b14)): missing file, size error, sub-header size, bad magic, wrong format version, hash mismatch and failed body read all fall through to recompile; pre-v0.6 headerless files fail the magic check as intended; the struct is 16 bytes with no padding.
- **In-place texture reload does re-bake for `Renderer2D`** — `Reinitialize` swaps the native handle and `SetTexture`'s handle comparison forces a re-bake.
- **Other `CreateFromFile` callers are guarded** — `AssetManager::LoadInternal` and `Model::LoadDiffuseTexture` both check; `Renderer2D` degrades a null texture to white *at flush time* (see [B3](#b3) for the earlier path that does not).

**Example / conventions**
- **ASCII compliance** — byte-level scan of `GameLayer.cpp` found zero non-ASCII bytes; every on-screen string is clean. (Em-dashes appear only in `.md` files and C++ comments, both exempt.)
- **Input semantics are correct** — `Pressed` (edge) for one-shot start/retry, `Down` (held) for movement, `Down` + cooldown for auto-fire. No v0.5.1 inversion.
- **Backend hiding** — `DebugPanels.h` contains no ImGui type or include.
- **Comment hygiene** — no changelog-style or narrate-the-next-line comments in any reviewed file; the ones present state real constraints (std140 layout, registry-snapshot-for-stable-rows).
- **Asset ownership** — no client code deletes a managed asset; `OnDetach` tears down only its own raw resources. Audio clips are correctly re-fetched per use rather than cached (the same hazard as [B2](#b2), handled right).
- **`GetPendingCount() == 0` is a reliable gate** — `FinalizeResult`/`LoadInternal` publish the object and flip `State` together, with no torn window.
- **Build/CI additions** are clean and additive: the launch config sets `cwd` correctly, and artifact names match between the build and packaging jobs.
- **README/shader agreement** — the tweakable constants the README cites match `background.glsl` byte-for-byte; `BackgroundUniform` matches the shader's std140 block exactly.
