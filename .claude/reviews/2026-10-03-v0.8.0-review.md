## Medium

### B1 — A one-shot that returns before it ever led fires the interrupted clip's marks twice {#b1}

`Animator.cpp:375-379` (`Resume` is a copy, same `Serial`), `:644-652` (the second `CollectEvents`). CONFIRMED.

**The case:** the way back starts while the one-shot is still under weight 0.5. With the default fades (0.1 in, 0.2 out), that is any one-shot shorter than about 0.25 s.

**What happens:** the first `CollectEvents` is led by the original interrupted state and fires its marks in `(prev, t]`. Then `Resume` is pushed with `Returning` and leads the second pass. It has the same `Serial` and clip as `EventSerial`/`EventClip`, so nothing closes, and it fires the same `(prev, t]` again.

**Example:** Walk at 0.28 s with `step_fl` at 0.287, and `PlayOneShot(flinch 0.2 s, 0.1, 0.2)`. The first `Update(1/60)` fires `step_fl` twice. A related case: `Led` is copied when `PlayOneShot` is called, so a non-looping interrupted state that had not led yet catches up from its start a second time on the way back.

**Fix:** before the second `CollectEvents`, when `layer.EventSerial == resume.Serial`, set `resume.PreviousTime = resume.Time` and clear `Wrapped`. When a dominant state gets `Led`, also set `layer.Resume.Led` if `Resume` carries the same serial.

### B2 — A non-looping state seeked before it first leads catches up from the clip's start {#b2}

`Animator.cpp:756-760` (catch-up), `:495-502` (`MarkSeek`), `:287-292` (`MakeState`). CONFIRMED.

**Seek case:** the catch-up is `from = forward ? 0 : duration`, inclusive, whatever the state's real start. So `Play(Clip(slash).SetLoop(false)); SetTime(0.4f); Update(dt)` fires `whoosh@0.12` and opens `hitbox@0.32..0.48`. That breaks the documented "a seek counts the new time as a start; seeking into the middle of a range opens nothing".

**Negative step case:** a forward non-looping state given a negative step (a negative `AnimatorComponent::Speed`) stays at 0 with `Direction = −1`. Its first lead then fires every mark of the clip at once.

**Fix:** a `CatchUpFrom` on `PlayingState`, set to the initial time in `MakeState` and to the new time in `MarkSeek`. The catch-up then runs from there.

### B3 — `Stop` is swallowed while a one-shot that interrupted nothing is pending {#b3}

`Animator.cpp:338-340`, `Animator.h:136`. CONFIRMED.

**Cause:** on an empty layer, `Resume` is the transparent state, and `Stop` is `Play(Clip(nullptr))`. So `OneShotPending && Resume.State == state` makes `Stop` a no-op.

**Example:** `PlayOneShot(emote, 0.1, 0.2, 1)` on an empty upper layer, then `Stop(0.1, 1)` on death. The emote plays to its end, and nothing can cut it short except `SetTime` or another `Play`.

**Fix:** let `Stop` always cancel a pending one-shot (or add `CancelOneShot`), and document it under One-shots.

### B4 — The F7 tab reads the clips of an animator whose model is gone {#b4}

`AnimationDebug.cpp:115-141` (`CollectAnimators`), `ImGuiDebugPanels.cpp:692,712,721`, `Animator.cpp:536-537`, `AnimationSystem.cpp:220-222`. CONFIRMED.

**Cause:** `CollectAnimators` lists every `AnimatorRuntime` in every registered scene without checking that it is still bound to the entity's current model, which `BoundAnimator` checks for rendering. `AnimationSystem::Update` skips an entity whose model is null or has no skeleton before `EnsureAnimator`, so its animator keeps the old clip pointers.

**Example:** a script sets `skinned.Model = nullptr` (or removes the component) and the game frees that model. F7 then reads the freed clips every frame through `GetStates` and the state labels. Game code can't reach this, because `Scene::GetAnimator` always rebinds first.

**Fix:** show only runtimes whose `SkeletonId` matches the current model, and list the rest as unbound without touching the animator.

### B5 — A body on a socket is built at the rest pose, not at `DefaultClip`'s first frame {#b5}

`Scene.cpp:479-480` (`OnStart`: scripts, then the physics bake), `PhysicsSync.cpp:640-643`, `HierarchySystem.cpp:517-524`, `AnimationSystem.cpp:271-284` (`JointFrame` reads `BoundAnimator`, which never creates the animator). CONFIRMED.

**Cause:** the animator is made by `GetAnimator` or the first `Scene::OnUpdate`. Bodies are built before either runs, at `OnStart`, `CreateRigidBody` and `DuplicateEntity` while running. So `JointFrame` falls back to the rest pose. The docs and `AnimationSystem.cpp:166-168` say a body baked on a joint sees `DefaultClip`'s first frame. The Animation Test hides this: `BuildScene` calls `GetAnimator` before `OnStart`.

**Example:** a kinematic hitbox on a T-posed character's hand sweeps from the rest pose to the clip's hand in its first step (about 0.5 m in 1/60 s), launching anything dynamic it crosses. A static body on a socket stays at the rest-pose joint.

**Fix:** create the animator for every `AnimatorComponent` with a skinned model before baking: at the top of `OnPhysicsStart`, and for the socket parent in `CreateRigidBody` and `DuplicateSubtree`.

### B6 — A custom skinned material reaches the static batch path {#b6}

`Scene.cpp:399`, `Renderer3D.cpp:808-` (`SubmitMesh`, no guard), `:339`; compare `SubmitSkinnedMesh`'s guard at `:368-371`. Path CONFIRMED, outcome PLAUSIBLE.

**Cause:** `RenderEntities3D` sends every submesh without a skin through `SubmitMesh` with the component's `Material`. That covers a prop outside the armature, every submesh of a static model, and a model a reload turned static. A material whose shader is a custom `DE_SKINNED` one then builds a pipeline from the static vertex layout. It also gets a binding set without `SkinData`.

**Per backend:**
- D3D12 fails PSO creation (an assert in Debug).
- D3D11 drops the draw.
- Vulkan runs a mismatched pipeline with a dynamic UBO it never writes: undefined behaviour, possibly device loss.

`SubmitSkinnedMesh`'s own fallback already swaps such a material for the default one.

**Fix:** move that guard into `SubmitMesh`. If the material's shader has a `SkinData` block, warn once and draw with the default material.

### D1 — One-shot marks in the last `fadeOut` seconds never fire {#d1}

`docs/animation.md:651-652` ("a mark at a one-shot's very end fires too"), `Animator.cpp:637-651`. CONFIRMED.

**What happens:** the way back takes the events over `fadeOut` seconds before the end. So with the default 0.2, a `done` or `recover` mark in the last 0.2 s is lost. A one-shot shorter than `fadeOut + fadeIn/2` never leads, so none of its marks fire. The tests only cover `fadeOut = 0`.

**Fix:** document it under One-shots: author end marks before `duration − fadeOut`, or pass a `fadeOut` of 0. Alternatively, let the one-shot keep firing until the way back passes 0.5.

## Low

### B7 — A `Play` during a one-shot's fade-back hands the events back to it {#b7}
`Animator.cpp:671-697`. CONFIRMED.

**Cause:** `Returning` only wins while it is on top.

**Example:** the stack is `[one-shot (1.0), way back (0.2)]` and `Play(run, 0.3)` is called. The one-shot's share becomes 0.8 and it leads again, so its tail marks fire after it had handed over.

**Fix:** flag the one-shot when its way back is pushed, and give it share 0 in `Dominant` while still folding its weight.

### B8 — A range kept across an events change stays open if its new end is behind the playhead {#b8}
`Animator.cpp:737-749`. CONFIRMED (hot-reload only).

**Cause:** the reconcile keeps a range whose index and name still match but never checks its new times.

**Example:** a reload moves `hitbox` from 0.32..0.48 to 0.32..0.40 at time 0.45. The range never closes, and on a finished, held one-shot it stays open for good.

**Fix:** keep the range only if the time is still inside its new span.

### B9 — A huge layer index wraps or allocates without bound {#b9}
`Animator.cpp:197-211`. CONFIRMED.

**What happens:** `resize(index + 1)` with `UINT32_MAX` (a `-1` passed in) resizes to 0, which deletes layer 0, then indexes past the end. An index of 1e9 allocates a billion layers.

**Fix:** cap layers at a small maximum and warn past it.

### B10 — A hand-built clip with mismatched track sizes reads out of bounds {#b10}
`AnimationClip.cpp:43-46`, `Animator.cpp:41-46`. CONFIRMED.

**What happens:** "one value per time" is an unchecked precondition of the public constructor.

**Fix:** validate or truncate the tracks there.

### B11 — Removing an `AnimatorComponent` drops its open ranges without a `RangeEnd` {#b11}
`AnimationSystem.cpp:110-113` (`DropRuntime`). CONFIRMED.

**What happens:** this is a second hole beside K22. On death, a game swapping to a ragdoll by removing the component leaves a hitbox flag that was set on `RangeBegin` on.

**Fix:** queue `RangeEnd`s into the scene's event scratch from the hook, or extend K22 to cover it.

### B12 — An unknown socket joint is silent without a skinned model, and for a 2D child {#b12}
`Entity.cpp:169-175`, `Entity.h:85-90`. CONFIRMED.

**What happens:** the warning needs the parent's model to have a skeleton already. A typo made before the model is assigned leaves the child at the origin without a word. A 2D child's socket is stored and reported, but ignored.

**Fix:** warn in both cases.

### B13 — Deleting a `.events` file is acted on without waiting for it to settle {#b13}
`AssetManager.cpp:127-144,465-474`. Path CONFIRMED, real-world gap PLAUSIBLE.

**Cause:** "missing" reads as the epoch, and the epoch is also the "nothing pending" sentinel.

**What happens:** a delete-and-rename save is caught in its gap. `ReloadEvents` then clears every clip's events until the file returns a poll or two later.

**Fix:** track pending with a separate flag.

### B14 — The scene registry is an unsynchronised global {#b14}
`AnimationDebug.cpp:89-113`, `Scene.cpp:28-29,34`, `AnimationSystem.cpp:175`. PLAUSIBLE.

**What changed:** a `Scene` constructor now has a process-wide side effect.

**What can go wrong:** building or destroying a scene on a loading thread races with the F7 tab.

**Fix:** add a mutex, or document that scenes live on the main thread.

### B15 — Rigid-mesh nodes interleave with bones, so a scene-rooted rig can pass 128 joints {#b15}
`Model.cpp:753-786`, `docs/animation.md:851-852`. PLAUSIBLE (needs such a file).

**Cause:** one animated node outside the armature makes the scene root the skeleton root. Every static-mesh node then becomes a rigid-skinned joint, sorted among the bones.

**What happens:** bone indices can pass 127. The character falls back to its rest pose with fewer than 128 bones, and every prop becomes its own skinned draw.

**Fix:** order bones and their ancestors first, then rigid nodes.

### O1 — Masked layers sample their whole clip; `FireMarks` scans every mark {#o1}
`Animator.cpp:896-904,943-947,970-990`. PLAUSIBLE (not measured).

**Cost:** an upper-body Survey layer samples all 24 channels for about 14 masked joints, roughly 0.3 µs per layered animator a frame. `FireMarks` scans every mark linearly, which only matters at hundreds of marks.

**Fix:** skip channels outside the mask, and binary-search the marks.

### O2 — One socket puts every linked entity on the socket path {#o2}
`HierarchySystem.cpp:517-524,566-567,586-587`. PLAUSIBLE (not measured).

**Cost:** once any socket exists, every chain composition does a `contains` lookup in the socket pool. In the 10k parented stress scene that is about 10k lookups per pass.

**Fix:** keep a socketed bit in `HierarchyComponent`.

### O3 — The F7 tab's cost grows with the number of animators while open {#o3}
`AnimationDebug.cpp:115-141`, `ImGuiDebugPanels.cpp:650-735`. CONFIRMED.

**Cost:** every frame, every row copies names, converts the model path and formats a label, scrolled-out rows included.

**Also:** open tree nodes are keyed by row index, so they jump when the crowd changes.

**Fix:** use a list clipper and key the IDs on the entity.

### O4 — `LoadEvents` rebuilds and re-sorts every mark per line {#o4}
`Model.cpp:1221-1224` → `AnimationClip.cpp:51,59,88-117`. CONFIRMED.

**Cost:** a sidecar of n lines costs O(n² log n). This is at load and reload only.

**Fix:** add events in a batch and rebuild once.

### D2 — Lap and seek wording {#d2}
`docs/animation.md:650-651,654`, `Animator.h:187-188`. CONFIRMED.

**Laps:** a step fires `(from, end] ∪ [0, to]`, so a step of up to two clip lengths can fire a mark twice. "No more than one lap's worth" is wrong.

**Seeks:** a seek ends the layer's open ranges only when the seeked state is the one leading.

### D3 — `SkinnedJoints` on D3D11, and F4's per-scene count against a per-frame budget {#d3}
`Renderer3D.cpp:539`, `ImGuiDebugPanels.cpp:235-239`. CONFIRMED.

**What's wrong:** D3D11 uploads the whole 128-joint block per instance, but `SkinnedJoints` counts only the joints used. The F4 bar draws a per-scene instance count against a per-frame budget.

### T1 — "A Play during a one-shot cancels its return" cannot fail {#t1}
`AnimationTest.cpp:676-680`. CONFIRMED.

**Why it can't fail:** `Update` drops the return by itself once the one-shot isn't on top.

**Fix:** assert `!IsOneShotPlaying()` right after the `Play`, and play two states in one frame.

### T2 — The gait sweep crosses the blend's clip switch once {#t2}
`AnimationTest.cpp:809-834`. CONFIRMED.

**Why it's weak:** a double fire at the switch only shows if a footfall lands in that one frame, about a 4% chance.

**Fix:** oscillate `Speed` around 2.75.

### T3 — The ancestor filter's cleanup paths are untested {#t3}
`HierarchyTest.cpp` (`RunCollisionFilterChecks`). CONFIRMED.

**Not covered:** destroying a kinematic child or its ancestor while a pair is applied, `DestroyBody`'s partner cleanup, and `OnStop`/`OnStart` restoring the pairs.

### T4 — The reload name check can pass for the wrong reason in Release {#t4}
`AnimationTest.cpp:1005,1018`. CONFIRMED.

**Why it can pass:** without interning, the view would read freed short-string storage. A Release run may still find the old bytes there.

**Fix:** also compare the pointer with the interned one.
