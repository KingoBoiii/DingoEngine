## High

### D1 — `save["new"] = save["existing"]` reads a freed or shifted child {#d1}

`src/DingoEngine/Core/SaveData.cpp:355-370` (non-const `operator[]` inserts into `m_Items`, a `std::vector<SaveData>`); `include/DingoEngine/Core/SaveData.h:194` (children stored by value); the implicit copy assignment. CONFIRMED (ASan repro).

**What happens:** C++17 sequences the right operand of `=` before the left one, and that also applies to overloaded operators. In `save["copy"] = save["original"];`:
1. `save["original"]` runs first and yields a reference into `m_Items`.
2. `save["copy"]` then inserts a new member. The vector either reallocates, which frees the referenced element, or shifts it one slot, because "copy" sorts before "original".
3. The copy assignment then reads a dangling or wrong element.

Probe results:
- With ASan: `heap-use-after-free ... in SaveData::operator=(SaveData const&)`, freed by `vector::_M_realloc_insert` from `SaveData::operator[]` (`SaveData.cpp:369`).
- Without ASan: the "copy" member comes out as Null (type 0) and its string is gone.
- `save["a"] = save["c"]` with "b" and "c" present is also UB; it happened to read correctly that run.

The header does say a reference "is invalidated by adding or removing a member". But nothing in a single expression like `save["previous"] = save["current"]` or `settings.Game["last"] = settings.Game["profile"]` looks like holding a reference, and those are ordinary save-game moves. The result is a crash or a silently lost subtree that then gets written to disk.

**Fix:** keep children at stable addresses so an insert never moves a value: `std::vector<std::unique_ptr<SaveData>> m_Items` (deep-copying in the copy constructor and copy assignment), or a node-based container. Then only `Remove` of that very member invalidates a reference; update the header comment to match. A stopgap that doesn't touch storage cannot work, because the dangling happens before `operator=` is entered.

**Test:** in `test/UnitTests/src/SaveDataTests.cpp`, case "objects keep their keys sorted and unique": `SaveData s; s["original"] = std::string(64, 'x'); s["copy"] = s["original"]; CHECK(s["copy"].AsString() == std::string(64, 'x'));`, and the same with a three-member object where the new key sorts first. Run it under Debug-ASan.

### B1 — A Static entity given a new Mesh or Material at a freed one's address keeps its old bake {#b1}

CONFIRMED (code path traced end to end; the trigger needs the allocator to hand the new object the freed address, which glibc's tcache and MSVC's LFH do for a same-size delete-then-new).

**Where:**
- `src/DingoEngine/Scene/Systems/StaticGeometry.cpp:86-89`: the draw-state compare is `baked.Mesh == mesh.Mesh` and `baked.Material == mesh.Material`, pointer equality.
- `src/DingoEngine/Graphics/Renderer3D.cpp:2763-2773`: the batch's own id walk (`entry.Desc.Mesh->GetId() != entry.MeshId`) runs only when `Mesh::GetReinitializeCount()` moved, and only `Mesh::Reinitialize` bumps that count (`src/DingoEngine/Graphics/Mesh.cpp:46`). Creating or deleting a `Mesh` doesn't.
- The baked state that depends on the material: `BakesLoose` (`Renderer3D.cpp:2713-2720`, translucent / skinned-only / Instancing) and the surface records (`Renderer3D.cpp:2885`, `2923`, lit only). A range that `EnqueueBatch` then marks translucent is skipped at `Renderer3D.cpp:2980`.

**What happens:**
- **Mesh.** A game regenerates a `Static` mesh (terrain chunk, fence, a placed building swapped on upgrade through the AssetManager) as `delete mrc.Mesh; mrc.Mesh = Mesh::Create(newVertices, newIndices);`. The new `Mesh` usually lands at the freed address. Next frame, `Track` sees the same pointer, transform, colour and so on, so it doesn't call `Update`. `Submit` sees `Tracked == GetMeshCount()`. `PrepareStaticBatch` skips the id walk because no `Reinitialize` happened. No cell is dirty, so the cell keeps drawing and casting the **old** geometry, and the cascade caster box is the old one too. This lasts until something else rebakes that cell or any model anywhere is hot-reloaded. The same entity without `Static` draws the new mesh. This breaks the docs' promise that "changing its mesh … rebakes it quietly" (`Components.h:518-523`, `docs/scenes-and-ecs.md:304`, `docs/performance.md:152`) and CLAUDE.md's "ids, never addresses" invariant.
- **Material.** Same pattern. For example, a wall's material is replaced by a translucent "ghost" material through `delete m; m = renderer.CreateLitMaterial(MaterialParams().SetTranslucent(true)); mrc.Material = m;`. Nothing rebakes, so the range stays in the cell. `EnqueueBatch` now marks the key `Translucent`, and `LayoutStaticBatches` skips it at `:2980`. The wall **disappears** (no lit draw, no translucent draw, no shadow), where `SubmitMesh` would have drawn it translucent. A swap from a custom-shader material to a lit one at the same address loses the entity's `Surface`, because no record was baked (index 0).

**Fix:** compare ids, not addresses, in `Track`. Store the ids the entry was last added or updated with in `Bake::Entry` (`uint64_t MeshId, MaterialId`, taking `GetId()` of the non-null pointer and 0 for null). Treat a difference as a change (quiet `Update`, no move warning). Keep the pointer compare as well, so a null↔non-null change is still seen. This costs two loads per static entity per frame and needs no deref beyond what `SubmitMesh` already does for the same entity.

**Test:** in `test/src/Tests/Scene/ThroughputTest.cpp` `RunStaticChecks`, beside the duck reload check:
1. Make a `Static` entity with `Mesh* a = Mesh::CreateBox()` in front of the camera and render.
2. `delete a; Mesh* b = Mesh::CreateSphere(...)`. With glibc and one thread, the same-size LIFO tcache makes `b == a` deterministic. If the addresses differ, log INFO and skip.
3. Assign `b`, render, and require `StaticCellsBaked >= 1` and 0 px against the same frame with `Static` cleared.

Today it bakes 0 cells and draws the box. A material variant: swap in a translucent material at the same address and require `TranslucentMeshes == 1`.

### D2 — `uint64_t` values at or above 2^63 (half of all UUIDs) don't survive a save {#d2}

`include/DingoEngine/Core/SaveData.h:45-46` (the integral constructor does `static_cast<int64_t>`); `SaveData.h:211-218` (`Get<integral>` returns the fallback when `!std::in_range<T>(number)`); `SaveData.cpp:94-98` (JSON unsigned above `INT64_MAX` becomes a double, losing precision). CONFIRMED (repro).

**What happens:**
1. `save["id"] = static_cast<uint64_t>(entity.GetUUID());` with an id of 2^63 or more stores a negative `int64_t`, and the JSON writes it negative (probe: `{"id":-1152921504606846975}`).
2. Reading it back with `save.Get<uint64_t>("id", 0)` returns 0, because -1152921504606846975 is not in `uint64_t`'s range.

`UUID::Generate` draws from `[1, UINT64_MAX]`, so about half of all entity and asset ids are lost silently. `UUID.h:22` even advertises `UUID(uint64_t)` for "one read back from a save". A hand-written or foreign JSON with a large unsigned number is also turned into a double and rounded.

**Fix:** pick one:
- In `Get<T>` for unsigned 64-bit `T`, return `static_cast<T>(value->AsInt())` for an Int (the bit pattern round-trips), and document that `uint64_t` is stored as its two's-complement `int64_t`.
- Add a `UUID` constructor and a `Get<UUID>` overload that does the same.

**Test:** in `SaveDataTests.cpp`, case "Get reads members as the asked type": `const uint64_t id = 0xF000000000000001ull; s["id"] = id; auto r = SaveData::FromJson(s.ToJson()); CHECK(r->Get<uint64_t>("id", 0) == id);`, and the same for `UUID::Generate()` values in a loop of 64.

### R1 — `Renderer::Upload(buffer, data, size, offset)` ignores `offset` on a volatile buffer on Vulkan and D3D12 {#r1}

`include/DingoEngine/Graphics/Renderer.h:103-106` (the new public overload, documented as "Writes `size` bytes ... starting `offset` bytes in"); `src/DingoEngine/Graphics/Renderer.cpp:468-474`; `src/DingoEngine/Graphics/NVRHI/NvrhiGraphicsBuffer.cpp:119-131` (passes the offset straight to `writeBuffer`); `vendor/nvrhi/src/vulkan/vulkan-buffer.cpp:447-454`; `vendor/nvrhi/src/d3d12/d3d12-buffer.cpp:498-525`. CONFIRMED.

**What happens:** user code calls `Renderer::Upload(ubo, &value, 16, 64)` on a buffer from `GraphicsBuffer::CreateUniformBuffer`, or any buffer with `SetIsVolatile(true)`. It wants to update one field of a uniform block. The three backends then differ:
- **Vulkan, Debug:** NVRHI hits `assert(destOffsetBytes == 0)` and aborts.
- **Vulkan, Release:** `writeVolatileBuffer` copies the 16 bytes to the start of a fresh version and ignores the offset. The shader reads the new bytes at offset 0 and stale bytes everywhere else.
- **D3D12:** `writeBuffer` sub-allocates `dataSize` bytes, copies the data to its start and points the root CBV at it. The offset is dropped, and the rest of the block reads whatever follows in the upload page.
- **D3D11:** honours the offset (`UpdateSubresource` with a box).

So the same call gives three different pictures, and the header promises the D3D11 behaviour. Every engine caller passes an offset only for non-volatile buffers: the arena, which is the reason the overload was added in P2, and the object records (`Renderer3D.cpp:1379`, `1383`, `1451`, `1453`). So the engine itself is unaffected. The overload is public, though, and `docs/compute.md:40` shows it on a volatile uniform buffer (at offset 0).

**Fix:**
- Add `DE_CORE_ASSERT(!desc.isVolatile || offset == 0, "...")` in `NvrhiGraphicsBuffer::Write` (or in `Renderer::Upload`), with a `DE_CORE_WARN` once for Release builds.
- Add to the `Renderer.h` doc: "a volatile (uniform) buffer is written whole from offset 0; `offset` must be 0 for it".

**Test:** `test/src/Tests/Renderer/Renderer3DBatchTest.cpp`. Draw a custom material whose uniform block has two vec4 colours. Write the first colour with `Renderer::Upload(ubo, &a, 16, 0)` and the second with `Renderer::Upload(ubo, &b, 16, 16)`, then read back a pixel coloured by the second field. That fails today on Vulkan. Or, once the assert is in, check that the offset call is rejected.

### K1 — Every skinned instance still ends and restarts the Vulkan render pass, and the `DE_SkinDraw` contract freezes that for 1.x {#k1}

CONFIRMED (the mechanism; its cost on a GPU is unmeasured).

**Where:**
- `src/DingoEngine/Graphics/Renderer3D.cpp:2113-2117` (`UploadSkinDraw`), `:2119-2131` (`BindSkinInstance`, opaque and translucent passes), `:3474-3482` (shadow pass);
- `vendor/nvrhi/src/vulkan/vulkan-buffer.cpp:444` (`writeBuffer` calls `endRenderPass()` before it checks `isVolatile` at :448);
- `vendor/nvrhi/src/vulkan/vulkan-graphics.cpp:606-614`, `:645-668` (the next `setGraphicsState` sees `framebuffer == nullptr` and calls `beginRenderPass` again);
- the contract: `src/DingoEngine/Graphics/Shaders/Skinning.glsl:29-32`, `docs/animation.md:322-341`, `include/DingoEngine/Graphics/Renderer3D.h:421-423`.

**What happens:**
- P6 replaced the per-instance `SkinData` palette upload with a 16-byte volatile `DE_SkinDraw` write, and it still happens once per instance per pass.
- On Vulkan, NVRHI's `CommandList::writeBuffer` calls `endRenderPass()` for *every* buffer write, volatile ones included. The following draw's `setGraphicsState` then calls `vkCmdBeginRenderPass` again.
- So a shadowed scene of N visible skinned instances costs 2N `vkCmdEndRenderPass`/`vkCmdBeginRenderPass` pairs: N on the shadow atlas and N on the lit target. A translucent instance adds one more pair.
- At the default `MaxSkinnedInstances` of 1024 that is about 2,000 render-pass restarts a frame. At the 4096 ceiling it is about 8,000. Each also forces a descriptor-set rebind.
- D3D11 and D3D12 have no render passes, so they don't pay this.
- §1.4 of the plan names Vulkan's CPU submission as the budget. P0 measured Marionette's Vulkan render CPU at 0.79–0.88 ms against D3D's 0.14–0.15 ms. Per-instance restarts are one plausible part of that gap. That part is PLAUSIBLE and needs a GPU timing.
- The arena retired the *bytes* of the per-draw upload but not the *break*.
- `docs/animation.md` publishes `DE_SkinDraw` as a uniform block at binding 2–13 for custom skinned shaders, so any 1.x fix that changes how the base reaches the shader is a breaking change to that contract. Under SemVer it would have to wait for 2.0.
- P4's `UploadInstanceDraw` (one write per instanced group) has the same pattern, but it runs per group, not per character ([R4](#r4)).

**Fix:** decide before 1.0 is tagged.
- The smallest change that removes the break is to pass `PaletteBase` as a push constant. NVRHI's Vulkan `setPushConstants` is a `vkCmdPushConstants` and doesn't end the pass (`vulkan-commandlist.cpp:114-119`). It becomes root constants on D3D12, and NVRHI emulates it on D3D11. The engine already reflects push-constant blocks into the binding layout (`NvrhiShader.cpp:540-542`).
- This needs a per-draw push-constant path through `Renderer::DrawIndexed(Material*, …)`. `Skinning.glsl` would declare `layout(push_constant) uniform DE_SkinDraw { uvec4 SkinDraw; }` in place of the UBO.
- If the owner keeps the UBO for 1.0, document the per-instance Vulkan cost in `docs/performance.md` ("Skinned meshes and animation LOD"). Also record it in the plan's §9 P6 so S2 times it, for example with `--throughput=skinned --count=1024 --perf` on Vulkan against DX12.

**Test:**
- Add `Statistics::SkinDrawWrites`, counted in `UploadSkinDraw`.
- In the Throughput Test's `skinned --count=128` check (`test/src/Tests/Scene/ThroughputTest.cpp:588`), require it to be at most the number of passes, not the number of instances. Today it reads one write per drawn instance per pass, so the check fails.
- On the GPU machine (S2), compare Vulkan render-thread ms per skinned instance with DX12's.

### S1 — Two instances started together share, truncate or rotate away each other's `Dingo.log` {#s1}

`src/DingoEngine/Log.cpp:168-205` (`PickLogPath`), `:285-314` (`OpenLogFile`: `PickLogPath` at 292, `FileSink` at 294, which truncates at 61, `HoldLog` at 301), `:144-159` (`IsLogInUse`, `HoldLog`); `src/DingoEngine/Core/Application.cpp:62-63`. CONFIRMED (reproduced with a verbatim copy of the rotation code).

**What happens:** nothing makes "choose a name, create the file, lock it" atomic across processes.
- Instance A renames `Dingo.log` aside, shifts the old runs, prunes, and only then creates the new `Dingo.log` and `flock`s it.
- An instance B that checks during that window finds no `Dingo.log` (`exists` is false at 173) and also returns `Dingo.log`. Both `FileSink`s then open the same file. B's `trunc` (line 61) wipes A's opening lines, and both append into one file.
- A B that checks between A's create and A's `HoldLog` takes the transient test lock in `IsLogInUse` (149), finds the file "not in use", and renames A's live log to `Dingo.1.log`. A's `HoldLog` then opens and locks B's new `Dingo.log`, or fails `LOCK_NB` against B's test lock. The failure is ignored (158), so A may run with no lock at all, and later instances rotate A's live log too.

### S2 — Linux: a second thread faulting with the same signal kills the process mid-report (`SA_RESETHAND`) {#s2}

`src/DingoEngine/Core/CrashHandler.cpp:609` (`SA_SIGINFO | SA_ONSTACK | SA_RESETHAND`), `:484-497` (`BeginReport`), `:521-556` (`OnSignal`). The contract is in `CrashHandler.h:7` and `docs/application-and-layers.md:92-93`: "A second thread that crashes while the first is reporting waits for the exit". CONFIRMED (reproduced).

**What happens:** `SA_RESETHAND` resets the process-wide disposition of the delivered signal to `SIG_DFL` as soon as the first thread enters the handler. A second thread that then raises the same signal (SIGSEGV is the usual case) never reaches `BeginReport`'s wait. The kernel applies the default action at once and kills the whole process, while the first thread is still writing its backtrace and before the spdlog flush.

This is the normal shape of a crash in parallel code: Jolt's workers stepping a freed body, or llvmpipe's rasterizer threads reading a bad buffer, all fault within microseconds. Harness with the engine's exact handler logic (`multi.cpp`): eight threads fault together. In 50 of 50 runs only the header line was written: no backtrace, no "End of backtrace". The same harness without `SA_RESETHAND`, restoring `SIG_DFL` explicitly before `raise`, completes the report in 50 of 50 runs. Only a different signal on the second thread (say SIGABRT during a SIGSEGV report) waits as designed. Windows is not affected: its filter really does make the second thread wait.

**Fix:** drop `SA_RESETHAND`. In `OnSignal`, call `signal(sig, SIG_DFL)` (async-signal-safe) immediately before each `raise(sig)`: at line 525, for the same-thread re-entry, and at 555. A nested synchronous fault on the reporting thread still kills, because the kernel forces the default action for a blocked synchronous signal. Do this together with [S3](#s3)'s try-lock: otherwise a second thread that crashed inside a log call now parks holding the sink lock, and the reporter's flush waits on it.

**Test:** add `--crash=threads` to `test/src/CrashTrigger.cpp`: eight `std::thread`s spin on an atomic and then write through null. Add `crash threads 139 'End of backtrace'` to `scripts/ci/linux-smoke-test.sh` and `Invoke-Crash 'threads' 0xC0000005 'crashed: access violation[\s\S]*Minidump: '` to the Windows script. ### S3 — The report's closing `Log::Flush` can hang the dying process; when it doesn't, the last lines land after the report {#s3}

  - `Shared->Live` holds raw `StaticBatchData*` that `~StaticBatch` erases. `m_SceneStaticBatches` holds `shared_ptr`s, so a batch destroyed or evicted mid-scene stays alive until `EndScene`.
- **Pending and id reuse:**
  - Remove → Add of the same id while it is queued leaves the id twice in `Pending`, but the `Queued` flag processes it once. Update twice before a submission is fine, and `Clear` empties `Pending`.
  - A `Detach` from a cell later freed can't leave a stale `entry.Cell`, because a cell empties only by detaching all its members. Cell slots are reused through `FreeCells` and `CellLookup` is erased. References into `Cells` are re-fetched after `emplace_back`.
- **Records:**
  - `Revision` bumps on every write. A shrink needs no upload, and the scene's records start at the new `S`, so they only overwrite freed slots. `S` grows only through an `Allocate` append, which bumps.
  - Growing the object buffer resets `m_StaticRecordsUploaded`. The `static_assert` that the record size is 32 B holds. `DynamicObjectIndex` is applied to CPU, translucent and instanced records alike; skinned writes 0.
  - Within a frame, a later scene's re-upload of `[1,S)` follows earlier scenes' draws in command-list order, and `NvrhiGraphicsBuffer::Write` commits the barrier back to the initial state.
- **A batch outliving its renderer:**
  - `Shutdown` clears `m_SceneStaticBatches` first, so a last reference dies while `RendererAlive` is still true and its buffers land in `Retired`, which `Shutdown` then frees. It then frees every live cell's buffers, nulling them, then `Retired`, sets `RendererAlive = false` and resets the shared state. A second `Shutdown` is guarded.
  - A later `~StaticBatch` or `Clear` finds null buffers, and `Release` is CPU only. `OwnsStaticBatch` compares the shared pointer, so a new renderer at the old address can't claim the batch. `StaticGeometry::Find` drops dead renderers' bakes. `Renderer::GetFrameIndex()` is null-safe after `Renderer` shutdown.
- **Retirement:** rebaked buffers go to `m_RetiredArenaBuffers` with the frame; destroyed or cleared batches' buffers go through `Shared->Retired`, drained at the next unskipped `BeginScene`. They are freed by `ReserveArena` after `k_ArenaRetireFrames`, so no double free between the two lists. Cell buffers use `KeepInitialState` (default true) like the skinned and instanced mesh buffers written once. Skipped frames never reach `PrepareStaticBatch`, so no once-only upload is lost.
- **Two renderers drawing one scene:** each gets its own bake and its own `StaticBatchShared`, records and object buffer; `Pass`/`Seen` are per bake. The removal walk is exact (`GetMeshCount() - Tracked` equals the number of unseen entries, since an entity is tracked at most once a pass and a reused entity index is removed inline). A different scene drawn by the same renderer gets its own batch sharing the records correctly. The fifth renderer evicts with a warning (documented).
- **Change detection coverage in code:** world transform via `memo.Transform` (a moved parent counts), mesh, colour, material, shadows, groups and all four `SurfaceOverride` fields are compared bitwise. Hidden, inactive, mesh-less, `CullDistance`-carrying and no-longer-`Static` entities are not tracked and so removed. PhysicsSync skips static bodies' read-back, so a `Static` floor with a static body never warns.
- **Layout and draws:**
  - `LayoutStaticBatches` runs after the lit slots are acquired and needs `Enqueued && !SkinnedOnly && !Translucent && Usable` for its key. `BindsPastSlotZero` and unusable `Instancing` materials are skipped exactly as `SubmitMesh`'s are, and keys use the same `Off → groups 1` normalisation.
  - In-view casting ranges are drawn by the shadow pass from their slot's `StaticDraws`, and culled casters and `ShadowsOnly` ranges from `m_StaticShadowDraws` with the right caster mask. `m_Layout` and `m_LitLayout` match the 52 B `Vertex` of the cell buffers.
  - Indices are 32-bit and pre-offset within the cell VB, so no base vertex is needed (D3D11/D3D12 fine). A range can't have `IndexCount == 0`, which `DrawIndexed` would read as "the rest".
- **Cell bounds vs casters:** a range's culling box is the union of its meshes' padded `WorldBounds`, so a visible or shadow-reaching mesh never culls its range. The caster fold uses the exact baked positions, computed with the same expression as `foldVertices`, so the cascade fit is bit-identical to `SubmitMesh`'s. Unusable ranges are folded just as unusable dynamic submissions are. The local-light `SphereTouchesBox` test uses that same box.
- **Loose entries:** translucent (not `ShadowsOnly`), skinned-only, custom `Instancing`, over-capacity, non-affine, non-finite or |centre| > 1e9 cells go through `SubmitMesh` with their surface. A translucent `ShadowsOnly` mesh bakes, as `EnqueueBatch` treats it as opaque.
- **Candlewick:** `SpawnDecor`'s static decor uses the renderer's long-lived box mesh and fixed surfaces. The flicker touches only the non-static glow cores. Cut-away walls toggle `Shadows` and mounted decor toggles `Visible` only on change, and flasks are destroyed once, so cells rebake only on those events.
- **Invariants:** the public `StaticBatch.h` has no EnTT, NVRHI, Jolt or ImGui (EnTT stays in the internal `StaticGeometry.h`); no `near`/`far` identifiers and no `DE_CORE_ASSERT` with format arguments; `<Windows.h>` `max` appears only in engine `.cpp` code that already used the pattern; no per-frame allocation on the static path (`Track` builds the `StaticMesh` on the stack, and the slot and draw vectors are reused).
- **The existing 0 px checks** catch a broken transform, colour, surface record index, the scene's records offset (`DynamicObjectIndex`), a range's culling bounds (Throughput `static`/`mixed`) and a lost hot-reload entry (the duck's pixel compare, plus its bake count). The Throughput readbacks are recorded before the duck renders reuse target 3. The gaps are [B2](#b2)–[B4](#b4).

**Skinned throughput and animation (K)**
- **`DE_SkinDraw` write count against the Vulkan version budget:**
  - Writes per admitted instance per frame are at most 3: one in the shadow pass (`uploadedInstance`, :3474-3479), one in the opaque pass and one in the translucent pass (`SkinUploads::Draw`). A two-sided translucent draw is two draws for one write.
  - An instance's submissions are contiguous, because a new instance is only ever the back of `m_SkinnedInstances`, and its translucent submissions share one sort key under `std::stable_sort` (:1515). A static translucent mesh between them never touches the buffer.
  - Dropped and non-live instances are never written. The budget is per frame across scenes (`m_SkinnedFrameIndex`) and fixed at `Create`, as is the buffer's `MaxWritesPerFrame = 3 × budget`, which has ×4 versions.
  - Every bind of a pass that holds `DE_SkinDraw` is preceded by a write in the same command list (the twin, the skinned shadow materials, and custom palette materials, which are skinned-only, so never drawn static).
- **SkinData path:** at most 2 writes per flagged, admitted instance (opaque and translucent; shadows use the arena), within `2 × min(budget, 256)`. The flag and the draw condition agree (`!CameraCulled`, `!ShadowsOnly`). "Admitted whole" also holds for the shadow pass (`skinnedShadowDrawn` checks `m_SkinnedInstanceDropped`).
- **Arena growth mid-frame:** the old buffer is retired with the frame index and freed after 8 frames (`ReserveArena`), so earlier scenes keep drawing from it. `Material::RepointStorageBuffer` re-points by `(pointer, GetId())`, so a new arena at a freed one's address still re-bakes. `GetShadowMaterial` re-sets the buffers on every call; a pass's desc briefly holding a retired buffer stays safe, because the old NVRHI binding set holds references to its resources until the re-bake.
- **Per-scene rewrite at offset 0:** it goes inline into the frame's command list (`NvrhiCommandList::UploadBuffer`, or `UploadStorage` → `TryGetRecordingCommandList`). NVRHI ends the render pass, puts the automatic ShaderResource→CopyDest barrier ahead of the write, and #145's `setBufferState(initial)` + `commitBarriers` follows it, so write-after-read and read-after-write are both covered on Vulkan and D3D12. D3D11's `UpdateSubresource` is ordered by the driver.
- **D3D11 slots:** `DE_SkinDraw` is `b4`, and a custom shader's is capped at 13 (D3D11 has 14 CB slots, and the lit twin uses b0, b1, b4 and b5). `DE_SkinPalette` is a readonly storage block declared only in the vertex stage, so it is a `RawBuffer_SRV`, which SPIRV-Cross emits as `ByteAddressBuffer : register(t11)`, inside the 128 SRV slots. The binding-layout visibility is `All`, so NVRHI binds it to the VS, and the 16-byte CB needs no partial update. `ResolveSkinnedMaterial`'s `freeBinding` matches the shared GLSL numbering (texture at 2+2i, sampler at 3+2i).
- **`SortBySlot`** (`NvrhiCommandList.cpp:303-307`): NVRHI collects `volatileConstantBuffers` in desc order (`vulkan-resource-bindings.cpp:528`) and Vulkan consumes dynamic offsets in binding order, so sorting the desc copy is the right fix.
- **Pass cache keys** use `GraphicsBuffer::GetId()` for the skin draw buffer, the scene UBO and the SkinData buffer, not addresses. Skinned twins are keyed by `Material::GetId()`, and `PrepareLitMaterial` only rewrites a twin's UBO when it changed.
- **`SubmitMesh` fallback** (more than 128 joints, too few joints, no skin): a skinned-only material is replaced by the default material, both in the fallback and in `EnqueueBatch`'s `SkinnedOnly`; the palette counts as seen (`m_UnskinnedPalettes`, recorded even when the fallback mesh is culled, as documented); an instanced fallback uses the rest-pose `GetVertices()`.
- **Animation LOD logic:**
  - Two frame slots are cleared on the first scene of a frame and unioned across scenes and renderers. Skipped scenes record nothing.
  - `SceneData::SkinnedViews` holds weak references and drops expired renderers. `rendered = SkinnedViewFrame + 1 >= frame` handles headless and menu-hidden scenes. A minimized `SkipFrame` doesn't bump the index, so the last drawn set persists.
  - A dropped instance counts as seen, because it is recorded before `ResolveSkinnedBudget`. `ReduceWhenCulled`'s offset spreads poses evenly, and the LOD check's 3-of-12 holds for any starting offset.
- **`Animator::Update(dt, false)`:** `CollectEvents`, fades, one-shot hand-back and `CollectRootMotion` all run before the `evaluatePose` test. `Evaluate()` is a pure function of the states, apart from the documented frozen pose, so the first evaluation after a culled stretch is exact. `EnsureAnimator` still poses on a rebind or a reload.
- **AnimationDebug threading:** scenes register on the main thread at their first `OnUpdate` and unregister first thing in `~Scene`, before `Clear()` and `delete m_Data`. The F7 section holds the recursive lock across `CollectAnimators`, `DescribeAnimator` and its reads of the animators. Scene updates and the tab are both on the main thread, `SceneManager` deletes scenes on the main thread, and no path waits on another lock while holding this one. `Scene` is non-copyable and non-movable, so the registered pointer can't go stale.
- **P1 model and animation changes:**
  - `SubMesh::BaseColor`: glTF base colour, else diffuse with `AI_MATKEY_OPACITY` as alpha, else white. It is carried across `Adopt` and reset for vanished submeshes. The `Dingo::Mesh* Mesh` and `Dingo::Material* Material` members follow the GCC naming rule.
  - Joint grouping (Bone, then Rigid, then Other, by min-propagation to parents) keeps every joint's parent at a lower index, so `ComputeGlobalTransforms` stays valid, and keeps `GetSkinJointCount` = Bone + Rigid.
  - `EventsFile`: `from_chars` with finite and full-consume checks, reversed and bad ranges reported, `RebuildEventMarks` once per touched clip with a stable time sort. The `partition_point` mark searches are equivalent to the old linear scans, given that sort.
  - `HandedOver` stops a handed-back one-shot from becoming dominant again. A revision change ends a range whose new span no longer holds the playhead, and the later end mark is suppressed because no range is open. Masked-out channels aren't sampled in upper layers, and `HoldRoot` is gated on the mask; frozen upper-layer poses still apply through the mask.
- **LOD test strength:** it would fail if `WasDrawn` always returned true (Paused 12/12) or always false (Seen 0/12), if `evaluatePose` were ignored, if culled animators didn't fire events, or if the headless rule were removed (Reduced 1/4).

**Stability and platform (S)**
- **Linux handler async-signal-safety:**
  - It writes with `write(2)` from fixed stack buffers (`LineBuilder`), takes no locks, and doesn't allocate before the flush. `backtrace` is pre-warmed at Install, so libgcc's first-use `malloc` doesn't happen in a handler. `backtrace_symbols_fd` doesn't allocate, `pthread_self` and `raise` are fine, and the atomics are lock-free.
  - `t_LoggingDepth` is local-exec TLS (static library in the executable). Every spdlog entry point (`PrintInternal`, `PrintInternalTag`, `Flush`) is inside a `LoggingScope`, and the unscoped sink-lock holders (`ReplaceEarlySink`, `add_sink`) run before `Install` or only once. So a thread that crashes inside a log call never self-deadlocks.
- **Re-raise and exit codes:** 139/134/133 match. `abort()`'s second raise works, and the core dump is kept. A nested fault on the reporting thread terminates.
- **Windows crash handling:**
  - The dump thread is made at Install, and the 64 KB stack guarantee on the main thread and on every engine thread lets an overflow reach the filter. `RunGuarded`'s `__try` frame holds no unwindable objects, so there is no C2712.
  - Chaining to the CRT filter only for `0xE06D7363`, and only when nobody is reporting, makes `current_exception` valid in `OnTerminate`. `s_Installed` stops a restart from chaining the filter to itself.
  - The abort, purecall and invalid-parameter handlers are process-wide, and `ReportAndExit` captures context. A second crashing thread really does wait (`Sleep(INFINITE)`), so two-thread crashes are fine here, apart from [S3](#s3).
- **`FatalError`:** it waits for another thread's report, and the log is flushed before `_Exit(1)`. Distribution's `DE_VERIFY` and `DE_CORE_VERIFY` compile with no message and with a literal; no call site passes format arguments (7 uses). Behaviour only changes from a debug break to a message, since Distribution's `__debugbreak` was already fatal.
- **Logs in one instance:** the ring is replayed and swapped under the `dist_sink` lock, with the file's pattern set before the replay, and a restart keeps the file. Rotation keeps five runs, stops at the first failed rename, never overwrites, and leaves at worst an `-previous` side log. Windows detects a running instance correctly (MSVC's `ofstream` opens without `FILE_SHARE_DELETE`, so the rename is refused). The crash handler's `FILE_APPEND_DATA` or `O_APPEND` handle coexists with the sink's. Dumps are pruned in date order by name.
- **Shutdown order (d56f74c):**
  - `Renderer::Shutdown` waits until the render thread has taken the last frame. It is notified only after that frame is executed, presented and the next image acquired, so in effect it waits for the whole frame. Then the sentinel, then the join. There is no lost wakeup, and the `HasPendingFrame` fallback is now dead but harmless.
  - `Destroy` runs swap chain → context → window. D3D12's `Destroy` waits on its present fence, then NVRHI's `waitForIdle` and GC, before releasing back buffers; D3D11's drops its handles, then `waitForIdle`, `ClearState` and GC before `Release`. Vulkan's `DestroySwapChain` calls `waitIdle`, and the surface goes before the instance, which goes before the window.
  - The acquire left pending after the last present is #182.
- **Vulkan debug_utils:** the callback is null-safe on `pMessageIdName` and `pMessage` and logs through thread-safe macros; the messenger is destroyed before the instance; the cast to `vk::PFN_...` is ABI-identical, since the loader calls it through the C type. Validation is on by default in Debug and Debug-ASan (both define `DE_DEBUG`), `--vulkan-validation[=off|false|0|no]` is parsed correctly, and the smoke grep `Validation Error|VUID-` matches the new `[Vulkan] Validation Error: [ ... ]` format, SYNC hazards included.
- **Application:** `Initialize` is idempotent (`m_Window` guard). `RequestRestart`'s API is applied in the constructor and the flag is cleared. The default `Name` goes through `PathToUtf8`, and `GetUserDataDir` joins with `PathFromUtf8`.
- **CI and scripts:**
  - Exit status propagates: `xvfb-run` passes the script's on; the smoke scripts count failures and `exit` non-zero; crash runs check the exact exit code and the log text in `Dingo.log`; the Windows script fails loudly under `ErrorActionPreference = 'Stop'`; negative `[int]` hex exit codes are right, and pwsh carries the last native exit code through.
  - `set -euo pipefail` is on in `package-linux-programs.sh` and `make-bundle.sh`. `gather-notices.sh` checks every licence outside any pipeline before generating, so `--check` fails loudly. `install-desktop-entry.sh` escapes correctly for the desktop-entry spec (string escapes, Exec quoting with `\\"`, and `%%`) and for sed's replacement.
  - `docs.yml` fails on a non-empty `WARN_LOGFILE`. The release tag `v1.0.0-rc.1` parses to 1.0.0 in both the bash and pwsh steps and in `WriteBuildInfo`. `exeMetadata`'s `.rc` needs no `<windows.h>` constants, names the icon `GLFW_ICON`, sets `#pragma code_page(65001)` and uses forward-slash paths.
- **Unit tests:** 53/53 pass on the current Debug build. The UUID, Utf8, `.events`, shadow-atlas and tone-map cases assert what their names say.
- **Noted, not filed:**
  - `Log::ReportAssertion` calls `PrintInternal` without `ShouldLog`, so an assert from a static destructor after `ShutdownLog` dereferences a null logger (Debug only).
  - `s_GuardedExceptionCode` is global, so if two guarded threads crash, the exit code can be the second one's.
  - Debug Windows builds no longer offer the JIT-debugger prompt on an unattached `__debugbreak`, because the filter returns `EXECUTE_HANDLER`.

**Data and API (D)**
- **Atomic write, step by step (Linux and Windows):**
  - A kill while `.tmp` is written leaves `<path>` and `.bak` intact, and so does a kill after the flush and before `path -> .bak`. A kill between the renames leaves `.tmp` complete, and `ReadFile` reads it. A kill after the second rename leaves the new `<path>`.
  - Power loss on Linux: `.tmp` is `fsync`ed before either rename and the directory is `fsync`ed after.
  - On Windows, `MoveFileExW(REPLACE_EXISTING | WRITE_THROUGH)` replaces an existing `.bak` and the target. The `.bak` rotation is skipped when `<path>` doesn't exist, so the first save never needs a `.bak`. A failed `tmp -> path` keeps `.tmp`, which `ReadFile` then reads.
  - Writes are serialized by a static mutex.
- **Paths:** every path-to-text conversion in `SaveData.cpp` goes through `u8string` (`DisplayPath`, `List`); files open through `path.c_str()` (wide on Windows) and `std::ifstream(path)`; `GetPath` builds from a `std::string` only after `IsValidName` restricts it to ASCII; `GetUserDataDir` uses `PathFromUtf8`; `--save-dir` builds a path from argv, which is ANSI on Windows, so `path(std::string)` is the consistent decoding there (the real defect is [S7](#s7)).
- **JSON numbers:** unsigned above `INT64_MAX` becomes a double; `AsInt` rejects NaN, infinity, fractions and anything at or beyond 2^63; `Get<integral>` range-checks; non-finite values are written as null; nesting is capped at 256 in `FromJson`, and nlohmann's parse and destroy are iterative.
- **Settings:** `ReadVolume` and the deadzone are filtered with `isfinite` and clamped. Width and height are taken only when both are above 0 and are clamped to 16384. An invalid `fullscreenMode` means the desktop mode. `Apply` changes the mode before the size and skips what already matches, and its exclusive comparison uses `ChooseDisplayMode`, so an unlisted saved mode isn't re-entered every time. The `SettingsSlot` path runs after `s_Instance` and `SaveDirectory` are set, and the master volume is applied after the audio engine exists.
- **Display modes:** `SortDisplayModes` dedups correctly (equal area and width imply equal height). `ChooseDisplayMode` orders by exact size, then area, then aspect, then refresh. The desktop mode is cached only while exclusive, and exclusive to borderless and exclusive to windowed restore it through GLFW. `glfwGetVideoMode` is null-checked.
- **`SetActive`:**
  - Bodies, 2D bodies and controllers are destroyed on deactivate and rebuilt on activate, only while physics runs. `CreateBody*`/`CreateController` skip inactive entities, so `Start` and `DuplicateEntity` respect the flag.
  - Audio stops on deactivate, and a `PlayOnStart` source replays on activate while the scene runs. `PlayAudioSource` refuses an inactive entity.
  - Animators are skipped, with root motion and events cleared and the driven controller stopped. Particle emitters are neither updated nor submitted. Static bakes drop an untracked (inactive) entity in `StaticGeometry::Submit`. Lights skip but still count as `hasLight`. Fog and cameras are skipped.
  - Scripts get no `OnUpdate`/`OnFixedUpdate`; an `OnStart` waits for activation, which sets `MarkPending`. `SetParent`, `RemoveParent` and `DuplicateSubtree` re-derive the flag.
- **Script lifetime:** `CallScope` wraps every callback (OnCreate, OnStart, OnFixedUpdate, OnUpdate, OnAnimationEvent, ForEach and OnDestroy). `Detach` parks the instance in `m_Detached`, so a script that destroys its own entity, calls `RemoveScript` or replaces itself inside its own callback keeps its `this` alive. The `Update` loop re-finds by handle after each call, `DetachAll` snapshots the handles, and `~Scene` calls `Clear` before `delete m_Data`.
- **Fixed step:** dt is capped at 4/60 s and at most 8 steps run per update, with the remainder reduced by `fmod`, so there is no spiral of death. The accumulator is zeroed on `OnStart`, and `SetFixedTimeStep` rejects NaN and clamps.
- **Scene lifecycle:** the first-scene start can't run `OnStart` twice (`Scene::OnStart` returns early when running). The remaining explicit `OnStart` calls (AngryBirds replay, DungeonCrawler3D `RestartScene`, Marionette `RestartArena`) follow a `Clear`/`OnStop`.
- **Component-removal hooks:** runtime pools are pre-created in `Connect`. `Stop` clears runtimes before `Clear` destroys the registry, so `DropBody*` never touches a null world. `StopAllSources` clears runtimes even without an application. `GetLightVisibility` returns 1 and `GetShadowedLightAttenuation` returns 0 for an inactive light.
- **Examples:** `BoxCollider2DComponent::HalfExtents` is a pure rename with the same math in `PhysicsSync`, and AngryBirds keeps its defaults. Ambient migrations keep the look (DungeonCrawler3D day is 0.65 sun plus 0.35 ambient, night is 0.12*0.95 plus 0.05; EchoVault is 0.65 plus 0.35; Marionette's explicit `Ambient = 0` is dropped; Candlewick and Marionette already used `AmbientLightComponent`). Every example removed its `app->Initialize()` and `FramesInFlight`, and builds its scenes before `SetActiveScene`.
- **Docs:** in `versioning.md`, the simulation-timing and append-only rules match the code. In the migration guide, the "first SetActiveScene" and "component edits apply on rebuild" sections and the `SetActive(false)`/`SetActive(true)` rebuild idiom match the code.
- **Other P9 changes:** `AssetManager`'s change to `RGBA8_UNORM` is correct, because `ReadImage` is called with `forceRGBA = true`. `Input.cpp` changes are renames only. `NvrhiFramebuffer::Destroy` frees its attachments.
